Database Backup, Recovery and Security

ब्याकअप, रिकभरी र सुरक्षा

8 hrs · 6 marks

By the end of this unit you can…

  1. Define backup and say why it is not optional.
  2. Distinguish physical from logical backup.
  3. List the reasons a database fails.
  4. Compare full, incremental and differential backup.
  5. Explain recovery, and say when redo is used and when undo is used.
  6. State the measures that make a database secure, and name common threats.
यो युनिट सकिँदा: backup को परिभाषा दिन र किन अनिवार्य छ भन्न, physical र logical backup छुट्याउन, डाटाबेस बिग्रने कारण सूचीबद्ध गर्न, full–incremental–differential तुलना गर्न, recovery व्याख्या गर्न र redo–undo कहिले प्रयोग हुन्छ भन्न, र सुरक्षाका उपाय तथा सामान्य खतरा नाम लिन सक्नुहुनेछ।

7.1 – 7.3  Backup, and what it protects against

Definition — learn this wording

A backup is a copy of the database kept separately, so that the data can be restored if the original is lost, damaged or corrupted.

Two types, and the difference is what is copied:

Physical backup — a copy of the actual database files as they sit on the disk. It is fast to take and fast to restore, but tied to the same kind of system.

Logical backup — a copy of the SQL statements that would rebuild the database: the CREATE TABLEs and the INSERTs. It is slower, but it is readable and can be restored onto a different system.

परिभाषा — यही शब्दमा सम्झनुहोस्

Backup भनेको डाटाबेसको छुट्टै राखिएको प्रतिलिपि हो, ताकि मूल हराए, बिग्रिए वा भ्रष्ट भए data फर्काउन सकियोस्।

दुई प्रकार, र फरक के प्रतिलिपि गरिन्छ भन्नेमा छ:

Physical backup — डिस्कमा जस्ताको तस्तै रहेका डाटाबेस फाइलको प्रतिलिपि। लिन र फर्काउन छिटो, तर उस्तै प्रणालीमा मात्र।

Logical backup — डाटाबेस पुनर्निर्माण गर्ने SQL कथनहरूको प्रतिलिपि: CREATE TABLE र INSERT। ढिलो हुन्छ, तर पढ्न मिल्ने र फरक प्रणालीमा पनि फर्काउन सकिने।

7.3 — Why a database fails. Hardware failure — a disk dies. Software failure — a bug in the DBMS or the operating system. Human error — a DELETE without a WHERE, or a DROP on the wrong table. Power failure — a transaction stops halfway. Natural disaster — fire, flood, earthquake. Malicious attack — deliberate damage or theft. डाटाबेस बिग्रने कारण: हार्डवेयर बिग्रनु — डिस्क बिग्रियो; सफ्टवेयर — DBMS वा OS मा त्रुटि; मानवीय गल्ती — WHERE नभएको DELETE, वा गलत तालिकामा DROP; बिजुली — ट्रान्ज्याक्सन बीचमै रोकिनु; प्राकृतिक प्रकोप — आगलागी, बाढी, भूकम्प; नियतवश आक्रमण — जानाजान बिगार्नु वा चोर्नु।

7.4  Methods of backup

Predict first · पहिले अनुमान गर्नुहोस्

A full backup is taken on Sunday. Differential backups run Monday to Friday. The disk fails on Friday evening. How many backup files are needed to restore? आइतबार full backup लिइयो। सोमबारदेखि शुक्रबारसम्म differential backup। शुक्रबार साँझ डिस्क बिग्रियो। फर्काउन कति backup फाइल चाहिन्छ?

Two. A differential backup holds everything that changed since the last full backup, so Friday's already contains Monday to Thursday's changes as well. You need the full backup plus the most recent differential.

Had they been incremental, the answer would be six — each incremental holds only what changed since the previous backup, so every one is needed, in order. That is the trade: differential takes more space, incremental takes more restoring.

दुई। Differential ले अघिल्लो full backup देखिका सबै परिवर्तन राख्छ, त्यसैले शुक्रबारकोमा सोम–बिहीका पनि छन्। Full र सबैभन्दा नयाँ differential चाहिन्छ। Incremental भएको भए उत्तर छ हुन्थ्यो। सन्तुलन यही हो: differential ले ठाउँ बढी लिन्छ, incremental ले फर्काउन समय।

7.5  Recovery — redo and undo

step 0 / 3
One log, two directions

Recovery is the process of restoring the database to a correct, consistent state after a failure. The tool it uses is the log — a file in which the DBMS records every change before it is applied.

After a crash the recovery manager reads the log and sorts every transaction into one of two piles, by a single test: is there a COMMIT record?

REDO — the transaction committed, so its work must exist. The log is read forwards and the changes are applied again. This delivers durability.

UNDO — the transaction did not commit, so its half-finished work must not survive. The log is read backwards and the changes are reversed. This delivers atomicity.

एउटै लग, दुई दिशा

Recovery भनेको असफलतापछि डाटाबेसलाई सही र सङ्गत अवस्थामा फर्काउने प्रक्रिया हो। यसले प्रयोग गर्ने साधन log हो — DBMS ले हरेक परिवर्तन लागू गर्नु अघि लेख्ने फाइल।

Crash पछि recovery manager ले log पढेर हरेक ट्रान्ज्याक्सनलाई एउटै जाँचबाट दुई थुप्रोमा छुट्याउँछ: COMMIT रेकर्ड छ कि छैन?

REDO — commit भएको थियो, त्यसैले काम रहनुपर्छ। Log अगाडिबाट पढेर परिवर्तन फेरि लागू गरिन्छ। यसले durability दिन्छ।

UNDO — commit भएको थिएन, त्यसैले आधा काम बाँच्नु हुँदैन। Log पछाडिबाट पढेर परिवर्तन उल्टाइन्छ। यसले atomicity दिन्छ।

Example 1 Deciding redo or undo from a log

Question: the log below survives a crash. State what recovery does with T1, T2 and T3, and give the reason.

Given
T1 start T1 write A T1 COMMIT T2 start T2 write B T3 start T3 write C T3 COMMIT -- CRASH --
Answer
T1 REDO it has a COMMIT record, so its work must exist T2 UNDO no COMMIT record — it was still running T3 REDO it has a COMMIT record

Do not read the order or the amount of work done. The only question is whether a COMMIT record appears before the crash. T2 had written B — real work, on its way to the disk — and it is still discarded entirely, because atomicity does not allow half a transaction to survive. क्रम वा कति काम भयो भन्ने नहेर्नुहोस्। एउटै प्रश्न हो — crash अघि COMMIT रेकर्ड छ कि छैन। T2 ले B लेखिसकेको थियो — साँच्चिकै काम — तर पूरै हटाइन्छ, किनभने atomicity ले आधा ट्रान्ज्याक्सन बाँच्न दिँदैन।

Practise the judgement · निर्णय अभ्यास गर्नुहोस्

Redo or undo? Decide from the log

What you will learn: to apply the one test that decides it, and to stop being distracted by how much work a transaction had already done. तपाईंले के सिक्नुहुन्छ: तय गर्ने एउटै जाँच लागू गर्न, र ट्रान्ज्याक्सनले कति काम गरिसकेको थियो भन्नेमा नअल्मलिन।

How to use this

Before you press an answer, find the COMMIT record — or confirm there isn't one. That is the whole decision. Do not read the writes.

Case 2 has two writes and no commit; case 3 has a commit and almost no work. They go opposite ways, and that pair is the point: the amount of work is never the test.

उत्तर थिच्नुअघि COMMIT रेकर्ड खोज्नुहोस् — वा छैन भनी पक्का गर्नुहोस्। पूरा निर्णय त्यति नै हो। लेखाइ नपढ्नुहोस्। केस २ मा दुई पटक लेखिएको छ तर commit छैन; केस ३ मा commit छ तर झन्डै केही लेखिएको छैन। दुवै विपरीत दिशामा जान्छन् — कति काम भयो भन्ने कहिल्यै जाँच होइन।

7.6 & 7.7  Database security

What security actually protects

Database security is the protection of a database from unauthorised access, malicious damage and accidental loss. It has three separate jobs, and answers that name all three score better than answers that describe one at length.

Authentication — proving who a user is, usually with a username and password.

Authorisation — deciding what that user is allowed to do, which is what GRANT and REVOKE control. Authentication without authorisation is a door with a lock and no rooms.

Encryption — storing the data so that it is unreadable even to someone who obtains the file. It protects against the theft that gets past the first two.

Add regular backup and an audit trail — a record of who did what — and you have the full set of measures.

सुरक्षाले साँच्चै के जोगाउँछ

डाटाबेस सुरक्षा भनेको अनधिकृत पहुँच, नियतवश बिगार र आकस्मिक क्षतिबाट डाटाबेसको संरक्षण हो। यसका तीन छुट्टै काम छन्, र तीनै नाम लिने उत्तरले एउटालाई लामो लेख्नेभन्दा बढी अंक पाउँछ।

Authentication — प्रयोगकर्ता को हो भनी प्रमाणित गर्ने, प्रायः प्रयोगकर्ता नाम र पासवर्डबाट।

Authorisation — त्यो प्रयोगकर्ताले के गर्न पाउने भन्ने तय गर्ने, जुन GRANT र REVOKE ले नियन्त्रण गर्छन्।

Encryption — फाइल नै पाएको मान्छेले पनि पढ्न नसक्ने गरी data राख्ने।

नियमित backup र audit trail — कसले के गर्‍यो भन्ने अभिलेख — थपेपछि उपायहरूको पूरा सूची बन्छ।

7.7 — Common threats. Unauthorised access — someone reads or changes data they should not. SQL injection — a user types SQL into an input box and the program runs it, so a login form becomes a way to read the whole table. Malware — software that damages or steals the data. Privilege abuse — a legitimate user doing more than their job needs. Weak passwords and unencrypted backups — the two easiest ways in, and the two most often forgotten. सामान्य खतरा: अनधिकृत पहुँच; SQL injection — प्रयोगकर्ताले इनपुट बाकसमा SQL टाइप गर्दा प्रोग्रामले चलाइदिनु, जसले login फारमलाई पूरै तालिका पढ्ने बाटो बनाइदिन्छ; Malware; अधिकारको दुरुपयोग; कमजोर पासवर्ड र encrypt नगरिएको backup — भित्र पस्ने सबैभन्दा सजिला र सबैभन्दा बिर्सिने दुई बाटा।
Example 2 Choosing a backup schedule, and counting the cost

Question: a school database changes a little every day. A full backup takes 2 hours; each day's changes take 10 minutes to copy. Compare an incremental and a differential schedule for a Sunday-to-Saturday week, and say which restores faster after a Saturday failure.

Working — incremental
Sun FULL 2 hrs Mon changes since Sun 10 min Tue changes since Mon 10 min Wed changes since Tue 10 min Thu changes since Wed 10 min Fri changes since Thu 10 min Sat changes since Fri 10 min To restore: FULL + all 6 incrementals = 7 files, in order
Working — differential
Sun FULL 2 hrs Mon changes since Sun 10 min Tue changes since Sun 20 min Wed changes since Sun 30 min Thu changes since Sun 40 min Fri changes since Sun 50 min Sat changes since Sun 60 min To restore: FULL + Saturday's only = 2 files
Answer
Incremental fastest to TAKE (10 min every day) slowest to RESTORE (7 files, in order) Differential slower to take, growing each day fastest to RESTORE (2 files) Differential restores faster after a Saturday failure.

The trade is always the same shape: time spent every day, against time spent on the one day it goes wrong. An incremental schedule is cheap all week and expensive exactly when you are already in trouble — which is why many real systems accept the larger daily cost of a differential. सन्तुलन सधैं उही आकारको हुन्छ: हरेक दिन लाग्ने समय, बनाम बिग्रने त्यो एक दिनमा लाग्ने समय। Incremental हप्तैभरि सस्तो हुन्छ र ठ्याक्कै समस्या परेकै दिन महँगो — त्यसैले धेरै वास्तविक प्रणालीले differential को दैनिक भार स्वीकार गर्छन्।

Mistakes that cost marks here

  • Treating backup and recovery as the same thing. Backup is the copy taken beforehand; recovery is the process of using it, plus the log, after a failure. Backup र recovery लाई एउटै मान्नु। Backup पहिले लिइने प्रतिलिपि हो; recovery असफलतापछि त्यो र log प्रयोग गर्ने प्रक्रिया।
  • Swapping incremental and differential. Incremental is since the last backup; differential is since the last full backup. Incremental र differential साट्नु। Incremental अघिल्लो backup देखि; differential अघिल्लो full backup देखि।
  • Saying redo is used for failed transactions. It is the opposite — redo is for committed ones, undo is for uncommitted ones. असफल ट्रान्ज्याक्सनलाई redo भन्नु। उल्टो हो — redo commit भएका लाई, undo commit नभएकालाई।
  • Confusing authentication with authorisation. Authentication is who you are; authorisation is what you may do. Authentication र authorisation मिसाउनु। Authentication भनेको तपाईं को; authorisation भनेको के गर्न पाउने।

Exam focus — what is asked from this unit

Everything in this unit is answered from memory, so the work is done before the exam, not in it. The three questions that recur are: define backup and state its types; compare the backup methods; and explain recovery with redo and undo. Each is a short, structured answer — a definition, then a list, then one line per item. Learn the lists as lists and you can write them out in two minutes. यस युनिटका सबै उत्तर सम्झेर लेख्ने हुन्, त्यसैले काम परीक्षामा होइन, अघि नै सकिन्छ। दोहोरिने तीन प्रश्न: backup को परिभाषा र प्रकार; backup विधिको तुलना; र redo–undo सहित recovery को व्याख्या। हरेक छोटो र संरचित उत्तर हो — परिभाषा, अनि सूची, अनि प्रति बुँदा एक हरफ।
2 marks Practice question

What is database backup? Name its two types. डाटाबेस backup के हो? यसका दुई प्रकार नाम लिनुहोस्।

A backup is a copy of the database stored separately so that the data can be restored if the original is lost, damaged or corrupted.

Its two types are physical backup (a copy of the actual database files) and logical backup (a copy of the SQL statements needed to rebuild the database).

परिभाषा र दुई प्रकार, प्रत्येकको एक हरफको व्याख्यासहित।
3 marks Practice question

Differentiate between full, incremental and differential backup. Full, incremental र differential backup बीचको फरक लेख्नुहोस्।

FULL copies the entire database every time slowest to take, simplest to restore needs 1 file to restore INCREMENTAL copies only what changed since the LAST backup fastest to take, slowest to restore needs the full backup + EVERY incremental DIFFERENTIAL copies everything changed since the last FULL backup grows each day, quick to restore needs the full backup + the LATEST differential only

One mark each. Stating how many files a restore needs is what proves you have understood the difference rather than memorised two similar sentences.

एक–एक अंक। फर्काउन कति फाइल चाहिन्छ भनेर लेख्नुले घोकेको होइन, बुझेको देखाउँछ।
3 marks Practice question

What is database recovery? Explain redo and undo. डाटाबेस recovery के हो? Redo र undo व्याख्या गर्नुहोस्।

Recovery is the process of restoring a database to a correct and consistent state after a failure, using the log — a file recording every change before it is applied.

REDO re-applies the changes of transactions that had committed before the failure. The log is read forwards. This enforces durability.

UNDO reverses the changes of transactions that had not committed. The log is read backwards. This enforces atomicity.

The presence or absence of a COMMIT record in the log decides which one a transaction gets.

परिभाषा, redo, undo — र कुन लागू हुने भन्ने COMMIT रेकर्डले तय गर्छ भन्ने वाक्य नछुटाउनुहोस्।

Key points to revise — दोहोर्‍याउनुपर्ने मुख्य बुँदा

  • A backup is a separate copy taken in advance; recovery is the process of using it after a failure. They are not the same thing. Backup पहिले लिइने छुट्टै प्रतिलिपि हो; recovery असफलतापछि त्यो प्रयोग गर्ने प्रक्रिया। दुई फरक कुरा हुन्।
  • Physical backup copies the files; logical backup copies the SQL that would rebuild them. Physical backup ले फाइल, logical backup ले पुनर्निर्माण गर्ने SQL प्रतिलिपि गर्छ।
  • Incremental = since the last backup. Differential = since the last FULL backup. Restoring needs every incremental, but only the latest differential. Incremental = अघिल्लो backup देखि। Differential = अघिल्लो FULL backup देखि। फर्काउन सबै incremental चाहिन्छ, तर differential भने पछिल्लो एउटै।
  • Redo re-applies committed transactions and gives durability. Undo reverses uncommitted ones and gives atomicity. The COMMIT record decides which. Redo ले commit भएका फेरि लागू गर्छ — durability। Undo ले commit नभएका उल्टाउँछ — atomicity। COMMIT रेकर्डले तय गर्छ।
  • Security has three jobs: authentication (who you are), authorisation (what you may do) and encryption (unreadable if stolen). सुरक्षाका तीन काम: authentication (को हो), authorisation (के गर्न पाउने), encryption (चोरिए पनि नपढिने)।
  • Common threats: unauthorised access, SQL injection, malware, privilege abuse, weak passwords and unencrypted backups. सामान्य खतरा: अनधिकृत पहुँच, SQL injection, malware, अधिकारको दुरुपयोग, कमजोर पासवर्ड र encrypt नगरिएको backup।
