Inheritance

इनहेरिटेन्स — गुण सर्ने प्रक्रिया

10 hrs · 7 marks

By the end of this unit you can…

  1. Define inheritance and explain base class and derived class.
  2. Write the syntax of inheritance and name the three modes.
  3. Draw and explain all five types of inheritance.
  4. Say what happens to public, protected and private members under each mode.
  5. Predict the order in which constructors and destructors run.
  6. Explain the diamond problem and how a virtual base class solves it.

यो युनिट सकिँदा: परिभाषा, syntax, पाँचै प्रकारको चित्र, access मोडको असर, कन्स्ट्रक्टरको क्रम, र diamond problem भन्न सक्नुहुनेछ।

5.1  What is Inheritance?

Definition — learn this wording

Inheritance is the process by which one class acquires (gets) the properties and member functions of another class.

The class that gives its features is the base class (also called parent or super class). The class that receives them is the derived class (also called child or sub class).

The main purpose is reusability of code — common code is written once in the base class and reused by every derived class.

Inheritance represents an "IS-A" relationship: a Dog IS-A Animal, a Circle IS-A Shape. If you cannot say "IS-A", inheritance is probably the wrong tool.

परिभाषा — यही शब्द कण्ठ पार्नुहोस्

इनहेरिटेन्स भनेको एउटा क्लासले अर्को क्लासका गुण र मेम्बर फङ्सन प्राप्त गर्ने प्रक्रिया हो।

गुण दिने क्लास base class (बाबु/parent) हो। गुण पाउने क्लास derived class (छोरा/child) हो।

मुख्य उद्देश्य कोडको पुनः प्रयोग हो — साझा कोड एक पटक base मा लेख्ने र सबै derived क्लासमा चलाउने।

इनहेरिटेन्सले "IS-A" सम्बन्ध जनाउँछ: Dog एक प्रकारको Animal हो, Circle एक प्रकारको Shape हो।

Real-world analogy — a family

A child inherits eye colour, surname and blood group from a parent, and also has qualities of their own.

But the child does not get everything. The parent's private members are like a personal diary — it exists inside the parent, but the child cannot open it directly. That is exactly how private behaves in inheritance.

उदाहरण — परिवार। छोराले बाबुबाट आँखाको रङ, थर र रगतको समूह पाउँछ, र आफ्नै छुट्टै गुण पनि राख्छ। तर सबै कुरा पाउँदैन — बाबुको private मेम्बर व्यक्तिगत डायरी जस्तै हो: छ त, तर छोराले सिधै खोल्न पाउँदैन।
Advantages of inheritance
  • Reusability — common code is written once and reused by every child class.
  • Saves time and reduces code size — no duplication.
  • Easy to extend — new features go in a derived class without touching the tested base class.
  • Supports polymorphism — function overriding is impossible without inheritance.
  • Better structure — the parent–child relationship models the real world clearly.
  • Easier maintenance — fixing a bug in the base class fixes it for every derived class at once.
इनहेरिटेन्सका फाइदा
  • पुनः प्रयोग — साझा कोड एक पटक लेखेर सबै सन्तान क्लासमा चलाइन्छ।
  • समय र कोड बचत — दोहोरो लेख्नु पर्दैन।
  • सजिलो विस्तार — परीक्षण भइसकेको base नछोई derived मा नयाँ सुविधा थपिन्छ।
  • Polymorphism सम्भव बनाउँछ — inheritance बिना overriding हुँदैन।
  • राम्रो संरचना — बाबु–छोराको सम्बन्धले वास्तविक संसार प्रस्ट देखाउँछ।
  • सजिलो मर्मत — base मा गल्ती सुधार्दा सबै derived क्लासमा एकैचोटि सुधार हुन्छ।

5.4  Syntax of Inheritance

Example 1 The basic syntax, with output
#include <iostream>
using namespace std;

class Base {              // base / parent class
public:
    void greet() { cout << "Hello from Base" << endl; }
};

class Derived : public Base {     // <-- mode : base class name
public:
    void hi() { cout << "Hello from Derived" << endl; }
};

int main() {
    Derived d;
    d.greet();      // inherited from Base
    d.hi();         // its own function
    return 0;
}
Output 
Hello from Base
Hello from Derived

Object d is a Derived, yet it can call greet() which was never written inside Derived. That is inheritance doing its job. अब्जेक्ट d चाहिँ Derived हो, तर Derived भित्र कहिल्यै नलेखिएको greet() बोलाउन सक्छ। यही इनहेरिटेन्सको काम हो।

The word after the colon (:) is the mode of inheritance — public, protected or private. If you write nothing, a class defaults to private inheritance (a struct defaults to public). In practice, public is used almost always.

What the derived class actually receives

Base member is…public inheritanceprotected inheritanceprivate inheritance
publicstays publicbecomes protectedbecomes private
protectedstays protectedstays protectedbecomes private
privateNever inherited / not accessible in the derived class, in any mode. कुनै पनि मोडमा derived क्लासले base को private मेम्बर सिधै प्रयोग गर्न पाउँदैन।
Common mistake
Trying to use a base class private member inside the derived class: 
class A { private: int x; };
class B : public A {
public:
    void show() { cout << x; }   // ERROR: x is private in A
};
If a child class needs it, the base must declare it protected, not private. base को private मेम्बर derived भित्र प्रयोग गर्न खोज्नु गल्ती हो। सन्तानलाई चाहिन्छ भने base मा protected लेख्नुपर्छ, private होइन।

5.5  Types of Inheritance

Five types. The exam very often says "explain the types of inheritance with diagrams" — so learn to draw each shape as well as write its syntax.

TypeMeaningSyntax
Single One base class → one derived class. The simplest form. एउटा base बाट एउटा derived क्लास। class B : public A { };
Multilevel A chain — a derived class itself becomes the base of another class. Grandparent → parent → child. शृंखला — derived क्लास आफैं अर्कोको base बन्छ। class B : public A { };
class C : public B { };
Multiple Two or more base classes → one derived class. The bases are separated by commas. दुई वा बढी base बाट एउटा derived क्लास। class C : public A, public B { };
Hierarchical One base class → many derived classes. Several children share one parent. एउटा base बाट धेरै derived क्लास। class B : public A { };
class C : public A { };
Hybrid A combination of two or more of the above types — for example hierarchical plus multiple. This can create the diamond problem. माथिका दुई वा बढी प्रकारको मिश्रण। combination of the above
Example 2 Multiple inheritance — two bases, one derived
#include <iostream>
using namespace std;

class Father {
public:
    void height() { cout << "Tall from father" << endl; }
};

class Mother {
public:
    void colour() { cout << "Fair from mother" << endl; }
};

class Child : public Father, public Mother {   // TWO bases
public:
    void own() { cout << "Smart on my own" << endl; }
};

int main() {
    Child c;
    c.height();     // from Father
    c.colour();     // from Mother
    c.own();        // its own
    return 0;
}
Output 
Tall from father
Fair from mother
Smart on my own

The diamond problem and virtual base class

The problem

In hybrid inheritance, suppose B and C both inherit from A, and D inherits from both B and C.

D then receives two copies of everything in A — one through B and one through C. When you write d.show() the compiler cannot decide which copy to use, and reports an ambiguity error. Because the diagram is diamond-shaped, this is called the diamond problem.

समस्या

Hybrid inheritance मा मानौं B र C दुवैले A बाट इनहेरिट गर्छन्, र D ले B र C दुवैबाट।

तब D ले A का सबै कुराको दुई प्रति पाउँछ — एउटा B बाट, अर्को C बाट। d.show() लेख्दा कम्पाइलरले कुन प्रति चलाउने भन्ने निर्णय गर्न सक्दैन र ambiguity error देखाउँछ। चित्र हीरा जस्तो देखिने भएकाले यसलाई diamond problem भनिन्छ।

Example 3 Solving it with a virtual base class
class A {
public:
    void show() { cout << "From A"; }
};

class B : virtual public A { };    // <-- virtual
class C : virtual public A { };    // <-- virtual

class D : public B, public C { };

int main() {
    D d;
    d.show();     // now unambiguous - only ONE copy of A exists
    return 0;
}
Output 
From A

The keyword virtual tells C++ to keep only one shared copy of A, so the ambiguity disappears. A base class declared this way is called a virtual base class. virtual शब्दले C++ लाई A को एउटै साझा प्रति राख्न भन्छ, त्यसैले अलमल हट्छ। यसरी घोषित base क्लासलाई virtual base class भनिन्छ।

Constructor and destructor order — asked very often

The rule in one line
When a derived object is created, the base class constructor runs FIRST, then the derived constructor. Destructors run in the exact reverse: derived destructor first, then base destructor. derived अब्जेक्ट बन्दा पहिले base को कन्स्ट्रक्टर चल्छ, अनि derived को। डिस्ट्रक्टर ठ्याक्कै उल्टो — पहिले derived, अनि base।
Example 4 Proving the order — predict this output before you read it
#include <iostream>
using namespace std;

class A {
public:
    A() { cout << "A constructor" << endl; }
    ~A() { cout << "A destructor" << endl; }
};

class B : public A {
public:
    B() { cout << "B constructor" << endl; }
    ~B() { cout << "B destructor" << endl; }
};

int main() {
    B obj;          // only ONE object is created
    return 0;
}
Output 
A constructor
B constructor
B destructor
A destructor

Four lines from one object. The base is built first (you cannot build the first floor before the ground floor) and destroyed last. एउटै अब्जेक्टबाट चार लाइन। base पहिले बन्छ (भुइँतला नबनाई पहिलो तला बन्दैन) र अन्तिममा भत्किन्छ।

Exam focus — questions asked from this unit

SEE exam connection · परीक्षा जोड

Types of inheritance and constructor call order carry the marks here — the order question appears very often.

Inheritance का प्रकार र constructor चल्ने क्रममा अंक छन् — क्रमको प्रश्न धेरै पटक आउँछ।
Q1 · Define inheritance. Explain base class and derived class with syntax. [4 marks]

Inheritance is the process by which one class acquires the properties and member functions of another class. The class whose features are inherited is called the base class (parent), and the class that inherits them is called the derived class (child). The main purpose is reusability of code.

Syntax: class Derived : access_mode Base { … }; for example class Dog : public Animal { };

परिभाषा + base/derived + syntax — तीनै लेख्नुहोस्।
Q2 · Explain the types of inheritance with suitable diagrams. [6 marks]

Draw all five diagrams and give one line each:

Single — one base, one derived (A → B).
Multilevel — a chain where a derived class becomes a base (A → B → C).
Multiple — two or more bases, one derived (A and B → C).
Hierarchical — one base, many derived (A → B and A → C).
Hybrid — a combination of two or more of the above; may cause the diamond problem, solved with a virtual base class.

पाँचै चित्र कोर्नुहोस् र एक–एक लाइन व्याख्या दिनुहोस्। चित्र बिना पूरा अंक आउँदैन।
Q3 · What is the output of the given program? (base and derived constructors) [3 marks]

Apply the rule: base class constructor first, then derived; destructors in exact reverse order. For a two-level program the answer is: A constructor, B constructor, B destructor, A destructor.

For a three-level chain (Animal → Dog → Puppy) it is: Animal, Dog, Puppy going in and ~Puppy, ~Dog, ~Animal coming out.

नियम लगाउनुहोस्: बन्दा माथिबाट तल, नष्ट हुँदा तलबाट माथि।
Q4 · What is the diamond problem? How is it solved? [3 marks]

In hybrid inheritance, when two classes B and C both inherit from the same base A, and a fourth class D inherits from both B and C, class D receives two copies of A's members. The compiler cannot decide which copy to use, causing an ambiguity error. This is called the diamond problem.

It is solved by declaring A as a virtual base class: class B : virtual public A { }; — then only one shared copy of A exists.

समस्या + virtual कीवर्डको समाधान — दुवै लेख्नुहोस्।

Key points to revise — दोहोर्‍याउनुपर्ने मुख्य बुँदा

  • Inheritance = one class acquires the properties and functions of another. Purpose: reusability.
  • Base = parent = gives. Derived = child = receives. Relationship is IS-A.
  • Syntax: class Derived : public Base { }; — the word after : is the mode.
  • Five types: single, multilevel, multiple, hierarchical, hybrid — be able to draw all five.
  • private members are NEVER inherited, in any mode. Use protected if the child needs access.
  • Default inheritance mode for a class is private.
  • Constructors: base first, then derived. Destructors: exact reverse.
  • Diamond problem comes from hybrid inheritance; solved by a virtual base class.
