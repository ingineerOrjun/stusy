Polymorphism

पोलिमर्फिज्म — एउटै नाम, धेरै रूप

10 hrs · 7 marks

By the end of this unit you can…

  1. Define polymorphism and explain where the word comes from.
  2. Draw the tree of polymorphism types and name what achieves each.
  3. Write programs using function overloading and operator overloading.
  4. Explain function overriding and the virtual keyword.
  5. Compare overloading vs overriding — the most-tested table in the unit.
  6. Predict the output of a program that uses a base class pointer.

यो युनिट सकिँदा: परिभाषा, प्रकारको रूख, overloading र overriding का प्रोग्राम, virtual को काम, र तुलनात्मक तालिका लेख्न सक्नुहुनेछ।

6.1  What is Polymorphism?

Definition — learn this wording

The word polymorphism comes from Greek: poly means many and morph means forms. So polymorphism literally means "many forms".

In C++, polymorphism is the ability of the same function name or the same operator to behave differently in different situations, depending on the object or on the arguments used.

परिभाषा — यही शब्द कण्ठ पार्नुहोस्

Polymorphism ग्रीक शब्दबाट बनेको हो: poly = धेरै, morph = रूप। अर्थात् "धेरै रूप"।

C++ मा एउटै फङ्सनको नाम वा एउटै अपरेटर ले फरक अवस्थामा फरक व्यवहार गर्ने क्षमतालाई polymorphism भनिन्छ — कुन अब्जेक्ट वा कस्तो आर्गुमेन्ट प्रयोग भयो, त्यसमा भर पर्छ।

Real-world analogy — one person, many roles

One person is a son at home, a student at school, a customer in a shop and a patient at the hospital.

Same person — different behaviour in different places. The name did not change; the situation decided the behaviour. That is polymorphism.

उदाहरण — एउटै मान्छे, धेरै भूमिका। एउटै मान्छे घरमा छोरा, स्कुलमा विद्यार्थी, पसलमा ग्राहक र अस्पतालमा बिरामी हुन्छ। व्यक्ति उही, ठाउँ अनुसार व्यवहार फरक। नाम फेरिएन, अवस्थाले व्यवहार तय गर्‍यो — यही polymorphism हो।

6.4  Types of Polymorphism

A. Compile-time Polymorphism

Also called static polymorphism or early binding. The compiler decides which function to call while compiling, by looking at the number and type of the arguments.

Achieved by:
Function Overloading Operator Overloading

यसलाई static polymorphism वा early binding भनिन्छ। कुन फङ्सन बोलाउने भन्ने कुरा कम्पाइल गर्दै आर्गुमेन्टको संख्या र प्रकार हेरेर निर्णय हुन्छ। यो छिटो हुन्छ किनकि निर्णय पहिल्यै भइसकेको हुन्छ।

B. Run-time Polymorphism

Also called dynamic polymorphism or late binding. The decision is made while the program is running, by looking at which object the base class pointer is actually pointing to.

Achieved by:
Function Overriding Virtual Functions

यसलाई dynamic polymorphism वा late binding भनिन्छ। निर्णय प्रोग्राम चल्दै गर्दा हुन्छ — base पोइन्टरले वास्तवमा कुन अब्जेक्ट देखाइरहेको छ त्यो हेरेर। यो अलि ढिलो तर बढी लचिलो हुन्छ।

Function Overloading — compile-time

Function overloading

Function overloading means writing two or more functions with the same name in the same class, but with different parameter lists.

The parameter lists must differ in the number of parameters, the type of parameters, or their order.

Important: a difference in the return type alone is NOT enough. Two functions with the same name and same parameters but different return types cause a compiler error.

फङ्सन ओभरलोडिङ

Function overloading भनेको उही क्लास भित्र उही नाम तर फरक प्यारामिटर भएका दुई वा बढी फङ्सन लेख्नु हो।

प्यारामिटर संख्या, प्रकार, वा क्रम मा फरक हुनुपर्छ।

महत्त्वपूर्ण: return type मात्र फरक भएर पुग्दैन। नाम र प्यारामिटर उही तर return type फरक भए कम्पाइलर error दिन्छ।

Example 1 Function overloading — three versions of area()
#include <iostream>
using namespace std;

class Shape {
public:
    void area(int s) {                    // 1 int
        cout << "Square area = " << s * s << endl;
    }
    void area(int l, int b) {             // 2 ints
        cout << "Rectangle area = " << l * b << endl;
    }
    void area(float r) {                  // 1 float - different TYPE
        cout << "Circle area = " << 3.14 * r * r << endl;
    }
};

int main() {
    Shape s;
    s.area(5);          // matches version 1
    s.area(4, 6);       // matches version 2
    s.area(2.0f);       // matches version 3
    return 0;
}
Output 
Square area = 25
Rectangle area = 24
Circle area = 12.56

One name, three jobs. Version 1 and 3 both take a single argument — they are still valid overloads because the types differ (int vs float). एउटै नाम, तीन काम। संस्करण १ र ३ दुवैले एउटै आर्गुमेन्ट लिन्छन् — तर प्रकार फरक (int vs float) भएकाले दुवै मान्य overload हुन्।

Operator overloading

Operator overloading

Operator overloading means giving an additional meaning to an existing C++ operator so that it also works with objects of your own class.

For example + normally adds numbers. By overloading it, you can make c1 + c2 add two Complex number objects.

The syntax uses the keyword operator followed by the symbol.

अपरेटर ओभरलोडिङ

Operator overloading भनेको भइरहेको C++ अपरेटरलाई थप अर्थ दिनु हो, ताकि यो तपाईंकै क्लासका अब्जेक्टसँग पनि काम गरोस्।

जस्तै + ले सामान्यतया संख्या जोड्छ। ओभरलोड गरेपछि c1 + c2 ले दुई Complex अब्जेक्ट जोड्न सक्छ।

Syntax मा operator कीवर्ड पछि चिन्ह लेखिन्छ।

Example 2 Overloading the + operator
#include <iostream>
using namespace std;

class Complex {
    int real, imag;
public:
    Complex(int r = 0, int i = 0) { real = r; imag = i; }

    Complex operator + (Complex c) {      // overloading +
        Complex temp;
        temp.real = real + c.real;
        temp.imag = imag + c.imag;
        return temp;
    }
    void show() { cout << real << " + " << imag << "i" << endl; }
};

int main() {
    Complex c1(3, 2), c2(1, 7);
    Complex c3 = c1 + c2;      // + now works on objects
    c3.show();
    return 0;
}
Output 
4 + 9i

Note that + still adds ordinary numbers exactly as before. Overloading adds a meaning; it never removes the original one. + ले सामान्य संख्या पहिले जस्तै जोड्छ। ओभरलोडिङले अर्थ थप्छ, पुरानो अर्थ हटाउँदैन।

6.5  Function Overriding — run-time

Function overriding

Function overriding means the derived class defines a function with exactly the same name, the same return type and the same parameters as a function already present in its base class.

The derived version replaces the base version for objects of the derived class. Overriding requires inheritance — it is impossible without a base and a derived class.

If the base function is marked virtual and you call it through a base class pointer, C++ calls the derived version at run time. That is run-time polymorphism. Without virtual, the base version is called instead.

फङ्सन ओभरराइडिङ

Function overriding भनेको derived क्लासमा base क्लासकै फङ्सन जस्तै उही नाम, उही return type र उही प्यारामिटर भएको फङ्सन लेख्नु हो।

derived अब्जेक्टका लागि derived कै संस्करणले base को संस्करणलाई प्रतिस्थापन गर्छ। Overriding का लागि inheritance अनिवार्य छ।

base फङ्सनमा virtual लेखिएको छ र base पोइन्टर बाट बोलाइयो भने C++ ले चल्दै गर्दा derived संस्करण बोलाउँछ — यही run-time polymorphism हो। virtual नलेखे base कै संस्करण चल्छ।

Example 3 With and without virtual — the exam's favourite trick
class Base {
public:
    void show() { cout << "Base show" << endl; }      // NOT virtual
};
class Derived : public Base {
public:
    void show() { cout << "Derived show" << endl; }
};

int main() {
    Base *p;  Derived d;
    p = &d;
    p->show();        // prints "Base show"  <-- surprising!
    return 0;
}
Output without virtual 
Base show

Now add one word — virtual void show() in Base — and the very same program prints Derived show instead. One keyword changes the whole output. That is exactly what the examiner is testing. अब Base मा एउटा शब्द थप्नुहोस् — virtual void show() — र उही प्रोग्रामले Derived show छाप्छ। एउटा कीवर्डले पूरै आउटपुट फेर्छ। परीक्षकले जाँच्ने ठ्याक्कै यही हो।

Common mistake
Thinking overriding works through the object as well as the pointer. If you write Derived d; d.show(); the derived version runs whether or not the function is virtual — because the object's type is known exactly. virtual only matters when you call through a base class pointer or reference. Derived d; d.show(); लेख्दा virtual भए पनि नभए पनि derived कै संस्करण चल्छ — किनकि अब्जेक्टको प्रकार ठ्याक्कै थाहा हुन्छ। virtual को महत्त्व base पोइन्टर बाट बोलाउँदा मात्र देखिन्छ।

▶  Experiment — Which function actually runs?

Decide first, then check. This is the single most-tested idea in the unit, and the one students most often get backwards.

Predict first · पहिले अनुमान गर्नुहोस्

Shape has a virtual void show(). Circle overrides it. You write Shape *p = &c; where c is a Circle, then call p->show(). Which one runs?

Because show() is virtual, C++ waits until the program is running and looks at the object, not at the pointer's type. The object is a Circle, so Circle::show() runs. Delete the word virtual and the answer flips to Shape::show() — that is the whole idea in one line.

show() virtual भएकाले C++ ले प्रोग्राम चल्दै गर्दा पोइन्टरको प्रकार होइन, अब्जेक्ट हेर्छ। अब्जेक्ट Circle भएकाले Circle::show() चल्छ। virtual हटाए उत्तर Shape::show() मा पल्टिन्छ — पूरै कुरा यही एक लाइनमा छ।

Interactive experiment · अन्तरक्रियात्मक प्रयोग

Compile-time choice vs run-time choice

What you will learn: when C++ decides which function to call. Overloading is settled while compiling; a virtual call is settled while running. तपाईंले के सिक्नुहुन्छ: C++ ले कुन फङ्सन बोलाउने भन्ने कहिले निर्णय गर्छ — overloading कम्पाइल गर्दा, virtual चल्दै गर्दा।

Try each call
Why did this happen?

Overloading — the compiler counts the arguments and picks the matching version before the program ever runs. Compile-time.

Virtual override — the computer looks at the object the pointer actually points to, while the program is running. Run-time. Same call, different output.

Overloading: कम्पाइलरले आर्गुमेन्ट गनेर प्रोग्राम चल्नु अघि नै छान्छ — compile-time। Virtual override: पोइन्टरले देखाएको वास्तविक अब्जेक्ट हेरेर चल्दै गर्दा छान्छ — run-time। उही कल, फरक आउटपुट।

Overloading vs Overriding — the key table

BasisFunction OverloadingFunction Overriding
MeaningSame function name with different parameters in the same class.Same function name with the same parameters, redefined in a derived class.
InheritanceNot required.Required — there must be a base and a derived class.
ParametersMust be different — in number, type or order.Must be exactly the same.
Return typeMay be same or different (return type alone is not enough).Must be the same.
BindingEarly / static binding.Late / dynamic binding when virtual is used.
TypeCompile-time polymorphism.Run-time polymorphism.
virtual keywordNot used.virtual is used in the base class.
PurposeTo give one name to several similar jobs.To give the child a different version of the parent's function.
छोटो सार

Overloading = उही क्लासमा उही नाम तर फरक प्यारामिटर; inheritance चाहिँदैन; compile-time। Overriding = derived क्लासमा उही नाम र उही प्यारामिटर; inheritance चाहिन्छ; virtual राखे run-time।

Advantages of polymorphism
  • One interface, many implementations — easier to read, write and remember.
  • Code reusability and shorter programs.
  • Flexibility — new derived classes can be added without changing existing code.
  • Supports dynamic binding and cleaner program design.
  • Reduces the number of different function names a programmer must remember.
पोलिमर्फिज्मका फाइदा
  • एउटै इन्टरफेस, धेरै काम — पढ्न, लेख्न र सम्झन सजिलो।
  • कोड पुनः प्रयोग र छोटो प्रोग्राम।
  • लचकता — पुरानो कोड नछोई नयाँ derived क्लास थप्न सकिन्छ।
  • Dynamic binding सम्भव बनाउँछ।
  • फरक–फरक नाम सम्झिरहनु पर्दैन।

Exam focus — questions asked from this unit

SEE exam connection · परीक्षा जोड

Overloading versus overriding, and compile-time versus run-time, are the highest-frequency questions in the whole subject.

Overloading र Overriding, अनि Compile-time र Run-time — यी पूरै विषयकै सबैभन्दा बढी सोधिने प्रश्न हुन्।
Q1 · Define polymorphism. Explain its types with examples. [6 marks]

Polymorphism comes from the Greek words poly (many) and morph (forms), so it means many forms. In C++ it is the ability of the same function name or operator to behave differently in different situations.

Compile-time (static) polymorphism — the compiler decides which function to call while compiling, by checking the arguments. It is achieved by function overloading and operator overloading. Example: three area() functions with different parameters.

Run-time (dynamic) polymorphism — the decision is made while the program runs, based on the object the base pointer points to. It is achieved by function overriding with virtual functions. Example: Base *p = &derivedObj; p->show();

परिभाषा + दुवै प्रकार + एक–एक उदाहरण। चित्र (रूख) कोरे झन् राम्रो।
Q2 · Differentiate between function overloading and function overriding. [5 marks]

Write a table with at least five rows: meaning (same class, different parameters vs derived class, same parameters); inheritance (not required vs required); parameters (must differ vs must be identical); binding (early/static vs late/dynamic); type (compile-time vs run-time); and the virtual keyword (not used vs used in the base class).

कम्तीमा पाँच हरफको तालिका लेख्नुहोस्।
Q3 · What is a virtual function? Why is it needed? [3 marks]

A virtual function is a member function declared in the base class using the keyword virtual and redefined (overridden) in a derived class.

It is needed so that when the function is called through a base class pointer, C++ decides at run time which version to run by looking at the actual object being pointed to, instead of the pointer's type. Without virtual the base class version would always be called, and run-time polymorphism would be impossible.

परिभाषा + किन चाहिन्छ (base पोइन्टरबाट derived संस्करण चलाउन) — दुवै लेख्नुहोस्।
Q4 · Write a program to demonstrate run-time polymorphism. [5 marks]

Write a base class Shape with virtual void draw(), two derived classes Circle and Square that each override draw(), and a main() that declares Shape *p; then points it first at a Circle object and then at a Square object, calling p->draw(); each time.

The output will be "Drawing a Circle" then "Drawing a Square" — the same call giving two different results. That is the full program traced step by step in the Trace a Program section.

Trace a Program सेक्सनको Program 3 नै यसको पूरा उत्तर हो — त्यहीँ लाइन–लाइन हेर्नुहोस्।

Key points to revise — दोहोर्‍याउनुपर्ने मुख्य बुँदा

  • Polymorphism = poly (many) + morph (forms) = one name, many forms.
  • Compile-time = static = early binding → function overloading + operator overloading.
  • Run-time = dynamic = late binding → function overriding + virtual functions.
  • Overloading: same class, different parameters, no inheritance needed.
  • Overriding: derived class, identical signature, inheritance required.
  • Return type alone cannot overload a function.
  • virtual matters only when calling through a base class pointer or reference.
  • Remove virtual and the base version runs — this is the classic output question.
