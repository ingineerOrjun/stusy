## 2. What was audited

Six developed units read as learning experiences (component sequence extracted
from every source file), the design system, navigation, bilingual presentation,
and live measurement at 320 / 375 / 768px. Full findings:
[PHASE-2-UX-AUDIT.md](PHASE-2-UX-AUDIT.md).

The audit's central finding: **the passive half of the learning loop was strong,
the active half barely existed.** 32 bilingual explanations and 22 diagrams, but
interaction in 2 of 6 units, no prediction anywhere, and every unit's exam
questions grouped at the very bottom.

## 3. What changed

### Design system

- **`design/tokens.css` restructured into three layers** — primitives → semantic
  roles → scales. Components now reference meaning (`--color-error`) rather than
  hue (`--coral`). Palette unchanged.
- **Scales added:** spacing (4px base, 11 steps + 3 rhythm tokens), type (8 steps,
  12px floor), radius (5), elevation (3), motion (3 + easing), touch floor.
- **`design/learning-ux.css`** — a fourth layer that corrects the earlier ones
  without rewriting them.

### Responsive

- **The containment fix.** `min-width: 0` on layout-container children removed
  226px of page overflow. Root cause was the grid/flex `min-width: auto` default
  inflating a track to 528px inside a 339px container.
- Wide content scrolls inside its own container; `core.js` marks genuinely
  overflowing regions `.is-scrollable`, adding an edge fade and keyboard focus.
- Touch floor of 44px under `pointer: coarse` only, so desktop keeps its density.

### Learning components

- **`.predict`** — new. Commit → reveal → compare → explain, with bilingual
  verdict, ARIA, one-commitment locking, delegated (no inline handlers).
- **`.sim`** — new container: kicker, title, **objective**, stage, labelled
  controls, result, **"why did this happen?"**. The last two are required by the
  build.
- **`.exam-connect`** — frames practice by naming what the SEE asks from that
  unit, in both languages, before the questions.

### Accessibility

- Heading levels derived from document nesting; navigation labels are no longer
  headings. Every page: exactly one `h1`, zero skips.
- `.console` → `role="log"` + `aria-live="polite"`; a screen-reader user now
  hears simulator output instead of silence.
- `.btn-ans` → `aria-expanded` + `aria-controls`.
- 12px type floor; `--lh-deva` 1.85 for Devanagari.
- `prefers-reduced-motion` honoured.

### Tooling

- **`design-system.html`** — every component on one page, generated by the real
  build, linked from nothing. A test asserts it stays unlinked.
- **Validation extended** to the new components: a prediction whose answer
  matches no option, or whose feedback has no Nepali, **fails the build**.

## 7. Technical debt

Carried forward: inline handlers (#6), contrast tokens (#4), diagram SVG
duplicated per page, `config/pages.js` still assumes one authored subject.

Added this phase: `learning-ux.css` is a corrective layer over `base.css` and
`site.css` rather than those files being fixed at source. That was the right call
for a phase that must not break 20 working pages, but a future consolidation
should fold the corrections down. The containment rule's selector list must be
extended when a new layout container is added — covered by a test, but it is a
list that can go stale.

## 9. Honest assessment

**What genuinely improved.** The site no longer scrolls sideways on a phone —
the single defect most likely to make a student abandon it, and it affected every
page. Heading structure went from actively misleading to correct on all 21 pages.
The design system now has the scales and roles it was missing, so the 500th
lesson has a shape to fall into. And the active half of the learning loop finally
has components: a prediction pattern that did not exist, and a simulation frame
that forces every simulation to say what it teaches and why the result happened.

**What a reviewer would fairly push back on.** Two of the six units gained new
interactive content; the other four benefited only from system-level fixes. The
exam-question placement problem was framed rather than solved. The bilingual
mobile-stacking tension is documented honestly but remains unsolved. And the
corrective-layer CSS is a pragmatic choice that adds a small amount of debt.

**What did not happen, by design.** No redesign. No framework. No backend. No
gamification, streaks, points or badges. No fake progress. The 20 pages a student
sees are the same 20 pages — with the sideways scrolling gone, larger tap
targets, readable type, a correct document outline, and two new ways to actually
think rather than only read.
