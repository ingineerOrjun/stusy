# Design System

The visual contract every subject inherits. Live reference: **`design-system.html`**
(generated by the build, never linked from student navigation).

---

## 1. Three layers

```
PRIMITIVES   raw values          --yellow, --panel, --line
     ↓
SEMANTIC     roles               --color-primary, --color-surface, --color-error
     ↓
SCALES       systematic steps    --sp-*, --fs-*, --r-*, --elev-*, --dur-*
```

**Rule: a component references a semantic token or a scale step. Never a
primitive, never a literal.** That is the whole mechanism by which 500 lessons
stay consistent. A test asserts the Phase 2 layer contains no raw hex values.

The palette itself is **unchanged from Phase 1** — Phase 2 built the system
around it rather than restyling the product.

## 3. Typography

| Family | Token | Use |
| --- | --- | --- |
| JetBrains Mono | `--mono` | Code, labels, data, metadata |
| Noto Sans | `--sans` | English prose |
| Noto Sans Devanagari | `--deva` | Nepali |

Every stack has a local fallback (Consolas, Segoe UI, **Mangal**), so the site
stays legible when the web font fails — the common case on a slow connection.

### Scale

| Token | Size | Role |
| --- | --- | --- |
| `--fs-xs` | 0.75rem / 12px | Labels, captions — **the floor** |
| `--fs-sm` | 0.85rem | Secondary prose, table cells |
| `--fs-base` | 1rem | Body |
| `--fs-md` | 1.05rem | Lead paragraphs |
| `--fs-lg` | 1.2rem | Sub-topic |
| `--fs-xl` | 1.45rem | Topic |
| `--fs-2xl` | 1.75rem | Lesson title |
| `--fs-3xl` | 2.15rem | Page title |

This replaced **20+ ad-hoc sizes** ranging down to 0.6rem. The audit measured
10px rendered text; the floor is now 12px.

### Line height

`--lh-tight` 1.25 headings · `--lh-snug` 1.45 code · `--lh-base` 1.65 body ·
**`--lh-deva` 1.85 Nepali**.

Devanagari carries the connecting *shirorekha* and stacked conjuncts, so it needs
more leading than Latin at the same size. Applied automatically via `[lang="ne"]`.

## 4. Spacing

4px base. Replaces the 16 different literal values the audit found.

`--sp-1` 4 · `--sp-2` 8 · `--sp-3` 12 · `--sp-4` 16 · `--sp-5` 20 · `--sp-6` 24 ·
`--sp-8` 32 · `--sp-10` 40 · `--sp-12` 48 · `--sp-16` 64

**Rhythm tokens** name spacing by role so pacing survives many authors:

| Token | Value | Between |
| --- | --- | --- |
| `--space-section` | 48px | Numbered topics |
| `--space-block` | 20px | Components within a topic |
| `--space-tight` | 12px | Inside a component |

## 5. Radius, elevation, motion

**Radius:** `--r-sm` 8 (controls) · `--r-md` 12 (code, tables, figures) ·
`--r-lg` 14 (panels) · `--r-xl` 18 (page head) · `--r-full` (pills).

**Elevation** — three steps, because depth marks importance and is not decoration:
`--elev-1` resting card · `--elev-2` panel/simulation · `--elev-3` overlay.

**Motion** — `--dur-fast` 120ms (hover, focus) · `--dur-base` 200ms (reveal) ·
`--dur-slow` 320ms (entering content) · `--ease`.

> **Motion principle.** Animation signals a state change or shows a process.
> It is never decorative. Anything longer than `--dur-slow` must be a step the
> student controls — which is why the simulators are stepped, not animated.

`prefers-reduced-motion: reduce` collapses every duration to zero. Asserted by test.

## 6. Touch and focus

`--touch-min: 44px`. Under `@media (pointer: coarse)` every control clears it;
desktop keeps its density because a mouse does not need a 44px target.

One focus treatment everywhere: `2px solid var(--color-focus)` with 2px offset on
`:focus-visible`, so keyboard users get a ring and mouse users do not.

## 7. Responsive

| Breakpoint | Collapses |
| --- | --- |
| 940px | Desktop nav → hamburger |
| 900px | Hero |
| 820px | `.pair`, simulator grids |
| 640px | Pager, lesson padding, heading sizes |

### The containment rule

```css
.pair > *, .simgrid > *, .cards > * … { min-width: 0; }
```

Grid and flex items default to `min-width: auto`, so a track can never shrink
below its content. That single default produced **226px of horizontal page
overflow at 320px**. This rule is load-bearing and is covered by a test.

Wide content — diagrams, tables, code — scrolls **inside its own container**,
never the page. Where content genuinely overflows, `core.js` adds
`.is-scrollable`, which paints an edge fade and makes the region keyboard
focusable, so a cropped diagram no longer reads as a broken one.

**Why diagrams scroll rather than scale:** a 520px diagram scaled into 284px
renders its 12px labels at ~6.5px. Controlled horizontal scrolling keeps them
legible. This is a deliberate choice, not a fallback.

## 8. Using the system

**Do**

- Reference `var(--color-*)`, `var(--sp-*)`, `var(--fs-*)`
- Compose from the existing component vocabulary
- Add a component only when a pattern repeats and is not expressible
- Check a change against every component on `design-system.html`

**Do not**

- Write a hex value, a literal px size, or an ad-hoc duration in a component
- Style by tag where a class exists — `.topic` carries appearance, the `<h2>`
  carries meaning, and the build sets the level
- Add a shadow, gradient or animation without a reason a student would notice

## 9. Product quality guardrails

The audit's standard, restated as rules the design must keep meeting:

- No decorative gradients, glassmorphism, or shadow stacking
- No heading that consumes a mobile screen — `.outcomes h2` is deliberately
  sized as a label despite being an `h2`
- No two adjacent sections with identical visual weight
- No control under the touch floor
- No text under 12px
- No animation without a learning purpose
