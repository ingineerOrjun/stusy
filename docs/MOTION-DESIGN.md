# Motion Design

How the platform moves, and why. Live reference: **`animation-showcase.html`**
(generated by the build, never linked from student navigation).

---

## 1. The one rule

> **Motion must answer: what educational concept does this movement communicate?**

If the honest answer is "it looks modern", the element stays still.

| Good | Because |
| --- | --- |
| A value enters a stack at the top | The movement *is* the definition of push |
| Constructors reveal top-down, destructors bottom-up | The order is the exam answer |
| A pointer's arrow moves to a different object | Re-binding is the mechanism |
| The executing code line transitions | The eye can follow where execution went |

| Bad | Because |
| --- | --- |
| A card floating up and down | Communicates nothing |
| A diagram pulsing continuously | State is not changing |
| Everything animating at once | Nothing is emphasised |
| A spinner on a static figure | Suggests activity that is not happening |

## 2. Three levels

| Level | What it is | Duration | Examples |
| --- | --- | --- | --- |
| **L1 · Micro-interaction** | The interface acknowledging a touch | 120–200ms | Hover, focus ring, button press, answer reveal |
| **L2 · Educational transition** | A component changing state | 200–320ms | Node activating, step advancing, value changing, box entering a structure |
| **L3 · Educational simulation** | The motion **is** the concept | 520ms transforms, 760ms between steps | Constructor order, pointer dispatch, stack push, traversal |

L1 should be felt, not watched. L2 must be clearly visible but never distracting.
L3 is expressive because the movement carries the teaching — and is therefore
always **student-controlled**, never autoplayed on load.

## 3. Duration tokens

Chosen against what the eye and the reading brain need, not copied from a framework.

| Token | Value | Reasoning |
| --- | --- | --- |
| `--dur-fast` | 120ms | Below conscious notice — feels instant without being abrupt |
| `--dur-base` | 200ms | The shortest change the eye can reliably track |
| `--dur-slow` | 320ms | An element entering or leaving a structure |
| `--dur-deliberate` | 520ms | A transformation the student is meant to follow |
| `--dur-step` | 760ms | The gap between narrated steps — long enough to read a bilingual caption, short enough to hold attention. Inherited from the existing tracer pacing, which reads well in practice |

`MotionService.ms(name)` returns these to JavaScript, so code and CSS cannot drift.
A test asserts the two agree.

## 4. Easing carries meaning

| Token | Curve | Used for |
| --- | --- | --- |
| `--ease-standard` | `cubic-bezier(.2,.6,.3,1)` | General state change |
| `--ease-emphasis` | `cubic-bezier(.2,.9,.25,1)` | A change that must be noticed |
| `--ease-enter` | `cubic-bezier(0,.7,.3,1)` | Element arriving — decelerates and settles |
| `--ease-exit` | `cubic-bezier(.5,0,.9,.3)` | Element leaving — accelerates away |
| `--ease-flow` | `linear` | **Constant-rate travel of data** |

The last one is a teaching decision, not a taste one. A value moving along a bus
or a pointer travels at a constant rate; easing it would show acceleration that
does not exist in the mechanism. Interface motion is eased; data movement is linear.

## 5. Stagger

`--stagger-sm` 40ms · `--stagger-md` 80ms · `--stagger-lg` 140ms

40ms reads as "ordered but together". 80ms reads as a clear sequence. 140ms is
for a small number of major stages only — beyond that it becomes waiting.

## 6. Animation primitives

Small composable behaviours, not a component per effect. All finite.

| Primitive | Where it lives | Purpose |
| --- | --- | --- |
| `setState` / `activate` | `MotionService` | Apply the shared state language |
| `pulse` | `MotionService` | One-shot attention. **Never loops** |
| `changeValue` | `MotionService` | Connect an old value to its replacement so the student sees it *changed* rather than finding a different number |
| `sequence` | `MotionService` | Step player with play / pause / resume / goTo / reset |
| `dia-step` | CSS + `DiagramRuntime` | Reveal a diagram element at a step |
| `dia-focus` | CSS + `DiagramRuntime` | Emphasise a shape without moving it |
| `dia-travel` | CSS | Move an element along the diagram's coordinates |
| `dia-draw` | CSS | Draw a connection so the eye follows its direction |
| `dia-dim` | CSS | Keep context visible but clearly not the focus |

## 7. The shared state language

One vocabulary across diagrams, simulators, the quiz and the tracer, so a
success in a diagram looks like a success in a quiz.

`is-active` · `is-selected` · `is-processing` · `is-success` · `is-error` ·
`is-complete` · `is-disabled`

Each works on HTML (border/background) **and** inside SVG (stroke/fill), because
a shape has no border. Text inside SVG is emphasised by **fill only** — stroking
text thickens every glyph and the label reads as smudged, which is the opposite
of emphasis. That was found during visual QA and fixed.

## 8. Control, not autoplay

Nothing plays on page load. An animated diagram mounts at step 0 and waits.
Controls: **◂ Prev · ▶ Play · Next ▸ · Reset**, with a live step counter.

Play is available for the student who wants it to run; Next is there for the
student who wants to think between steps. Both reach the same states, because
state is derived from the step number rather than accumulated by mutation.

A test asserts `mount()` contains no `.play()` call.

## 9. Reduced motion

`prefers-reduced-motion: reduce` is honoured in **both** CSS and JavaScript.
The CSS media query cannot reach a `setTimeout`, which is why timing goes
through `MotionService`.

| Under reduced motion | Behaviour |
| --- | --- |
| CSS durations | Collapse to 0 |
| `pulse`, `dia-travel` | No-ops |
| Step-revealed diagram elements | Rendered at 35% opacity instead of hidden, so the diagram still reads as one complete figure |
| Narrated simulator sequences | Play out **instantly and completely** — every caption and output line written at once |
| `--dur-step` | **Preserved at 760ms** in the token, because it is reading time rather than movement |

The principle: **less movement, not less teaching.** Information revealed by an
animation must remain available without it.

## 10. Lifecycle

Nothing animates that cannot be seen.

- A playing sequence pauses when the tab is hidden (`visibilitychange`)
- A playing sequence pauses when its element scrolls out of view
  (`IntersectionObserver`), and resumes only if it was playing when parked
- `destroy()` clears timers and observers

**Measured:** 0 animations running while a lesson page sits idle.

## 11. Performance rules

- Animate **transform, opacity and colour** only. All 8 keyframe animations in
  the product were audited and comply.
- No animation library. The whole motion system is 7.9 KB of JavaScript.
- Interactive modules load only on pages that use them — a page with no animated
  diagram does not download the diagram runtime.
- No `requestAnimationFrame` loops; sequences are timer-driven and cancellable.

## 12. When not to animate

Two thirds of the diagram library is deliberately static. Taxonomies, comparison
tables and reference shapes are **better** still: students screenshot them, print
them and revise from them, and a still image can be taken in at a glance.

> A beautifully animated but educationally unnecessary element should stay static.
> A simple animation that clearly communicates a difficult concept is worth more
> than an elaborate one with no instructional purpose.
