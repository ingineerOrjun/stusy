Database Management System

Almost every system you use keeps its information in a database — a school's marks, a bank's accounts, a shop's stock. This subject shows you how that information is designed, stored and asked for: how to model it, how to lay it out in tables, and how to write the SQL that gets it back.

तपाईंले प्रयोग गर्ने प्रायः हरेक प्रणालीले आफ्नो सूचना डाटाबेसमा राख्छ — विद्यालयको अंक, बैंकको खाता, पसलको स्टक। यो विषयले त्यही सूचना कसरी डिजाइन गरिन्छ, राखिन्छ र झिकिन्छ भन्ने देखाउँछ: मोडेल बनाउने, तालिकामा मिलाउने, र फिर्ता ल्याउने SQL लेख्ने।

How to use this subject

The three hardest things in DBMS are all things you have to see rather than read: what a cardinality actually means, what a query does to a table, and why a many-to-many relationship forces a third table. So each of those has a tool on the page — change the cardinality and watch the rows re-link, run a query and watch the result narrow stage by stage.

Use the tool first, then read the explanation. And when a query is coming, predict the answer before you press Run — a prediction you got wrong is worth more than a result you only watched.

Each unit ends with exam-style questions and a model answer, and every question tells you its mark value so you know how much to write.

यो विषय कसरी प्रयोग गर्ने

DBMS का तीन सबैभन्दा गाह्रा कुरा पढेर होइन, देखेर बुझ्ने खालका हुन्: cardinality को साँचो अर्थ के हो, क्वेरीले तालिकालाई के गर्छ, र धेरै–धेरै सम्बन्धले किन तेस्रो तालिका बनाउन बाध्य पार्छ। त्यसैले तीनैका लागि पृष्ठमा औजार छन् — cardinality बदलेर पङ्क्ति फेरि जोडिएको हेर्नुहोस्, क्वेरी चलाएर नतिजा चरण–चरणमा साँघुरो भएको हेर्नुहोस्।

पहिले औजार चलाउनुहोस्, अनि व्याख्या पढ्नुहोस्। र क्वेरी आउँदा Run थिच्नुअघि उत्तर अनुमान गर्नुहोस् — गलत परेको अनुमान, हेरेर मात्र पाएको नतिजाभन्दा धेरै काम लाग्छ।

हरेक युनिटको अन्त्यमा परीक्षा शैलीका प्रश्न र नमुना उत्तर छन्, र हरेक प्रश्नमा कति अंकको हो लेखिएको छ।
