Definition — learn this wording

SQL (Structured Query Language) is the standard language used to define, manipulate and control the data held in a relational database.

It is not a programming language in the ordinary sense. You do not tell it how to find the rows — you state what you want, and the DBMS works out how. That is why one line of SQL can replace a page of loops.

Almost every SQL statement is one sentence ending in a semicolon, and almost every one begins with a verb: SELECT, INSERT, CREATE, DROP. Reading the verb first tells you what is about to change.

परिभाषा — यही शब्दमा सम्झनुहोस्

SQL (Structured Query Language) रिलेसनल डाटाबेसमा रहेको डाटा परिभाषित गर्न, चलाउन र नियन्त्रण गर्न प्रयोग हुने मानक भाषा हो।

यो साधारण अर्थमा प्रोग्रामिङ भाषा होइन। पङ्क्ति कसरी खोज्ने भन्नु पर्दैन — तपाईं के चाहियो भन्नुहुन्छ, कसरी निकाल्ने भन्ने DBMS ले हेर्छ। त्यसैले SQL को एक हरफले पूरा पानाको loop को काम गर्छ।

प्रायः हरेक SQL कथन एउटा वाक्य हो, अन्त्यमा अर्धविराम। र प्रायः हरेक क्रियापदबाट सुरु हुन्छ: SELECT, INSERT, CREATE, DROP। पहिलो शब्द पढ्नेबित्तिकै के बदलिन लागेको हो थाहा हुन्छ।

4.1  The three families of SQL

The quickest way to classify a statement. Ask what would be lost if it ran. Structure gone → DDL. Rows changed → DML. Somebody's permission changed → DCL. छुट्याउने छिटो तरिका: यो चल्यो भने के हराउँछ भनी सोध्नुहोस्। संरचना गयो → DDL। पङ्क्ति बदलियो → DML। कसैको अधिकार बदलियो → DCL।

4.3 & 4.5  SELECT — asking the database a question

The shape of every query

A SELECT answers one question: which rows, and which columns of them? Those two choices are made by two different clauses, and mixing them up is the most common mistake in this unit.

WHERE chooses rows. It looks at each row in turn, tests the condition, and keeps the row or drops it. It can never change which columns appear.

SELECT chooses columns. It cannot remove a row.

ORDER BY chooses the order. It removes nothing at all — a result with three rows still has three rows after sorting.

हरेक क्वेरीको बनावट

SELECT ले एउटै प्रश्नको उत्तर दिन्छ: कुन पङ्क्ति, र तिनका कुन स्तम्भ? यी दुई छनोट फरक–फरक clause ले गर्छन्, र यिनै दुई मिसाउनु यस युनिटको सबैभन्दा सामान्य गल्ती हो।

WHERE ले पङ्क्ति छान्छ। हरेक पङ्क्ति हेरेर सर्त जाँच्छ, अनि राख्छ वा हटाउँछ। कुन स्तम्भ देखिने भन्ने यसले बदल्न सक्दैन।

SELECT ले स्तम्भ छान्छ। पङ्क्ति हटाउन सक्दैन।

ORDER BY ले क्रम छान्छ। केही पनि हटाउँदैन — तीन पङ्क्ति भएको नतिजा क्रम मिलाएपछि पनि तीनै पङ्क्तिको हुन्छ।

Predict first · पहिले अनुमान गर्नुहोस्

The Student table has 4 rows. You run SELECT name FROM Student WHERE marks > 60; and three students scored above 60. How many rows and how many columns come back? Student तालिकामा ४ पङ्क्ति छन्। SELECT name FROM Student WHERE marks > 60; चलाउनुहुन्छ, र ६० भन्दा माथि तीन जनाले ल्याएका छन्। कति पङ्क्ति र कति स्तम्भ फर्किन्छ?

Two separate cuts. WHERE takes 4 rows down to 3. SELECT name takes 4 columns down to 1. Neither clause does the other one's job. Run it in the simulator below and watch both numbers change.

दुई फरक कटाइ। WHERE ले ४ पङ्क्तिलाई ३ बनाउँछ। SELECT name ले ४ स्तम्भलाई १ बनाउँछ। एउटाले अर्कोको काम गर्दैन। तलको सिमुलेटरमा चलाएर दुवै सङ्ख्या बदलिएको हेर्नुहोस्।

Interactive experiment · अन्तरक्रियात्मक प्रयोग

The SQL simulator

What you will learn: how a query narrows the data in stages, so you can work out a result on paper before you ever run it. तपाईंले के सिक्नुहुन्छ: क्वेरीले डाटालाई चरण–चरणमा कसरी साँघुरो पार्छ, जसले गर्दा नचलाईकनै कागजमा नतिजा निकाल्न सक्नुहुन्छ।

What to notice

Run the query as it stands and read the pipeline. FROM 4 → WHERE 3: one student was dropped. Now change > 60 to > 90 and run it again — the WHERE line says 3 of 4 rows are dropped, and the result has one row.

Now delete the whole WHERE clause. The row count stops falling. That is the proof that WHERE is the only clause doing the filtering.

Finally, add ORDER BY marks DESC. Watch the last number: it does not change. Sorting never removes a row.

जस्ताको तस्तै चलाएर pipeline पढ्नुहोस्। FROM ४ → WHERE ३: एक जना हटे। अब > 60 लाई > 90 बनाएर फेरि चलाउनुहोस् — WHERE ले ४ मध्ये ३ हटेको भन्छ, नतिजामा एक पङ्क्ति आउँछ। अब पूरै WHERE मेटाउनुहोस्: सङ्ख्या घट्न छाड्छ — छान्ने काम WHERE ले मात्र गर्छ भन्ने प्रमाण यही हो। अन्त्यमा ORDER BY marks DESC थप्नुहोस्: अन्तिम सङ्ख्या बदलिँदैन। क्रम मिलाउँदा पङ्क्ति कहिल्यै हट्दैन।
Example 1 Reading a query the way the database reads it

Question: the Student table holds Ram 78 (class 10), Sita 91 (class 10), Hari 55 (class 11) and Gita 64 (no class). What does this return?

Query
SELECT name, marks FROM Student WHERE marks > 60 AND class_id = 10 ORDER BY marks DESC;

Step 1 — FROM. Start with all 4 rows of Student.

Step 2 — WHERE. Test each row against marks > 60 AND class_id = 10. Both halves must hold, because AND narrows:

Working
Ram 78 > 60 ✓ class 10 ✓ keep Sita 91 > 60 ✓ class 10 ✓ keep Hari 55 > 60 ✗ drop Gita 64 > 60 ✓ class NULL ✗ drop

Step 3 — SELECT. Keep only the columns name and marks.

Step 4 — ORDER BY. Sort by marks, largest first.

Answer
name marks Sita 91 Ram 78

Gita is dropped for a reason worth remembering: her class_id is NULL, and NULL is not equal to anything — not even to 10. A comparison against NULL is never true. गीता हट्नुको कारण सम्झनलायक छ: उनको class_id NULL छ, र NULL कुनै पनि कुरासँग बराबर हुँदैन — १० सँग पनि होइन। NULL सँगको तुलना कहिल्यै सत्य हुँदैन।

4.2  DDL — building and removing the structure

The four DDL statements

CREATE TABLE makes a new, empty table. You name each column and give it a data type, and you mark one column PRIMARY KEY.

ALTER TABLE changes the structure of a table that already exists — adding a column, removing one, changing a type. The rows stay.

DROP TABLE removes the table completely: its rows and its structure. After a DROP the name no longer exists.

RENAME gives an existing table a new name. Nothing inside it changes.

चार DDL कथन

CREATE TABLE ले नयाँ, खाली तालिका बनाउँछ। हरेक स्तम्भको नाम र डाटा टाइप दिनुहुन्छ, र एउटालाई PRIMARY KEY तोक्नुहुन्छ।

ALTER TABLE ले पहिले नै भएको तालिकाको संरचना बदल्छ — स्तम्भ थप्ने, हटाउने, टाइप बदल्ने। पङ्क्ति भने रहन्छन्।

DROP TABLE ले तालिका पूरै हटाउँछ: पङ्क्ति र संरचना दुवै। DROP पछि त्यो नाम नै रहँदैन।

RENAME ले भएकै तालिकालाई नयाँ नाम दिन्छ। भित्रको केही बदलिँदैन।

Example 2 Writing CREATE TABLE from a description

Question: create a table Teacher holding a teacher id, a name of up to 30 characters, and the subject taught. The id identifies each teacher.

Answer
CREATE TABLE Teacher ( teacher_id INT PRIMARY KEY, name VARCHAR(30), subject VARCHAR(30) );

Three marks are usually available here and they are usually lost in the same three places: forgetting the data types, forgetting PRIMARY KEY, and forgetting the brackets round the whole column list. Write it in that order every time — name, type, key — and you cannot leave one out. यहाँ प्रायः तीन अंक हुन्छन्, र प्रायः उही तीन ठाउँमा जान्छन्: डाटा टाइप छुट्नु, PRIMARY KEY छुट्नु, र पूरै स्तम्भ सूचीको कोष्ठक छुट्नु। सधैं यही क्रममा लेख्नुहोस् — नाम, टाइप, कुञ्जी — अनि केही छुट्दैन।

Interactive experiment · अन्तरक्रियात्मक प्रयोग

Changing the data — and the difference that costs marks

What you will learn: what INSERT, UPDATE and DELETE actually do to a table, and why DELETE and DROP are not the same thing. तपाईंले के सिक्नुहुन्छ: INSERT, UPDATE र DELETE ले तालिकामा साँच्चै के गर्छन्, र DELETE र DROP किन उस्तै होइनन्।

What to notice

Run DELETE FROM Student WHERE marks < 60. One row goes; the table is still there, still with its four columns. Now run DROP TABLE Student. The table itself disappears — there is nothing left to select from.

Press Reset, then run UPDATE Student SET marks = 80 with no WHERE. Every row changes, and the step turns red to tell you so. In a real school database that single missing WHERE would give every student the same mark.

DELETE FROM Student WHERE marks < 60 चलाउनुहोस्। एउटा पङ्क्ति गयो; तालिका भने चारै स्तम्भसहित रहन्छ। अब DROP TABLE Student चलाउनुहोस्। तालिका नै हरायो — अब केहीबाट select गर्न सकिँदैन। Reset थिचेर WHERE नराखी UPDATE Student SET marks = 80 चलाउनुहोस्। सबै पङ्क्ति बदलिन्छन्, र चरण रातो हुन्छ। वास्तविक विद्यालय डाटाबेसमा त्यही एउटा छुटेको WHERE ले सबै विद्यार्थीलाई उही अंक दिन्थ्यो।

4.6  Joins — reading two tables as one

Why a join is needed at all

A normalised database splits information across tables on purpose. The student's name is in Student; the room is in Class. A question like "which room is Ram taught in?" touches both, so the two must be read together. That is a join.

Every join starts the same way: a matching test, almost always foreign key = primary key. What separates the five kinds is only this — what happens to the rows that did not match.

Inner throws them away. Left keeps all of the left table. Right keeps all of the right. Full outer keeps everything from both. Natural is an inner join that finds the shared column by itself.

Join किन चाहिन्छ

Normalise गरिएको डाटाबेसले जानाजान सूचना धेरै तालिकामा बाँड्छ। विद्यार्थीको नाम Student मा; कोठा Class मा। "राम कुन कोठामा पढ्छन्?" भन्ने प्रश्नले दुवै छुन्छ, त्यसैले दुवैलाई सँगै पढ्नुपर्छ। त्यही नै join हो।

हरेक join उही तरिकाले सुरु हुन्छ: मिलान जाँच, प्रायः जसो foreign key = primary key। पाँच किसिमलाई छुट्याउने कुरा एउटै हो — नमिलेका पङ्क्तिको के हुन्छ।

Inner ले फालिदिन्छ। Left ले बायाँ तालिकाका सबै राख्छ। Right ले दायाँका सबै। Full outer ले दुवैका सबै। Natural भनेको साझा स्तम्भ आफैं खोज्ने inner join हो।

Interactive experiment · अन्तरक्रियात्मक प्रयोग

The same query, five joins

What you will learn: which rows each join keeps, by changing one word and watching the result grow. तपाईंले के सिक्नुहुन्छ: एउटै शब्द बदलेर नतिजा बढेको हेर्दै कुन join ले कुन पङ्क्ति राख्छ भन्ने।

What to notice

The teaching data has two deliberate gaps: Gita has no class, and room C-3 has no student. Those two gaps are the whole lesson.

Press the join examples in order. Inner gives 3 rows — both gaps vanish. Left gives 4 — Gita comes back with NULL for her room. Right gives 4 — C-3 comes back with NULL for the name. Full outer gives 5 — both.

If your data has no unmatched rows, all five joins return the same answer and you learn nothing from them. That is why this table was built with holes in it.

पढाइका लागि दुई ठाउँ जानाजान खाली छन्: गीताको कक्षा छैन, र कोठा C-3 मा विद्यार्थी छैनन्। यी दुई खाली ठाउँ नै पूरा पाठ हुन्। उदाहरण क्रमैसँग थिच्नुहोस्। Inner ले ३ पङ्क्ति — दुवै खाली ठाउँ हराउँछन्। Left ले ४ — गीता कोठाको ठाउँमा NULL लिएर फर्किन्छिन्। Right ले ४ — C-3 नामको ठाउँमा NULL लिएर आउँछ। Full outer ले ५ — दुवै। नमिल्ने पङ्क्ति नै नभए पाँचै join ले उही उत्तर दिन्छन् र केही सिकिँदैन।
Example 3 Which join produced this result?

Question: a query on Student and Class returned four rows, and one of them had NULL in the room column. Which join was used, and why?

Reasoning. A NULL on the right-hand column means a left row survived with no partner. An inner join would have dropped it, so it is not inner. A right join keeps unmatched right rows, which would put the NULL on the left instead. A full outer join would have returned five rows, not four.

Answer
LEFT OUTER JOIN Reason: every Student row was kept, and Gita had no matching Class row, so her room is NULL.

Work backwards from where the NULL is. NULL on the right → left join. NULL on the left → right join. NULLs on both sides → full outer. No NULLs and fewer rows than either table → inner. NULL कता छ भन्नेबाट उल्टो सोच्नुहोस्। दायाँ NULL → left join। बायाँ NULL → right join। दुवैतिर NULL → full outer। NULL छैन र दुवै तालिकाभन्दा कम पङ्क्ति → inner।

4.4  DCL — who is allowed to use the data

GRANT and REVOKE

A school database is not read by one person. The class teacher may need to see marks; the office may need to change addresses; a student should see neither. DCL is how a database administrator sets those limits.

GRANT gives a privilege to a user. REVOKE takes it back.

GRANT SELECT ON Student TO teacher; GRANT SELECT, UPDATE ON Student TO office; REVOKE UPDATE ON Student FROM office;

Read the shape once and it is easy to reproduce: GRANT what ON which table TO whom, and REVOKE with FROM.

GRANT र REVOKE

विद्यालयको डाटाबेस एक जनाले मात्र पढ्दैन। कक्षा शिक्षकलाई अंक हेर्नु पर्ला; कार्यालयलाई ठेगाना बदल्नु पर्ला; विद्यार्थीले दुवै नहेरून्। यी सीमा तोक्ने काम DCL ले गर्छ।

GRANT ले प्रयोगकर्तालाई अधिकार दिन्छ। REVOKE ले फिर्ता लिन्छ।

बनावट एक पटक हेरे सम्झिन सजिलो छ: GRANT के ON कुन तालिका TO कसलाई, र REVOKE मा FROM आउँछ।

यो साइटमा प्रयोगकर्ता र सर्भर नभएकाले सिमुलेटरले यी कथन चलाउँदैन — परीक्षामा पनि यिनको परिभाषा र वाक्यविन्यासबाटै सोधिन्छ।

4.7  SQL View

Definition — learn this wording

A view is a stored SELECT statement that behaves like a table. It has a name and columns and can be queried, but it holds no data of its own — it reads from the real tables every time it is used.

CREATE VIEW Passed AS SELECT name, marks FROM Student WHERE marks >= 40;

Now SELECT * FROM Passed; works as though Passed were a table.

Why views are used: they hide complexity (a long join becomes one name), and they restrict access — a teacher granted the view sees marks without being given the whole Student table.

परिभाषा — यही शब्दमा सम्झनुहोस्

View भनेको संग्रह गरिएको SELECT कथन हो, जुन तालिकाजस्तै व्यवहार गर्छ। यसको नाम र स्तम्भ हुन्छन् र query गर्न मिल्छ, तर आफ्नो डाटा हुँदैन — प्रयोग हुँदा हरेक पटक वास्तविक तालिकाबाटै पढ्छ।

अब SELECT * FROM Passed; ले Passed लाई तालिकाजस्तै मानेर चल्छ।

View किन प्रयोग हुन्छ: जटिलता लुकाउँछ (लामो join एउटा नाम बन्छ), र पहुँच सीमित गर्छ — view मात्र दिइएको शिक्षकले पूरै Student तालिका नपाई अंक हेर्न पाउँछन्।

Example 4 Writing a view, and saying why it is worth having

Question: the office should be able to see each student's name and class room, but must not see marks. Write a view that gives them exactly that, and state two reasons a view is better here than handing over the tables.

Step 1 — write the query first. A view is a stored SELECT, so start with the SELECT that returns the right columns:

Working
SELECT Student.name, Class.room FROM Student JOIN Class ON Student.class_id = Class.class_id;

Step 2 — wrap it in CREATE VIEW and give it a name:

Answer
CREATE VIEW StudentRoom AS SELECT Student.name, Class.room FROM Student JOIN Class ON Student.class_id = Class.class_id; Now: SELECT * FROM StudentRoom; behaves exactly as though StudentRoom were a table. Two reasons a view is better than the tables: 1. SECURITY marks are not in the view, so the office cannot read them even by accident 2. SIMPLICITY the join is written once; the office never needs to know the two tables are separate

The view holds no data of its own. Change a room in the Class table and the next SELECT * FROM StudentRoom shows the new value immediately — that is the sentence to write when a question asks how a view differs from a copy of a table. View सँग आफ्नो data हुँदैन। Class तालिकामा कोठा बदल्नुहोस्, अर्को पटक SELECT * FROM StudentRoom गर्दा नयाँ मान तुरुन्तै देखिन्छ — view र तालिकाको प्रतिलिपि कसरी फरक हुन् भनी सोध्दा यही वाक्य लेख्नुहोस्।

Mistakes that cost marks here

  • Using DELETE when the question says DROP. DELETE FROM Student; empties the table but leaves it standing — you can still insert into it tomorrow. DROP TABLE Student; removes the table itself. One is DML, the other is DDL. DROP भनेको ठाउँमा DELETE लेख्नु। DELETE FROM Student; ले तालिका खाली गर्छ तर तालिका रहन्छ। DROP TABLE Student; ले तालिका नै हटाउँछ। एउटा DML, अर्को DDL।
  • Thinking WHERE chooses columns. WHERE marks > 60 does not put marks in the answer. Only the SELECT list decides which columns appear. WHERE ले स्तम्भ छान्छ भन्ने भ्रम। WHERE marks > 60 ले marks लाई उत्तरमा राख्दैन। कुन स्तम्भ देखिने भन्ने SELECT ले मात्र तय गर्छ।
  • Writing UPDATE or DELETE without WHERE. The statement is legal, so nothing warns you — it simply changes every row. Write the WHERE clause first, then the SET. WHERE नराखी UPDATE वा DELETE लेख्नु। कथन वैध हुने भएकाले चेतावनी आउँदैन — सबै पङ्क्ति बदलिन्छ। पहिले WHERE लेख्नुहोस्, अनि SET।
  • Comparing with NULL using =. WHERE class_id = NULL matches nothing, ever. NULL means "unknown", and nothing is equal to an unknown. NULL लाई = ले तुलना गर्नु। WHERE class_id = NULL ले कहिल्यै केही मिलाउँदैन। NULL को अर्थ "थाहा छैन" हो, र थाहा नभएकोसँग केही बराबर हुँदैन।
  • Forgetting the quotes on text. WHERE name = Ram asks the database for a column called Ram. It must be WHERE name = 'Ram'. पाठमा उद्धरण चिन्ह छुटाउनु। WHERE name = Ram ले Ram नामको स्तम्भ खोज्छ। WHERE name = 'Ram' हुनुपर्छ।

DELETE empties the table. DROP removes the table. DELETE ले तालिका खाली गर्छ। DROP ले तालिका हटाउँछ।

Exam focus — what is asked from this unit

This unit is the largest in the subject — 14 hours and the most marks. Questions come in three shapes: classify a statement as DDL, DML or DCL; write a short query from a description; and read a query and state its result. The writing questions are where the marks are, and they are marked on syntax as well as logic — so practise on paper, with the semicolon. यो युनिट विषयकै सबैभन्दा ठूलो हो — १४ घण्टा र सबैभन्दा धेरै अंक। प्रश्न तीन किसिमका आउँछन्: कथनलाई DDL, DML वा DCL मा छुट्याउने; विवरणबाट छोटो क्वेरी लेख्ने; र क्वेरी पढेर नतिजा भन्ने। अंक लेख्ने प्रश्नमा छन्, र तर्कसँगै वाक्यविन्यास पनि जाँचिन्छ — त्यसैले अर्धविरामसहित कागजमै अभ्यास गर्नुहोस्।
2 marks Practice question

What is SQL? Name its three families of statements. SQL के हो? यसका तीन परिवारका नाम लेख्नुहोस्।

SQL (Structured Query Language) is the standard language used to define, manipulate and control the data in a relational database.

Its three families are DDL (Data Definition Language — CREATE, ALTER, DROP, RENAME), DML (Data Manipulation Language — SELECT, INSERT, UPDATE, DELETE) and DCL (Data Control Language — GRANT, REVOKE).

परिभाषा र तीनै परिवारका नाम — प्रत्येकको पूरा नाम र दुई–तीन उदाहरण कथनसहित लेख्नुहोस्।
3 marks Practice question

Write an SQL statement to create a table Book with a book id (the primary key), a title of up to 50 characters and a price. Book तालिका बनाउने SQL लेख्नुहोस् — book id (प्राथमिक कुञ्जी), बढीमा ५० अक्षरको शीर्षक, र मूल्य।

CREATE TABLE Book ( book_id INT PRIMARY KEY, title VARCHAR(50), price INT );

One mark for the CREATE TABLE line with brackets, one for the correct data types, one for PRIMARY KEY on book_id.

कोष्ठकसहितको CREATE TABLE लाई एक अंक, सही डाटा टाइपलाई एक, र book_id मा PRIMARY KEY लाई एक।
3 marks Practice question

A table Employee(emp_id, name, dept, salary) is given. Write a query to show the name and salary of every employee in the "Sales" department earning more than 30000, highest salary first. Employee(emp_id, name, dept, salary) तालिका दिइएको छ। "Sales" विभागमा ३०००० भन्दा बढी तलब पाउने सबैको नाम र तलब, ठूलो तलब पहिले आउने गरी देखाउने क्वेरी लेख्नुहोस्।

SELECT name, salary FROM Employee WHERE dept = 'Sales' AND salary > 30000 ORDER BY salary DESC;

Note the three things a marker looks for: quotes round 'Sales' because it is text, AND because both conditions must hold, and DESC because "highest first" is not the default.

परीक्षकले हेर्ने तीन कुरा: पाठ भएकाले 'Sales' मा उद्धरण चिन्ह, दुवै सर्त चाहिने भएकाले AND, र "ठूलो पहिले" default नभएकाले DESC।
3 marks Practice question

Differentiate between DELETE and DROP with an example of each. DELETE र DROP बीचको भिन्नता उदाहरणसहित लेख्नुहोस्।

DELETE DROP ------ ---- DML DDL removes ROWS removes the TABLE structure stays structure goes too can use WHERE no WHERE table can be refilled table must be recreated DELETE FROM Student WHERE marks < 40; DROP TABLE Student;

Any three clear differences earn the marks; the example statements make the answer unambiguous.

स्पष्ट तीन भिन्नताले अंक दिन्छ; उदाहरण कथनले उत्तर अझ स्पष्ट बनाउँछ।

Key points to revise — दोहोर्‍याउनुपर्ने मुख्य बुँदा

  • SQL defines, manipulates and controls data in a relational database. Three families: DDL (structure), DML (data), DCL (permission). SQL ले रिलेसनल डाटाबेसको डाटा परिभाषित, सञ्चालन र नियन्त्रण गर्छ। तीन परिवार: DDL (संरचना), DML (डाटा), DCL (अधिकार)।
  • A SELECT runs FROM → WHERE → SELECT → ORDER BY. WHERE picks rows, SELECT picks columns, ORDER BY picks the order and removes nothing. SELECT यसरी चल्छ: FROM → WHERE → SELECT → ORDER BY। WHERE ले पङ्क्ति, SELECT ले स्तम्भ, ORDER BY ले क्रम — र यसले केही हटाउँदैन।
  • AND narrows the result, OR widens it. Text values need single quotes. AND ले नतिजा साँघुरो, OR ले फराकिलो बनाउँछ। पाठ मानलाई एकल उद्धरण चिन्ह चाहिन्छ।
  • DELETE removes rows and keeps the table; DROP removes the table itself. This is the difference examiners ask for most. DELETE ले पङ्क्ति हटाउँछ, तालिका राख्छ; DROP ले तालिका नै हटाउँछ। परीक्षकले सबैभन्दा धेरै सोध्ने भिन्नता यही हो।
  • UPDATE or DELETE without WHERE changes every row. It is legal, so nothing warns you. WHERE नभएको UPDATE वा DELETE ले सबै पङ्क्ति बदल्छ। वैध हुने भएकाले चेतावनी आउँदैन।
  • All five joins share one matching test; they differ only in what they keep of the rows that did not match. NULL in the result tells you which join it was. पाँचै join को मिलान जाँच उही हो; फरक केवल नमिलेका पङ्क्तिको के गर्ने भन्नेमा। नतिजाको NULL ले कुन join थियो भन्ने बताउँछ।
  • A view is a stored SELECT that behaves like a table but holds no data of its own. View भनेको संग्रहित SELECT हो — तालिकाजस्तै व्यवहार गर्छ तर आफ्नो डाटा हुँदैन।
