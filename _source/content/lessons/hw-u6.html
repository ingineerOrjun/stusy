6.1  What backup and recovery mean

Definition — learn this wording

A backup is a copy of data kept separately, so that it can be restored if the original is lost, damaged or changed by mistake.

Recovery is the process of restoring that data, and returning the system to working order, after a failure.

Data is lost in more ways than hardware failure: accidental deletion, overwriting a file, a virus, theft, fire or flood, and a failed update. A backup plan has to survive all of them, which is why keeping the copy in the same building as the original is a weak plan and an off-site copy is part of a serious one.

The test of a backup is not whether it ran. It is whether a restore works — a backup that has never been restored from is an assumption, not a safeguard.

परिभाषा — यही शब्दमा सम्झनुहोस्

Backup भनेको छुट्टै राखिएको data को प्रतिलिपि हो, ताकि मूल हराए, बिग्रिए वा भुलवश बदलिए फर्काउन सकियोस्।

Recovery भनेको खराबीपछि त्यो data फर्काउने र प्रणालीलाई चल्ने अवस्थामा ल्याउने प्रक्रिया हो।

Data हार्डवेयर बिग्रेर मात्र हराउँदैन: भुलले मेटिनु, फाइल ओभरराइट हुनु, भाइरस, चोरी, आगलागी वा बाढी, र असफल अपडेट। ब्याकअप योजनाले यी सबै झेल्नुपर्छ — त्यसैले प्रतिलिपि मूलकै भवनमा राख्नु कमजोर योजना हो र अर्को ठाउँको प्रतिलिपि गम्भीर योजनाको हिस्सा हो।

ब्याकअपको जाँच "चल्यो कि चलेन" होइन। फर्काउन सकिन्छ कि सकिँदैन हो — कहिल्यै फर्काएर नहेरिएको ब्याकअप अनुमान हो, सुरक्षा होइन।

6.2  Backup methods

The three methods compared

Full backup — copies everything every time. Slowest to take and uses the most media, but a restore needs only one set, so it is the fastest and safest to recover from.

Incremental backup — copies only what has changed since the last backup of any kind. Fastest to take and smallest, but a restore needs the last full backup plus every increment since. If one increment in the chain is missing or damaged, everything after it is lost.

Differential backup — copies everything changed since the last full backup. Each day is larger than the last, but a restore needs exactly two sets: the full backup and the most recent differential.

The trade is always the same: time and media when you back up, against time and risk when you restore.

तीन विधिको तुलना

Full backup — हरेक पटक सबै कपी गर्छ। लिन सबैभन्दा ढिलो र मिडिया धेरै लाग्छ, तर फर्काउन एउटै सेट चाहिन्छ — त्यसैले recovery सबैभन्दा छिटो र सुरक्षित।

Incremental backup — जुनसुकै किसिमको अघिल्लो ब्याकअप पछि बदलिएको मात्र कपी गर्छ। लिन सबैभन्दा छिटो र सानो, तर फर्काउन अन्तिम full ब्याकअप र त्यसपछिका सबै increment चाहिन्छन्। शृंखलाको एउटा increment हराए वा बिग्रिए त्यसपछिको सबै जान्छ।

Differential backup — अन्तिम full ब्याकअपपछि बदलिएको सबै कपी गर्छ। हरेक दिनको अघिल्लो भन्दा ठूलो हुन्छ, तर फर्काउन ठ्याक्कै दुई सेट चाहिन्छ: full र सबैभन्दा पछिल्लो differential।

सौदा सधैं उही हो: ब्याकअप लिँदाको समय र मिडिया, बनाम फर्काउँदाको समय र जोखिम।

Example 1 How many sets does a Friday restore need?

Question: a full backup runs on Monday. Incremental backups run Tuesday to Friday. The disk fails on Friday evening. Which sets are needed, and what happens if Wednesday's tape is unreadable?

Decide two things before reading on: how many sets, and what Wednesday's failure costs you.पढ्नुअघि दुई कुरा निर्णय गर्नुहोस्: कति सेट चाहिन्छ, र बुधबारको असफलताले के गुमाउँछ।

Step 1 — what does an incremental hold? Only what changed since the previous backup of any kind — so Tuesday's holds Monday-to-Tuesday changes, Wednesday's holds Tuesday-to- Wednesday, and so on.

Step 2 — rebuild the timeline. Start from Monday's full set, then apply Tuesday's, Wednesday's, Thursday's and Friday's increments in order. That is five sets.

Step 3 — remove Wednesday. Thursday's increment holds only what changed after Wednesday's backup. Without Wednesday there is a gap in the chain that nothing else fills, so the restore can only be trusted up to Tuesday.

Answer
Five sets are needed. Losing Wednesday's breaks the chain: everything from Wednesday onwards is unrecoverable.

Run the same failure against a differential scheme and only Friday's differential matters — Wednesday's loss would cost nothing. That is what "two sets" buys you. यही असफलता differential योजनामा लगाउनुहोस् — शुक्रबारको differential मात्र काम लाग्छ, बुधबार हराए केही बिग्रँदैन। "दुई सेट" ले किन्ने कुरा यही हो।

6.3  Devices, media, scheduling and rotation

Definition — learn this wording

Backup devices and media: external hard disks (large, fast, cheap per gigabyte); USB flash drives (portable, small capacity); optical discs — CD, DVD, Blu-ray (write once, cheap, slow); magnetic tape (very large capacity, low cost, still used for archives); network attached storage; and cloud storage, which is off-site by nature.

Scheduling means deciding when backups run and automating them. Backups that depend on someone remembering do not happen. They are usually scheduled outside working hours, because a backup competes for the disk and the network.

Media rotation means reusing a set of media in a planned cycle, so that several generations of backup exist at once. The standard scheme is grandfather–father–son: daily backups (son) are kept for a week, weekly backups (father) for a month, and monthly backups (grandfather) for a year.

Rotation is what protects you from a problem you did not notice immediately. If a file was corrupted three weeks ago and every backup has been overwritten since, the only copies you hold are all corrupted too.

परिभाषा — यही शब्दमा सम्झनुहोस्

ब्याकअप उपकरण र मिडिया: बाहिरी hard disk (ठूलो, छिटो, प्रति GB सस्तो); USB flash drive (बोक्न सजिलो, कम क्षमता); optical disc — CD, DVD, Blu-ray (एक पटक लेखिने, सस्तो, ढिलो); चुम्बकीय टेप (धेरै ठूलो क्षमता, कम लागत, अभिलेखका लागि अझै प्रयोगमा); network attached storage; र cloud storage, जुन स्वभावतः अर्को ठाउँमा हुन्छ।

Scheduling भनेको ब्याकअप कहिले चल्ने तय गरेर स्वचालित बनाउनु हो। कसैले सम्झनुपर्ने ब्याकअप हुँदैन। प्रायः कार्यालय समयबाहिर राखिन्छ, किनकि ब्याकअपले डिस्क र नेटवर्क ओगट्छ।

Media rotation भनेको मिडियाको समूहलाई योजनाबद्ध चक्रमा पुनः प्रयोग गर्नु, ताकि एकैचोटि ब्याकअपका धेरै पुस्ता रहून्। मानक योजना grandfather–father–son हो: दैनिक ब्याकअप (son) एक हप्ता, साप्ताहिक (father) एक महिना, र मासिक (grandfather) एक वर्ष राखिन्छ।

तुरुन्तै थाहा नपाएको समस्याबाट जोगाउने कुरा rotation नै हो। तीन हप्ताअघि फाइल बिग्रेको थियो र त्यसपछि हरेक ब्याकअप ओभरराइट भइसक्यो भने तपाईंसँग भएका सबै प्रतिलिपि पनि बिग्रिएकै हुन्छन्।

6.4  RAID

Definition — learn this wording

RAID (Redundant Array of Independent Disks) combines several physical disks so the operating system sees them as one drive, in order to gain speed, fault tolerance, or both.

RAID 0 — striping. Data is split across the disks, so reads and writes are faster and the full capacity is usable. There is no redundancy: if any one disk fails, all the data is lost. Minimum two disks.

RAID 1 — mirroring. The same data is written to both disks. One disk can fail and the system keeps running. Only half the total capacity is usable. Minimum two disks.

RAID 5 — striping with parity. Data and parity information are spread across all the disks. Any one disk can fail and its contents are rebuilt from the parity. The capacity of one disk is given up to parity. Minimum three disks.

परिभाषा — यही शब्दमा सम्झनुहोस्

RAID (Redundant Array of Independent Disks) ले धेरै भौतिक डिस्कलाई जोडेर अपरेटिङ सिस्टमलाई एउटै ड्राइभजस्तो देखाउँछ — गति, खराबी सहनशीलता, वा दुवै पाउन।

RAID 0 — striping. Data डिस्कहरूमा बाँडिन्छ, त्यसैले पढ्न–लेख्न छिटो हुन्छ र पूरै क्षमता प्रयोग हुन्छ। कुनै redundancy छैन: एउटा डिस्क बिग्रिए सबै data जान्छ। न्यूनतम दुई डिस्क।

RAID 1 — mirroring. उही data दुवै डिस्कमा लेखिन्छ। एउटा बिग्रिए पनि प्रणाली चलिरहन्छ। कुल क्षमताको आधा मात्र प्रयोगयोग्य। न्यूनतम दुई डिस्क।

RAID 5 — parity सहितको striping. Data र parity सबै डिस्कमा फैलाइन्छ। कुनै एउटा बिग्रिए त्यसको सामग्री parity बाट पुनर्निर्माण हुन्छ। एउटा डिस्क बराबरको क्षमता parity मा जान्छ। न्यूनतम तीन डिस्क।

Predict first · पहिले अनुमान गर्नुहोस्

A server uses RAID 1. A user deletes an important folder by mistake. Is it recoverable from the RAID? एउटा सर्भरमा RAID 1 छ। प्रयोगकर्ताले भुलवश महत्त्वपूर्ण फोल्डर मेट्छ। के त्यो RAID बाट फर्काउन सकिन्छ?

Mirroring copies every change to both disks, and a deletion is a change. Both disks lose the folder at the same instant. RAID protects against a disk failing — a mechanical event affecting one disk. It gives no protection against deletion, overwriting, a virus or ransomware, because those are legitimate write operations as far as the array is concerned. Only a backup, held separately and not written to continuously, recovers this.

Mirroring ले हरेक परिवर्तन दुवै डिस्कमा सार्छ, र मेटाइ पनि परिवर्तन हो। दुवै डिस्कले एकै क्षणमा फोल्डर गुमाउँछन्। RAID ले डिस्क बिग्रिनु — एउटा डिस्कमा हुने यान्त्रिक घटना — बाट जोगाउँछ। मेटाइ, ओभरराइट, भाइरस वा ransomware बाट जोगाउँदैन, किनकि array का लागि ती वैध लेखाइ हुन्। छुट्टै राखिएको र निरन्तर नलेखिने ब्याकअपले मात्र यो फर्काउँछ।

6.5  Recovery techniques

Match the technique to the failure

Restore from backup — the general answer, and the only one that works when data itself has been lost or corrupted.

System restore point — rolls the operating system's settings and drivers back to an earlier state. Fixes a bad update or driver; does not recover deleted personal files.

Recovery / repair console — repairs a damaged boot sector or system files so the machine can start again.

Data recovery software — scans sectors directly to retrieve files whose index entries were deleted. This works precisely because a quick format and a delete do not remove the data itself.

Professional recovery from a failed drive — for physical damage such as a head crash, done in a clean room. Expensive, and never guaranteed.

Rebuilding a RAID array — replacing a failed disk and letting the array rebuild its contents from the mirror or the parity.

खराबी अनुसार उपाय मिलाउनुहोस्

ब्याकअपबाट फर्काउने — सामान्य उत्तर, र data नै हराएको वा बिग्रिएको बेला काम लाग्ने एक मात्र उपाय।

System restore point — अपरेटिङ सिस्टमका सेटिङ र driver लाई अघिल्लो अवस्थामा फर्काउँछ। खराब अपडेट वा driver मिलाउँछ; मेटिएका व्यक्तिगत फाइल फर्काउँदैन।

Recovery / repair console — बिग्रिएको boot sector वा सिस्टम फाइल मर्मत गरेर मेसिन फेरि सुरु हुन दिन्छ।

Data recovery सफ्टवेयर — सूची मेटिएका फाइल फर्काउन sector सीधै स्क्यान गर्छ। यो चल्नुको कारण नै quick format र delete ले data आफैँ नहटाउनु हो।

बिग्रेको ड्राइभबाट व्यावसायिक रिकभरी — head crash जस्तो भौतिक क्षतिका लागि, clean room मा गरिने। महँगो, र कहिल्यै ग्यारेन्टी नहुने।

RAID array पुनर्निर्माण — बिग्रेको डिस्क साटेर array लाई mirror वा parity बाट सामग्री फेरि बनाउन दिने।

Practise the judgement · निर्णय अभ्यास गर्नुहोस्

Which backup or RAID level fits this situation?

What you will learn: to choose a method from a described need, which is how this unit is examined — the exam gives you a situation and asks what you would use, not for three definitions. तपाईंले के सिक्नुहुन्छ: वर्णन गरिएको आवश्यकताबाट विधि छान्न — यो युनिट यसै गरी जाँचिन्छ। परीक्षाले तीन परिभाषा होइन, अवस्था दिएर के प्रयोग गर्नुहुन्छ सोध्छ।

Why this matters: every option here is correct for something. Marks are lost by choosing one that solves a different problem from the one described — RAID for accidental deletion is the classic.किन महत्त्वपूर्ण छ: यहाँका हरेक विकल्प कुनै न कुनै अवस्थाका लागि ठीक छन्। वर्णन गरिएको भन्दा फरक समस्या समाधान गर्ने विकल्प छानेर अंक गुम्छ — भुलले मेटिएकोमा RAID भन्नु उत्कृष्ट उदाहरण।

Example 2 How much space do you actually get?

Question: four 2 TB disks are available. What usable capacity does each of RAID 0, RAID 1 and RAID 5 give, and how many disks can fail in each?

Step 1 — RAID 0 keeps nothing back. Every disk stores data and none stores a copy or parity, so usable = 4 × 2 = 8 TB. Nothing is protected: 0 disks may fail.

Step 2 — RAID 1 stores everything twice. Half the total is a copy, so usable = 8 ÷ 2 = 4 TB. One disk of each mirrored pair may fail.

Step 3 — RAID 5 gives up one disk's worth to parity. Usable = (4 − 1) × 2 = 6 TB. Any one disk may fail and be rebuilt from the parity.

Answer
RAID 0 → 8 TB, no disk may fail · RAID 1 → 4 TB, one per pair · RAID 5 → 6 TB, any one

Read the pattern rather than memorising three numbers: capacity and safety trade directly against each other, and RAID 5 exists because it buys most of the capacity of RAID 0 with most of the safety of RAID 1. तीन सङ्ख्या घोक्नुभन्दा ढाँचा पढ्नुहोस्: क्षमता र सुरक्षा सीधै एक–अर्काको सट्टामा जान्छन्, र RAID 5 हुनुको कारण यही हो — यसले RAID 0 को धेरैजसो क्षमता र RAID 1 को धेरैजसो सुरक्षा सँगै दिन्छ।

Mistakes that cost marks here

  • Calling RAID a backup. RAID survives a disk failing. It mirrors deletion, corruption and ransomware faithfully onto every disk in the array. RAID लाई ब्याकअप भन्नु। RAID ले डिस्क बिग्रिँदा जोगाउँछ। मेटाइ, बिग्रिनु र ransomware लाई array का हरेक डिस्कमा जस्ताको तस्तै सार्छ।
  • Swapping incremental and differential. Incremental = since the last backup; differential = since the last full backup. Getting these the wrong way round reverses every answer about restore time. Incremental र differential साट्नु। Incremental = अघिल्लो ब्याकअप पछि; differential = अन्तिम full ब्याकअप पछि। उल्टो पारे फर्काउने समयसम्बन्धी हरेक उत्तर उल्टिन्छ।
  • Saying RAID 5 needs two disks. It needs a minimum of three, because parity has to live somewhere other than the data it protects. RAID 5 लाई दुई डिस्क चाहिन्छ भन्नु। न्यूनतम तीन चाहिन्छ, किनकि parity ले जोगाउने data भन्दा अन्तै बस्नुपर्छ।
  • Keeping the only backup beside the computer. Fire, flood and theft take both at once. A serious plan keeps a copy off-site. एक मात्र ब्याकअप कम्प्युटरकै छेउमा राख्नु। आगलागी, बाढी र चोरीले दुवै सँगै लैजान्छन्। गम्भीर योजनाले एउटा प्रतिलिपि अर्को ठाउँमा राख्छ।

RAID survives a disk; backup survives a mistake. Incremental = since last backup, differential = since last full. RAID ले डिस्क जोगाउँछ; ब्याकअपले गल्ती जोगाउँछ। Incremental = अघिल्लो ब्याकअपपछि, differential = अन्तिम full पछि।

Exam focus — what is asked from this unit

The shortest unit — 8 hours, 7 marks — and the most predictable. Three questions cover almost everything ever asked: differentiate full, incremental and differential backup (say what each copies AND what a restore needs, or you get half the marks), explain RAID 0, 1 and 5 with their minimum disks and what happens when one fails, and define backup and recovery / list recovery techniques. If a question gives you a scenario, the answer is almost always the trade-off between backup time and restore time — say which you are choosing and why. सबैभन्दा छोटो युनिट — ८ घण्टा, ७ अंक — र सबैभन्दा अनुमानयोग्य। तीन प्रश्नले सोधिने झन्डै सबै समेट्छन्: full, incremental र differential छुट्याउनुहोस् (हरेकले के कपी गर्छ र फर्काउन के चाहिन्छ दुवै भन्नुहोस्, नत्र आधा अंक), RAID 0, 1 र 5 व्याख्या गर्नुहोस् न्यूनतम डिस्क र एउटा बिग्रिँदा के हुन्छ सहित, र backup–recovery को परिभाषा / recovery का उपाय। प्रश्नले अवस्था दियो भने उत्तर झन्डै सधैं ब्याकअप समय र पुनर्स्थापना समयबीचको सौदा हो — कुन छान्दै हुनुहुन्छ र किन भन्नुहोस्।

Q1 3 marks

Differentiate between full, incremental and differential backup. Full, incremental र differential backup बीचको फरक छुट्याउनुहोस्।

A full backup copies all the data every time; it takes the longest and uses the most media but a restore needs only that one set. An incremental backup copies only what has changed since the last backup of any type; it is the quickest to take and the smallest, but restoring requires the last full backup together with every incremental taken since, and a missing one breaks the chain. A differential backup copies everything changed since the last full backup; each one grows larger than the last, but a restore needs exactly two sets — the full backup and the most recent differential.

Full backup ले हरेक पटक सबै data कपी गर्छ; समय सबैभन्दा बढी लाग्छ र मिडिया धेरै खपत हुन्छ तर फर्काउन त्यही एउटै सेट चाहिन्छ। Incremental backup ले जुनसुकै किसिमको अघिल्लो ब्याकअपपछि बदलिएको मात्र कपी गर्छ; लिन सबैभन्दा छिटो र सानो, तर फर्काउन अन्तिम full ब्याकअप र त्यसपछिका सबै incremental चाहिन्छन्, र एउटा हराए शृंखला टुट्छ। Differential backup ले अन्तिम full ब्याकअपपछि बदलिएको सबै कपी गर्छ; हरेक अघिल्लो भन्दा ठूलो हुँदै जान्छ, तर फर्काउन ठ्याक्कै दुई सेट चाहिन्छ — full र सबैभन्दा पछिल्लो differential।

Q2 3 marks

What is RAID? Explain RAID 0, RAID 1 and RAID 5, stating the minimum number of disks for each. RAID के हो? RAID 0, RAID 1 र RAID 5 व्याख्या गर्नुहोस्, र हरेकलाई चाहिने न्यूनतम डिस्क सङ्ख्या लेख्नुहोस्।

RAID (Redundant Array of Independent Disks) combines several physical disks so that the operating system treats them as a single drive, to gain speed, fault tolerance or both. RAID 0 uses striping: data is divided across the disks giving faster access and full capacity, but there is no redundancy and one disk failing loses everything — minimum two disks. RAID 1 uses mirroring: identical data is written to both disks so one can fail without loss, but only half the capacity is usable — minimum two disks. RAID 5 uses striping with parity spread across all disks, so any one disk can fail and be rebuilt from the parity, at the cost of one disk's capacity — minimum three disks.

RAID (Redundant Array of Independent Disks) ले धेरै भौतिक डिस्क जोडेर अपरेटिङ सिस्टमलाई एउटै ड्राइभजस्तो देखाउँछ — गति, खराबी सहनशीलता वा दुवैका लागि। RAID 0 ले striping प्रयोग गर्छ: data डिस्कहरूमा बाँडिन्छ, पहुँच छिटो हुन्छ र पूरै क्षमता पाइन्छ, तर redundancy नभएकाले एउटा डिस्क बिग्रिए सबै जान्छ — न्यूनतम दुई डिस्क। RAID 1 ले mirroring प्रयोग गर्छ: दुवै डिस्कमा उही data लेखिन्छ, त्यसैले एउटा बिग्रिए पनि हराउँदैन, तर आधा क्षमता मात्र प्रयोगयोग्य — न्यूनतम दुई डिस्क। RAID 5 ले सबै डिस्कमा फैलिएको parity सहित striping गर्छ, त्यसैले कुनै एउटा बिग्रिए parity बाट पुनर्निर्माण हुन्छ, एउटा डिस्क बराबरको क्षमताको मूल्यमा — न्यूनतम तीन डिस्क।

Q3 2 marks

Explain the grandfather–father–son media rotation scheme, and state one problem it protects against that a single daily backup does not. Grandfather–father–son media rotation योजना बुझाउनुहोस्, र दैनिक एउटै ब्याकअपले नजोगाउने कुन समस्याबाट यसले जोगाउँछ लेख्नुहोस्।

Grandfather–father–son is a media rotation scheme in which daily backups (son) are kept for about a week, weekly backups (father) for about a month, and monthly backups (grandfather) for about a year, with the media reused in that planned cycle. It protects against corruption or an unwanted change that is not noticed immediately: if a single daily backup is overwritten each day, then after a few days every copy held contains the same damage, whereas keeping older generations means an undamaged version still exists.

Grandfather–father–son एउटा media rotation योजना हो जसमा दैनिक ब्याकअप (son) करिब एक हप्ता, साप्ताहिक (father) करिब एक महिना, र मासिक (grandfather) करिब एक वर्ष राखिन्छ, र मिडिया त्यही योजनाबद्ध चक्रमा पुनः प्रयोग हुन्छ। यसले तुरुन्तै थाहा नपाइने बिग्रिनु वा अवाञ्छित परिवर्तनबाट जोगाउँछ: दैनिक एउटै ब्याकअप हरेक दिन ओभरराइट भइरहे केही दिनपछि भएका सबै प्रतिलिपिमा उही क्षति हुन्छ, तर पुराना पुस्ता राखे नबिग्रेको संस्करण अझै रहन्छ।

Key points to revise — दोहोर्‍याउनुपर्ने मुख्य बुँदा

  • A backup is a separate copy; recovery is the process of restoring it. A backup that has never been restored from is untested. Backup छुट्टै प्रतिलिपि हो; recovery त्यो फर्काउने प्रक्रिया। कहिल्यै फर्काएर नहेरिएको ब्याकअप परीक्षण नगरिएको हो।
  • Full = everything, one set to restore. Incremental = since the last backup, full plus every increment to restore. Differential = since the last full, exactly two sets to restore. Full = सबै, फर्काउन एउटै सेट। Incremental = अघिल्लो ब्याकअपपछि, फर्काउन full र सबै increment। Differential = अन्तिम full पछि, फर्काउन ठ्याक्कै दुई सेट।
  • Grandfather–father–son keeps daily, weekly and monthly generations, which is what protects against damage noticed late. Grandfather–father–son ले दैनिक, साप्ताहिक र मासिक पुस्ता राख्छ, जसले ढिलो थाहा भएको क्षतिबाट जोगाउँछ।
  • RAID 0 = speed, no redundancy, 2 disks. RAID 1 = mirror, 2 disks. RAID 5 = parity, 3 disks minimum. RAID 0 = गति, redundancy छैन, २ डिस्क। RAID 1 = mirror, २ डिस्क। RAID 5 = parity, न्यूनतम ३ डिस्क।
  • RAID is not a backup. It survives a disk failing, not a deletion, a virus or a mistake. RAID ब्याकअप होइन। यसले डिस्क बिग्रिँदा जोगाउँछ — मेटाइ, भाइरस वा गल्तीमा होइन।
