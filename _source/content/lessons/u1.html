1.1  What is a Data Structure?

Definition — learn this wording

A data structure is a particular way of organising, storing and managing data in a computer's memory so that it can be accessed and modified efficiently.

Notice what the definition does not say. A data structure is not the data itself. It is the arrangement of the data, together with the rules for putting data in and taking data out.

परिभाषा — यही शब्द कण्ठ पार्नुहोस्

डाटा स्ट्रक्चर भनेको कम्प्युटरको मेमोरीमा डाटालाई मिलाएर, राखेर र व्यवस्थापन गर्ने एउटा खास तरिका हो, ताकि त्यो डाटा छिटो र सजिलै प्रयोग र परिवर्तन गर्न सकियोस्।

ध्यान दिनुहोस् — डाटा स्ट्रक्चर भनेको डाटा आफैं होइन। यो डाटा कसरी मिलाइएको छ भन्ने कुरा र डाटा राख्ने–झिक्ने नियम हो।

Real-world analogy — the school library

Imagine a library with 5,000 books. The books are the data.

If the books are thrown in a heap on the floor, finding one book might take an hour — you must check them one by one. If the same books are kept on numbered shelves arranged by subject, you find any book in under a minute.

Same books. Same room. Same librarian. Only the arrangement changed — and the speed changed completely. That arrangement is the data structure.

व्यवहारिक उदाहरण — पुस्तकालय। ५,००० किताब भएको पुस्तकालय सम्झनुहोस्। किताबहरू नै डाटा हुन्। भुइँमा थुपारेको छ भने एउटा किताब खोज्न घण्टौं लाग्न सक्छ। तर विषय अनुसार नम्बर हालेको र्‍याकमा राखिएको छ भने एक मिनेटमै भेटिन्छ। किताब उही, कोठा उही — तर मिलाउने तरिका फेरियो, र गति पूरै फेरियो। त्यही मिलान नै डाटा स्ट्रक्चर हो।

1.2  Advantages of Data Structures

Six advantages
  • Efficiency — the right structure makes searching and sorting far faster. Searching a sorted array by binary search takes about 20 steps for 10,00,000 items; checking one by one takes up to 10,00,000 steps.
  • Reusability — one structure such as a stack can be written once and used in many different programs.
  • Abstraction — the user calls push() without knowing how it works inside.
  • Better memory use — structures like the linked list take memory only when it is actually needed.
  • Easy maintenance — organised data means shorter, clearer code that is easier to correct later.
  • Handles large data — millions of records stay manageable.
छ वटा फाइदा
  • Efficiency (दक्षता) — सही स्ट्रक्चरले खोज्ने र क्रम मिलाउने काम धेरै छिटो बनाउँछ। १० लाख डाटामा binary search ले करिब २० चरणमै भेट्छ; एक–एक गरी हेर्दा १० लाख चरणसम्म लाग्न सक्छ।
  • Reusability — एक पटक लेखेको स्ट्याक धेरै प्रोग्राममा प्रयोग गर्न सकिन्छ।
  • Abstraction — भित्र कसरी चल्छ थाहा नपाई पनि push() प्रयोग गर्न सकिन्छ।
  • मेमोरीको राम्रो प्रयोग — linked list ले चाहिएको बेला मात्र मेमोरी लिन्छ।
  • सजिलो मर्मत — मिलेको डाटाले कोड छोटो र स्पष्ट बनाउँछ।
  • ठूलो डाटा — लाखौं रेकर्ड पनि व्यवस्थित रहन्छ।

1.4  Need of Data Structures

Why they are needed
  • Data keeps growing — programs must handle huge amounts of data.
  • Processor speed is limited — a faster CPU cannot rescue a badly arranged pile of data.
  • Search must be fast — searching 1,00,000 unsorted names one by one is far too slow.
  • Many users at once — many requests must reach the data quickly.
  • Memory is limited — data must be stored without waste.
किन आवश्यक छ
  • डाटा बढ्दै छ — प्रोग्रामले धेरै ठूलो डाटा सम्हाल्नुपर्छ।
  • प्रोसेसरको गति सीमित छ — छिटो CPU ले पनि बिग्रेको मिलानलाई सुधार्न सक्दैन।
  • खोजी छिटो हुनुपर्छ — नमिलेको १ लाख नाम एक–एक गरी खोज्न धेरै ढिलो हुन्छ।
  • एकैचोटि धेरै प्रयोगकर्ता — डाटा छिटो पुग्नुपर्छ।
  • मेमोरी सीमित छ — खेर नफाली राख्नुपर्छ।

1.5  Classification of Data Structures

The two main groups

Linear data structure: the elements are arranged in a sequence, one after another. Each element has exactly one element before it and one after it. The whole structure can be traversed completely in a single run.

Non-linear data structure: the elements are not in a sequence. One element may be connected to many elements. It cannot be traversed in one straight run.

Some books first split data structures into primitive (int, float, char, pointer — supplied by the language) and non-primitive (built by the programmer). Linear and non-linear are the two kinds of non-primitive structures.

दुई मुख्य समूह

Linear (रेखीय): तत्त्वहरू एउटा पछि अर्को गरी क्रमैसँग राखिन्छन्। प्रत्येकको एउटा अघिल्लो र एउटा पछिल्लो हुन्छ। एकै पटकमा सबै घुम्न सकिन्छ।

Non-linear (अरेखीय): तत्त्वहरू क्रममा हुँदैनन्। एउटा तत्त्व धेरैसँग जोडिन सक्छ। सिधा एकै पटकमा सबै घुम्न सकिँदैन।

केही किताबले पहिले primitive (int, float, char, pointer — भाषाले नै दिएको) र non-primitive (प्रोग्रामरले बनाएको) भनेर छुट्याउँछन्। Linear र non-linear चाहिँ non-primitive कै दुई प्रकार हुन्।

1.5.1 (a)  Array — एरे

Array

An array is a collection of elements of the same data type, stored in continuous (contiguous) memory locations, and accessed using an index that always starts at 0.

Because the memory is continuous and every element is the same size, the computer can calculate the address of any element instantly: address = base + index × size. That is why array access is called direct or random access — reaching a[900] takes exactly as long as reaching a[0].

एरे

एरे भनेको एउटै प्रकारका तत्त्वहरूको संग्रह हो, जुन लगातार मेमोरी मा राखिन्छ र सधैं ० बाट सुरु हुने index ले पुगिन्छ।

मेमोरी लगातार भएकाले र हरेक तत्त्वको साइज उही भएकाले कम्प्युटरले जुनसुकै तत्त्वको ठेगाना तुरुन्तै गणना गर्न सक्छ: ठेगाना = base + index × size। त्यसैले एरेको पहुँचलाई direct/random access भनिन्छ — a[900] मा पुग्न पनि a[0] जत्तिकै समय लाग्छ।

Example 1 Declaring an array and printing it
#include <iostream>
using namespace std;

int main() {
    int marks[5] = {75, 82, 60, 91, 48};

    for (int i = 0; i < 5; i++) {
        cout << "marks[" << i << "] = " << marks[i] << endl;
    }
    return 0;
}
Output 
marks[0] = 75
marks[1] = 82
marks[2] = 60
marks[3] = 91
marks[4] = 48

The loop runs while i < 5, so i takes the values 0, 1, 2, 3, 4 — exactly the five valid indexes. लुप i < 5 सम्म चल्छ, त्यसैले i ले ०,१,२,३,४ मान लिन्छ — यीनै पाँच वटा मान्य index हुन्।

Common mistake
Writing marks[5] to reach the last element. In an array of size 5 the last index is 4. marks[5] is outside the array and gives a garbage value or crashes the program. C++ does not warn you. अन्तिम तत्त्वका लागि marks[5] लेख्नु गलत हो। साइज ५ को एरेमा अन्तिम index ४ हो। marks[5] एरे बाहिर पर्छ र फोहोर मान दिन्छ वा प्रोग्राम क्र्यास हुन्छ। C++ ले चेतावनी दिँदैन।

1.5.1 (b)  Linked List — लिंक्ड लिस्ट

Linked List

A linked list is a collection of elements called nodes, where each node has two parts: the data, and a pointer holding the address of the next node.

The nodes are not in continuous memory — they may sit anywhere. The list is held together only by the pointers. A special pointer called head points to the first node, and the last node's pointer holds NULL to mark the end.

Because memory is taken one node at a time, the list can grow and shrink while the program is running. This is called a dynamic data structure.

Types: singly linked list (one pointer), doubly linked list (pointers to next and previous), circular linked list (last node points back to the first).

लिंक्ड लिस्ट

लिंक्ड लिस्ट भनेको नोड भनिने तत्त्वहरूको संग्रह हो। हरेक नोडका दुई भाग हुन्छन्: डाटा, र अर्को नोडको ठेगाना राख्ने pointer।

नोडहरू लगातार मेमोरीमा हुँदैनन् — जहाँसुकै हुन सक्छन्। लिस्टलाई पोइन्टरले मात्र जोडेर राख्छ। head नामक पोइन्टरले पहिलो नोड देखाउँछ, र अन्तिम नोडको पोइन्टरमा NULL हुन्छ जसले अन्त्य जनाउँछ।

एक–एक नोड गरी मेमोरी लिने भएकाले लिस्ट प्रोग्राम चल्दै गर्दा घटबढ हुन सक्छ। यसैलाई dynamic डाटा स्ट्रक्चर भनिन्छ।

प्रकार: singly (एउटा पोइन्टर), doubly (अघि र पछि दुवैको पोइन्टर), circular (अन्तिम नोडले पहिलो नोड देखाउने)।

Example 2 What one node looks like in C++
struct Node {
    int data;          // part 1 — the value
    Node *next;        // part 2 — address of the next node
};

int main() {
    Node *head = new Node;   // create the first node
    head->data = 75;
    head->next = NULL;       // NULL means "the list ends here"
    return 0;
}

Notice Node *next; — a Node that stores the address of another Node. That single line is what makes the chain possible. Node *next; हेर्नुहोस् — एउटा Node ले अर्को Node को ठेगाना राख्छ। यही एउटा लाइनले शृंखला सम्भव बनाउँछ।

1.5.1 (c)  Stack — स्ट्याक

Stack

A stack is a linear data structure in which insertion and deletion take place at only one end, called the top.

It follows the LIFO principle — Last In, First Out. The element inserted last is the element removed first.

Operations: push() inserts, pop() removes, peek() (or top()) reads the top without removing it, isEmpty() and isFull() check the state.

Overflow = pushing into a full stack. Underflow = popping from an empty stack. An empty stack has top = -1.

Applications: the browser Back button, Undo in an editor, function calls in memory (the call stack), reversing a string, checking balanced brackets, and converting infix expressions to postfix.

स्ट्याक

स्ट्याक त्यस्तो रेखीय डाटा स्ट्रक्चर हो जहाँ राख्ने र झिक्ने काम एउटै छेउ (top) बाट मात्र हुन्छ।

यसले LIFO — Last In, First Out नियम मान्छ। अन्तिममा हालेको तत्त्व सबैभन्दा पहिले निस्कन्छ।

अपरेसन: push() हाल्ने, pop() झिक्ने, peek() नझिकी हेर्ने, isEmpty() र isFull() अवस्था जाँच्ने।

Overflow = भरिएको स्ट्याकमा push। Underflow = खाली स्ट्याकबाट pop। खाली स्ट्याकमा top = -1 हुन्छ।

प्रयोग: ब्राउजरको Back बटन, एडिटरको Undo, फङ्सन कलको call stack, स्ट्रिङ उल्टाउने, ब्राकेट मिलेको छ कि छैन जाँच्ने, infix लाई postfix मा बदल्ने।

Analogy — a pile of plates
You wash plates and stack them one on top of another. The plate you put down last sits on top, so it is the plate you pick up first. The very first plate is at the bottom and leaves last. You cannot pull a plate from the middle without lifting the ones above it. उदाहरण — थाकिएका प्लेट। धोएर एक–अर्कामाथि थुपारेका प्लेटमध्ये अन्तिममा राखेको सबैभन्दा माथि हुन्छ, त्यसैले पहिले त्यही उठाइन्छ। पहिलो प्लेट सबैभन्दा तल हुन्छ र अन्तिममा निस्कन्छ।

1.5.1 (d)  Queue — क्यु

Queue

A queue is a linear data structure in which insertion takes place at one end (the rear) and deletion takes place at the other end (the front).

It follows the FIFO principle — First In, First Out. The element inserted first is the element removed first.

Operations: enqueue() inserts at the rear, dequeue() removes from the front, front() reads the first element without removing it.

A queue is empty when front > rear.

Types: simple queue, circular queue (the rear wraps back to the start to reuse space), priority queue (the most important element leaves first), double-ended queue or deque (insert and delete allowed at both ends).

Applications: the printer job queue, CPU scheduling, a call-centre waiting line, and data buffers.

क्यु

क्यु त्यस्तो रेखीय डाटा स्ट्रक्चर हो जहाँ एउटा छेउ (rear) बाट राखिन्छ र अर्को छेउ (front) बाट झिकिन्छ।

यसले FIFO — First In, First Out नियम मान्छ। पहिले हालेको पहिले निस्कन्छ।

अपरेसन: enqueue() पछाडि हाल्ने, dequeue() अगाडिबाट झिक्ने, front() पहिलो तत्त्व नझिकी हेर्ने।

front > rear हुँदा क्यु खाली हुन्छ।

प्रकार: simple queue, circular queue (rear घुमेर सुरुमै फर्कने), priority queue (महत्त्वपूर्ण तत्त्व पहिले निस्कने), deque (दुवै छेउबाट राख्न–झिक्न मिल्ने)।

प्रयोग: प्रिन्टरको job queue, CPU scheduling, कल–सेन्टरको लाइन, डाटा बफर।

1.5.2 (a)  Tree — ट्री

Tree

A tree is a non-linear data structure that arranges data in a hierarchy of nodes. It has exactly one node at the top called the root, and every other node has exactly one parent. A tree contains no cycles.

Terms you must know:

  • Root — the topmost node; the only node with no parent.
  • Parent — a node that has nodes below it.
  • Child — a node directly below another node.
  • Siblings — nodes that share the same parent.
  • Leaf (terminal node) — a node with no children.
  • Level — the root is level 0, its children level 1, and so on.
  • Height / Depth — the number of levels from the root to the deepest leaf.

A binary tree is a tree in which every node has at most two children.

ट्री

ट्री त्यस्तो अरेखीय डाटा स्ट्रक्चर हो जसले डाटालाई नोडहरूको तह (hierarchy) मा मिलाउँछ। माथि एउटा मात्र root हुन्छ, र अरू हरेक नोडको एउटा मात्र parent हुन्छ। ट्रीमा चक्र (cycle) हुँदैन।

जान्नैपर्ने शब्दहरू:

  • Root — सबैभन्दा माथिको नोड; parent नभएको एक मात्र नोड।
  • Parent — तल नोड भएको नोड।
  • Child — कुनै नोडको ठीक तलको नोड।
  • Siblings — एउटै parent भएका नोडहरू।
  • Leaf — सन्तान नभएको नोड।
  • Level — root level ०, त्यसका सन्तान level १, यसरी नै।
  • Height — root देखि सबैभन्दा तलको leaf सम्मको तह संख्या।

Binary tree भनेको हरेक नोडका बढीमा दुई सन्तान हुने ट्री हो।

1.5.2 (b)  Graph — ग्राफ

Graph

A graph is a non-linear data structure made of a set of vertices (also called nodes) joined by a set of edges (lines).

Any vertex may connect to any other vertex. There is no root, no parent–child rule, and cycles are allowed — this is the main difference from a tree.

In a directed graph the edges have arrows (one-way). In an undirected graph the edges have no direction (two-way). A weighted graph puts a number on each edge, for example the distance between two cities.

Applications: road maps and Google Maps routing, social networks, computer networks.

ग्राफ

Example 3 Searching — linear search on an array
#include <iostream>
using namespace std;

int main() {
    int a[6] = {12, 45, 7, 23, 56, 9};
    int key = 23, pos = -1;

    for (int i = 0; i < 6; i++) {
        if (a[i] == key) {      // compare one by one
            pos = i;
            break;              // stop as soon as it is found
        }
    }

    if (pos != -1)
        cout << "Found " << key << " at index " << pos;
    else
        cout << "Not found";
    return 0;
}
Output 
Found 23 at index 3

Linear search checks elements one by one and works even on unsorted data. Binary search is far faster but the data must be sorted first. Linear search ले एक–एक गरी जाँच्छ र नमिलेको डाटामा पनि चल्छ। Binary search धेरै छिटो हुन्छ तर डाटा मिलेको हुनैपर्छ।

Why did this happen?

In the stack, the value pushed last came out first — only top moved. That is LIFO.

In the queue, the value inserted first came out first — rear moved on insert, front moved on delete. That is FIFO.

Exam focus — questions asked from this unit

SEE exam connection · परीक्षा जोड

Data structure terms, classification and operations are guaranteed marks — the definitions are asked almost every year.

डाटा स्ट्रक्चरका शब्द, वर्गीकरण र अपरेसन पक्का अंक हुन् — परिभाषा लगभग हरेक वर्ष सोधिन्छ।
Q1 · Define data structure and list any four advantages. [4 marks]

Model answer: A data structure is a particular way of organising, storing and managing data in a computer's memory so that it can be accessed and modified efficiently.

Advantages: (i) efficiency — searching and sorting become faster; (ii) reusability — one structure can be used in many programs; (iii) abstraction — the user need not know the internal working; (iv) better memory utilisation.

परिभाषा र कुनै चार फाइदा लेख्नुहोस्। माथिकै अंग्रेजी वाक्य जस्ताको तस्तै लेख्दा पूरा अंक आउँछ।
Q2 · Differentiate between linear and non-linear data structures with examples. [4 marks]

In a linear data structure the elements are arranged in a sequence, one after another, at a single level, and the whole structure can be traversed in one run. Examples: array, linked list, stack, queue.

In a non-linear data structure the elements are not in a sequence; one element may connect to many, the structure has multiple levels, and it cannot be traversed in one straight run. Examples: tree, graph.

दुवैको परिभाषा + कम्तीमा दुई–दुई उदाहरण लेख्नुहोस्। तालिकाको रूपमा लेखे झन् राम्रो।
Q3 · What is a stack? Explain LIFO with a real-life example and name its operations. [5 marks]

A stack is a linear data structure in which insertion and deletion take place at only one end, called the top. It follows LIFO — Last In, First Out — meaning the element inserted last is removed first.

Real-life example: a pile of plates. The plate placed last sits on top and is taken first.

Operations: push() to insert, pop() to remove, peek()/top() to read the top element, isEmpty() and isFull() to check the state. Pushing into a full stack causes overflow; popping from an empty stack causes underflow.

परिभाषा + LIFO + प्लेटको उदाहरण + अपरेसनका नाम — चारै कुरा लेखे पूरा अंक।
Q4 · Explain the terms entity, attribute, record and file with one example each. [4 marks]

Entity — a real-world thing about which data is stored, e.g. Student.
Attribute (field) — one property of that entity, e.g. Name, Roll, Marks.
Record — a collection of related fields describing one entity, e.g. Ram | 15 | 78.
File — a collection of related records, e.g. the records of all 40 students.

चारै शब्दको एक–एक लाइन परिभाषा र एक–एक उदाहरण दिनुहोस्।

Key points to revise — दोहोर्‍याउनुपर्ने मुख्य बुँदा

  • Data structure = organising + storing + managing data for efficient access.
  • Ladder: Field → Record → File. Entity = the real thing described.
  • Linear = array, linked list, stack, queue. Non-linear = tree, graph.
  • Array = continuous memory, fixed size, direct access by index (starts at 0).
  • Linked list = scattered memory, dynamic size, sequential access, node = data + pointer.
  • Stack = LIFO, one end (top). Queue = FIFO, two ends (front and rear).
  • Tree has a root and one parent per node, no cycles. Graph has no root and cycles are allowed.
  • Six operations: traversing, searching, insertion, deletion, sorting, merging.
