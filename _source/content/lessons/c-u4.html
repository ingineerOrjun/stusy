4.1  What a function is — Function भनेको के हो

A named block of code that does one job

A function is a named, self-contained block of statements that performs a particular task and can be called from anywhere in the program.

You have been using one since Unit 2 without naming it: main() is a function, and so are printf and scanf. A C program is nothing but functions — which is why C is called a structured language.

Three words the examination separates carefully:

  • an argument is the value you send at the call — larger(a, b);
  • a parameter is the variable that receives it — int x, int y;
  • the return value is the single answer sent back.

A function takes any number of arguments and returns at most one value. That asymmetry is not an accident of syntax — it is the reason 4.4 exists.

एउटा काम गर्ने, नाम भएको कोडको खण्ड

Function भनेको नाम भएको, आफैंमा पूरा statement को खण्ड हो, जसले कुनै निश्चित काम गर्छ र प्रोग्रामको जहाँबाट पनि बोलाउन सकिन्छ।

युनिट २ देखि नै तपाईंले नाम नलिई यो चलाइरहनुभएको छ: main() function हो, र printf अनि scanf पनि। C प्रोग्राम function बाहेक केही होइन — त्यसैले C लाई structured भाषा भनिन्छ।

परीक्षाले ध्यान दिएर छुट्याउने तीन शब्द:

  • argument भनेको call मा पठाइने मान — larger(a, b);
  • parameter भनेको त्यो पाउने variable — int x, int y;
  • return value भनेको फर्काइने एउटै उत्तर।

Function ले जति पनि argument लिन्छ र बढीमा एउटा मान फर्काउँछ। यो असमानता syntax को संयोग होइन — ४.४ हुनुको कारण त्यही हो।

4.2  Declaration, definition and calling — घोषणा, परिभाषा र call

One function, three appearances

Declaration (prototype) — tells the compiler the function's name, what it returns and what it takes, so a call can be checked before the body is read. It ends with a semicolon and is written above main.

Definition — the same heading with the body in braces. This is where the work is. There is no semicolon after the closing brace.

Call — the name with real values in the brackets, inside another function. This is the only one of the three that makes anything happen.

If the definition is written above main, the declaration may be left out — the definition has already told the compiler everything. Writing the prototype anyway is the habit to form, because real programs put definitions in a different file.

एउटै function, तीन पटक देखिने

Declaration (prototype) — compiler लाई function को नाम, के फर्काउँछ र के लिन्छ भन्छ, ताकि body पढ्नुअघि नै call जाँच्न सकियोस्। यो semicolon ले सकिन्छ र main माथि लेखिन्छ।

Definition — उही शीर्षक र brace भित्र body। काम यहीँ हुन्छ। बन्द गर्ने brace पछि semicolon हुँदैन।

Call — अर्को function भित्र, कोष्ठकमा वास्तविक मान राखेर नाम लेख्नु। तीनमध्ये केही गराउने एकमात्र यही हो।

Definition main माथि लेखिएको छ भने declaration छाड्न मिल्छ — definition ले compiler लाई सबै भनिसक्यो। तैपनि prototype लेख्ने बानी बसाल्नुहोस्, किनभने वास्तविक प्रोग्राममा definition अर्कै फाइलमा हुन्छ।

Example 1 All three, in one program

Question: write a program that uses a function to find the larger of two numbers, and label the declaration, the definition and the call.

Decide what the function should RETURN before you open this — the larger number, or nothing at all with the printing done inside? Both work; only one of them can be reused. खोल्नुअघि function ले के RETURN गर्नुपर्छ निर्णय गर्नुहोस् — ठूलो सङ्ख्या, कि भित्रै छापेर केही पनि होइन? दुवै चल्छन्; फेरि प्रयोग गर्न मिल्ने चाहिँ एउटै हो।

Working 
#include <stdio.h>

int larger(int x, int y);        /* 1. DECLARATION — note the semicolon */

int main()
{
    int a, b, big;

    printf("Enter two numbers: ");
    scanf("%d %d", &a, &b);

    big = larger(a, b);          /* 3. CALL — a and b are the ARGUMENTS */

    printf("Larger = %d", big);
    return 0;
}

int larger(int x, int y)         /* 2. DEFINITION — no semicolon here  */
{
    if (x > y)
        return x;
    return y;                    /* reached only when x is not larger  */
}
Output (if the user types 12 and 8) 
Enter two numbers: 12 8
Larger = 12

Returning the value rather than printing inside the function is what makes larger reusable: the caller decides whether to print it, store it or compare it again. Note also that the second return needs no else — if the first one runs, the function has already ended. Function भित्रै नछापी मान return गर्नुले larger लाई पुनःप्रयोगयोग्य बनाउँछ: छाप्ने, राख्ने कि फेरि तुलना गर्ने भन्ने बोलाउनेले निर्णय गर्छ। अर्को कुरा — दोस्रो return लाई else चाहिँदैन; पहिलो चल्यो भने function त्यहीँ सकिइसक्यो।

Practise the judgement · निर्णय अभ्यास गर्नुहोस्

Declaration, definition or call?

What you will learn: to name the three appearances of a function from the line alone. The punctuation at the end decides it — a semicolon, a brace, or a result being used. तपाईंले के सिक्नुहुन्छ: लाइन मात्र हेरेर function का तीन रूप नाम लिन। अन्त्यको चिन्हले निर्णय गर्छ — semicolon, brace, कि नतिजा प्रयोग भएको।

How to use this

Read the end of the line first. Semicolon after the brackets means a prototype; an opening brace means the definition; real values inside the brackets mean a call.

पहिले लाइनको अन्त्य पढ्नुहोस्। कोष्ठकपछि semicolon भए prototype; खुल्ने brace भए definition; कोष्ठकभित्र वास्तविक मान भए call।

4.3  Types of function — library and user-defined — Function का प्रकार — library र user-defined

Written for you, or written by you

A library function comes with the compiler, already written and already compiled. You do not define it; you include its header and call it. printf and scanf need stdio.h; strlen and strcpy need string.h; sqrt and pow need math.h.

A user-defined function is one you write yourself, because no library function does your particular job — larger above, or a function that computes a student's division from their marks.

By what crosses the boundary, a user-defined function is one of four shapes, and the examination sometimes asks for all four:

  • no arguments, no return value — void greet(void)
  • arguments, no return value — void show(int n)
  • no arguments, a return value — int readNumber(void)
  • arguments and a return value — int larger(int x, int y)

void means "nothing here". In front of the name it says no value comes back; inside the brackets it says no argument goes in.

तपाईंका लागि लेखिएको, कि तपाईंले लेखेको

Library function compiler सँगै आउँछ — पहिल्यै लेखिएको र compile भइसकेको। तपाईंले define गर्नुहुन्न; यसको header include गरेर बोलाउनुहुन्छ। printf र scanf लाई stdio.h; strlen र strcpy लाई string.h; sqrt र pow लाई math.h चाहिन्छ।

User-defined function भनेको तपाईं आफैंले लेख्ने हो, किनभने तपाईंको त्यो विशेष काम कुनै library function ले गर्दैन — माथिको larger, वा अंकबाट विद्यार्थीको श्रेणी निकाल्ने function।

सिमाना के–के नाघ्छ भन्ने आधारमा user-defined function चार आकारमध्ये एक हुन्छ, र परीक्षाले कहिलेकाहीं चारै सोध्छ:

  • argument छैन, return पनि छैन — void greet(void)
  • argument छ, return छैन — void show(int n)
  • argument छैन, return छ — int readNumber(void)
  • argument पनि छ, return पनि — int larger(int x, int y)

void को अर्थ "यहाँ केही छैन" हो। नाम अगाडि भए कुनै मान फर्कंदैन भन्छ; कोष्ठकभित्र भए कुनै argument जाँदैन भन्छ।

4.4  Call by value and call by reference — Call by value र call by reference

The most-asked question in this unit

In call by value, a copy of each argument is made and handed to the function. The function works on the copies, so the caller's variables cannot change. This is what C does by default, and it is safe: a function cannot damage something it was only shown.

In call by reference, the address of each argument is sent instead, using & at the call and * in the parameter list. The function can then reach back into the caller's memory, so the originals do change.

Strictly, C has only call by value — what is copied in the second case is the address, not the variable. The effect is call by reference and that is the name the syllabus and the examination use, so use it; but knowing that a pointer is itself passed by value is what makes the mechanism make sense rather than being a rule.

Why bother? A function returns at most one value. A function that must change two variables — a swap — has no other way.

यस युनिटको सबैभन्दा धेरै सोधिने प्रश्न

Call by value मा हरेक argument को प्रतिलिपि बनाएर function लाई दिइन्छ। Function ले प्रतिलिपिमै काम गर्छ, त्यसैले बोलाउनेका variable बदलिन सक्दैनन्। C ले पूर्वनिर्धारित रूपमा यही गर्छ, र यो सुरक्षित छ: देखाइएको मात्र कुरालाई function ले बिगार्न सक्दैन।

Call by reference मा हरेक argument को ठेगाना पठाइन्छ — call मा & र parameter सूचीमा * लेखेर। अनि function ले बोलाउनेको मेमोरीसम्म पुग्न सक्छ, त्यसैले मूल variable बदलिन्छन्।

कडा अर्थमा C सँग call by value मात्र छ — दोस्रो अवस्थामा प्रतिलिपि बन्ने कुरा ठेगाना हो, variable होइन। असर चाहिँ call by reference कै हो र पाठ्यक्रम अनि परीक्षाले त्यही नाम चलाउँछन्, त्यसैले तपाईं पनि त्यही लेख्नुहोस्; तर pointer आफैं value बाट पठाइन्छ भन्ने थाहा पाउनुले यो नियम होइन, व्यवस्था हो भन्ने बुझाउँछ।

किन चाहियो? Function ले बढीमा एउटा मान फर्काउँछ। दुई variable बदल्नुपर्ने function — swap — सँग अर्को उपाय छैन।

Call by value or call by reference?

What you will learn: to answer the real question, which is never what the function prints but whether the caller's variable survived unchanged. तपाईंले के सिक्नुहुन्छ: साँचो प्रश्नको उत्तर दिन — function ले के छाप्यो भन्ने होइन, बोलाउनेको variable जस्ताको तस्तै रह्यो कि रहेन भन्ने।

How to use this

Look for two things together: an & at the call and a * in the parameter list. One without the other is not call by reference. Arrays are the one exception — the name is already an address.

दुई कुरा सँगै खोज्नुहोस्: call मा & र parameter सूचीमा *। एउटा मात्र भए त्यो call by reference होइन। Array एक मात्र अपवाद हो — नाम आफैं ठेगाना हो।

4.5  Recursive functions — Recursive function

A function that calls itself, and the line that stops it

A recursive function is one that calls itself, directly or through another function. It is used where a problem is naturally defined in terms of a smaller version of itself: 4! is 4 × 3!, and 3! is 3 × 2!, and so on.

Every recursive function needs two parts, and leaving out the first is the classic error:

  • a base case — a condition under which it returns an answer without calling itself. For factorial that is if (n == 1) return 1;
  • a recursive case — the call to itself, with an argument moving towards the base case.

Without a base case the calls never stop. The program does not loop forever quietly: each call takes memory on the stack, the stack fills, and the program crashes with a stack overflow.

Recursion versus a loop. Anything recursion can do, a loop can do. Recursion is often shorter and closer to the mathematical definition; a loop uses less memory, because it does not stack up unfinished calls. For factorial a loop is the better program and recursion is the better illustration, which is why the curriculum asks for it.

आफैंलाई बोलाउने function, र त्यसलाई रोक्ने लाइन

Recursive function भनेको सिधै वा अर्को function मार्फत आफैंलाई बोलाउने function हो। समस्या आफैंको सानो रूपमा परिभाषित हुने ठाउँमा यो चलाइन्छ: 4! भनेको 4 × 3! हो, र 3! भनेको 3 × 2!, यसरी नै।

हरेक recursive function लाई दुई भाग चाहिन्छ, र पहिलो छुटाउनु नै उत्कृष्ट गल्ती हो:

  • base case — जुन सर्तमा आफैंलाई नबोलाई उत्तर फर्काउँछ। Factorial मा if (n == 1) return 1;
  • recursive case — आफैंलाई बोलाउने, र argument base case तिर सर्दै जाने।

Base case नभए call कहिल्यै रोकिँदैनन्। प्रोग्राम चुपचाप सधैं चलिरहने होइन: हरेक call ले stack मा मेमोरी लिन्छ, stack भरिन्छ, र प्रोग्राम stack overflow भएर crash हुन्छ।

Recursion कि loop। Recursion ले गर्न सक्ने सबै loop ले पनि गर्छ। Recursion प्रायः छोटो र गणितीय परिभाषासँग नजिक हुन्छ; loop ले कम मेमोरी खान्छ, किनभने अधुरा call थुपार्दैन। Factorial का लागि loop राम्रो प्रोग्राम हो र recursion राम्रो उदाहरण — त्यसैले पाठ्यक्रमले यो माग्छ।

Four calls down, four returns back

What you will learn: that every multiplication happens on the way back up, not on the way down, and that four unfinished calls exist at once. The call stack panel is the point of this one. तपाईंले के सिक्नुहुन्छ: हरेक गुणन तल जाँदा होइन फर्कंदा हुन्छ, र एकैचोटि चार अधुरा call हुन्छन्। यसको मुख्य कुरा call stack को प्यानल नै हो।

How to use this

Watch the call stack grow to four and then empty. Ask at each step: has any multiplication happened yet? The answer is no until the base case returns.

Call stack चारसम्म बढेर अनि खाली भएको हेर्नुहोस्। हरेक चरणमा सोध्नुहोस्: कुनै गुणन भयो? Base case नफर्कंदासम्म जवाफ होइन हुन्छ।

4.6  Advantages of functions — Function का फाइदा

Five reasons, each with the problem it solves
  • Reusability — written once, called many times from anywhere in the program. Copying the same ten lines to four places means fixing a mistake in four places.
  • Smaller, readable programs — a long main becomes a short list of named steps, and the name is documentation that cannot go out of date.
  • Easier testing and debugging — a fault is located in one function instead of searched for across the whole file.
  • Division of work — different people can write different functions at the same time, agreeing only on the prototypes.
  • Abstraction — the caller needs to know what a function does, not how. You use printf daily and have never read it.

The one cost worth naming: a call has a small overhead in time and stack memory. For Grade 9 programs it is far too small to matter, and clarity wins every time.

पाँच कारण, हरेकसँग त्यसले समाधान गर्ने समस्या
  • पुनःप्रयोग — एक पटक लेखेर प्रोग्रामको जहाँबाट पनि धेरै पटक बोलाउन मिल्छ। उही दस लाइन चार ठाउँमा सार्नु भनेको गल्ती चार ठाउँमा सच्याउनु हो।
  • सानो, पढ्न सजिलो प्रोग्राम — लामो main नाम भएका चरणको छोटो सूची बन्छ, र नाम आफैं कहिल्यै पुरानो नहुने documentation हो।
  • जाँच्न र सच्याउन सजिलो — त्रुटि पूरै फाइलमा खोज्नुभन्दा एउटै function मा भेटिन्छ।
  • कामको बाँडफाँट — prototype मा मात्र सहमत भएर फरक मान्छेले फरक function एकैचोटि लेख्न सक्छन्।
  • Abstraction — बोलाउनेलाई function ले के गर्छ थाहा हुनुपर्छ, कसरी गर्छ होइन। तपाईं दिनहुँ printf चलाउनुहुन्छ र कहिल्यै पढ्नुभएको छैन।

नाम लिनै पर्ने एउटा लागत: हरेक call ले समय र stack मेमोरीमा सानो भार थप्छ। कक्षा ९ का प्रोग्रामका लागि त्यो नगण्य छ, र स्पष्टता सधैं जित्छ।

Predict first · पहिले अनुमान गर्नुहोस्

A function must give back BOTH the quotient and the remainder of a division. How can it? कुनै function ले भागफल र शेष दुवै फर्काउनुपर्छ। कसरी सक्छ?

One comes back through return; the other is written through a pointer. int divide(int a, int b, int *rem) { *rem = a % b; return a / b; } called as q = divide(17, 5, &r); leaves q as 3 and r as 2.

Option A is not C. return q, r; compiles — the comma operator evaluates q, throws it away, and returns r — so the function silently returns only the remainder. A wrong answer that compiles is worse than one that does not.

Option B works and does the division twice. On this scale that costs nothing; the reason to prefer option C is that the two answers come from one calculation and should leave together.

This is why call by reference exists. "A function returns at most one value" is not a limitation you work around — it is the fact that makes pointers necessary.

एउटा return ले फर्कन्छ; अर्को pointer मार्फत लेखिन्छ। int divide(int a, int b, int *rem) { *rem = a % b; return a / b; } लाई q = divide(17, 5, &r); ले बोलाउँदा q ३ र r २ हुन्छ। विकल्प (क) C होइन। return q, r; compile त हुन्छ — comma operator ले q मूल्याङ्कन गरेर फाल्छ र r फर्काउँछ — त्यसैले function ले चुपचाप शेष मात्र फर्काउँछ। Compile हुने गलत उत्तर नहुने भन्दा नराम्रो हो। विकल्प (ख) चल्छ तर भाग दुई पटक गर्छ; यति सानो कुरामा लागत छैन, तर (ग) रोज्नुको कारण दुवै उत्तर एउटै गणनाबाट आउँछन् र सँगै निस्कनुपर्छ भन्ने हो। Call by reference हुनुको कारण यही हो। "Function ले बढीमा एउटा मान फर्काउँछ" भन्ने कुरा पन्छाउने बाधा होइन — pointer लाई अनिवार्य बनाउने तथ्य त्यही हो।
Example 2 One call, traced through both files of the program

Question: state the output, and say how many times main is suspended.

#include <stdio.h>

int square(int n)
{
    printf("in square, n = %d\n", n);
    return n * n;
}

int main()
{
    int r;
    printf("before\n");
    r = square(4);
    printf("after, r = %d\n", r);
    return 0;
}

Write the three output lines in the order they appear. The question is not what square does — it is where main is while square is running. तीन output लाइन देखिने क्रममा लेख्नुहोस्। प्रश्न square ले के गर्छ भन्ने होइन — square चल्दै गर्दा main कहाँ हुन्छ भन्ने हो।

Working
main starts prints before reaches r = square(4) SUSPENDS here, and waits square starts, n is a new variable holding 4 prints in square, n = 4 returns 16 main RESUMES at the same line stores 16 into r prints after, r = 16 returns 0
Output 
before
in square, n = 4
after, r = 16

main is suspended exactly once, and the line r = square(4); is not finished until the return arrives — the assignment happens after the function has ended, not before it starts. That ordering is what "a call is a round trip" means, and it is why "after" cannot be printed in the middle. main ठ्याक्कै एक पटक रोकिन्छ, र r = square(4); लाइन return नआएसम्म सकिँदैन — assignment function सकिएपछि हुन्छ, सुरु हुनुअघि होइन। "Call भनेको आउने–जाने यात्रा हो" भन्नुको अर्थ त्यही क्रम हो, र "after" बीचमा छापिन नसक्नुको कारण पनि त्यही।

Practise it — the help comes away · अभ्यास गर्नुहोस् — सहयोग घट्दै जान्छ

Mistakes that cost marks here

  • A semicolon after the definition's closing brace. A prototype takes one; a definition does not.
  • Expecting a call-by-value function to change the caller's variable. It cannot. Look for & and *.
  • Writing a recursive function with no base case. It is not an infinite loop, it is a crash.
  • Confusing argument with parameter. Argument is at the call; parameter is in the definition.
  • Returning two values. A function returns at most one; use pointers for the second.
  • Calling a library function without its header. sqrt without math.h is an error, not a warning you can ignore.
Definition को बन्द brace पछि semicolon: prototype लाई चाहिन्छ, definition लाई चाहिँदैन। Call by value ले बोलाउनेको variable बदल्छ भन्ठान्नु: सक्दैन; & र * खोज्नुहोस्। Base case नभएको recursive function: यो अनन्त loop होइन, crash हो। Argument र parameter मिसाउनु: argument call मा, parameter definition मा। दुई मान return गर्न खोज्नु: बढीमा एउटा; दोस्रोका लागि pointer। Header नराखी library function बोलाउनु: math.h विनाको sqrt बेवास्ता गर्न मिल्ने चेतावनी होइन, त्रुटि हो।

Memory hook — Value sends a photocopy; reference sends the address. No ampersand, no change. सम्झने तरिका — Value ले फोटोकपी पठाउँछ; reference ले ठेगाना। Ampersand छैन भने बदलाव पनि छैन।

2 marks Practice question

What is a function? Write any two advantages of using functions. Function भनेको के हो? Function प्रयोग गर्नुका कुनै दुई फाइदा लेख्नुहोस्।

A function is a named, self-contained block of statements that performs a specific task and can be called from anywhere in the program. It may take arguments and returns at most one value.

Advantages (any two): reusability — written once and called many times; readability — a long program becomes a short list of named steps; easier debugging — a fault is isolated to one function; division of work — several people can write different functions at once.

Function भनेको नाम भएको, आफैंमा पूरा statement को खण्ड हो, जसले निश्चित काम गर्छ र प्रोग्रामको जहाँबाट पनि बोलाउन सकिन्छ। यसले argument लिन सक्छ र बढीमा एउटा मान फर्काउँछ। फाइदा (कुनै दुई): पुनःप्रयोग, पढ्न सजिलो, सच्याउन सजिलो, कामको बाँडफाँट।
4 marks Practice question

Write a C program to find the factorial of a number using a recursive function. Recursive function प्रयोग गरेर सङ्ख्याको factorial निकाल्ने C प्रोग्राम लेख्नुहोस्।

#include <stdio.h>

int fact(int n);

int main()
{
    int n;

    printf("Enter a number: ");
    scanf("%d", &n);

    printf("Factorial = %d", fact(n));
    return 0;
}

int fact(int n)
{
    if (n == 1 || n == 0)       /* base case */
        return 1;
    return n * fact(n - 1);     /* recursive case */
}

Marks: the base case, the recursive call with n - 1 moving towards it, and a correct prototype. Including n == 0 is worth a mark of its own, because 0! is defined as 1 and a base case of n == 1 alone would recurse forever on an input of 0.

अंक: base case, base case तिर सर्ने n - 1 सहितको recursive call, र सही prototype। n == 0 समेट्नुको आफ्नै अंक छ, किनभने 0! लाई १ मानिन्छ र n == 1 मात्रको base case भए input ० मा सधैं recurse भइरहन्थ्यो।
8 marks Practice question

Differentiate between call by value and call by reference with a suitable program for each. Call by value र call by reference को फरक, हरेकको उपयुक्त प्रोग्रामसहित लेख्नुहोस्।

Call by value: a copy of each argument is passed. The function works on the copies, so the caller's variables are unchanged. It is the default in C and it is safe.

#include <stdio.h>

void swap(int x, int y)
{
    int t = x;
    x = y;
    y = t;
}

int main()
{
    int a = 5, b = 9;
    swap(a, b);
    printf("a = %d, b = %d", a, b);   /* a = 5, b = 9 */
    return 0;
}

Call by reference: the address of each argument is passed, with & at the call and * in the parameter list. The function reaches the caller's memory, so the originals change.

#include <stdio.h>

void swap(int *x, int *y)
{
    int t = *x;
    *x = *y;
    *y = t;
}

int main()
{
    int a = 5, b = 9;
    swap(&a, &b);
    printf("a = %d, b = %d", a, b);   /* a = 9, b = 5 */
    return 0;
}

The differences, in a line each. What is passed: a copy, against an address. What the function can change: nothing outside itself, against the caller's variables. Memory: two extra variables, against two pointers. Safety: cannot damage the caller, against can. Use it when: the function only needs to read, against the function must change the caller's data or return more than one answer.

Call by value: हरेक argument को प्रतिलिपि जान्छ; function प्रतिलिपिमै काम गर्छ, त्यसैले बोलाउनेका variable नबदलिने। C मा पूर्वनिर्धारित र सुरक्षित। Call by reference: ठेगाना जान्छ — call मा &, parameter मा *; function ले बोलाउनेको मेमोरीसम्म पुगेर मूल variable बदल्छ। फरक: के पठाइन्छ — प्रतिलिपि कि ठेगाना। Function ले के बदल्न सक्छ — आफूबाहिर केही होइन, कि बोलाउनेका variable। सुरक्षा — बिगार्न नसक्ने कि सक्ने। कहिले चलाउने — function ले पढ्ने मात्र भए पहिलो, बोलाउनेको data बदल्नुपर्ने वा एकभन्दा बढी उत्तर चाहिने भए दोस्रो।

Key points from this unit

  • A function is a named block doing one job; main is one, and so is printf.
  • Declaration ends with a semicolon, definition has the body and no semicolon, a call carries real values.
  • Argument is at the call; parameter is in the definition.
  • Library functions come with the compiler and need their header; user-defined functions you write.
  • Call by value copies — the caller cannot change. Call by reference sends the address with & and * — the caller does change.
  • An array name is already an address, so a function always gets the real array.
  • A recursive function needs a base case, or the stack overflows.
  • A function returns at most one value; pointers are how a second answer gets out.
Function एउटा काम गर्ने, नाम भएको खण्ड हो; main पनि, printf पनि। Declaration semicolon ले सकिन्छ, definition सँग body हुन्छ र semicolon हुँदैन, call मा वास्तविक मान हुन्छन्। Argument call मा, parameter definition मा। Library function compiler सँगै आउँछ र header चाहिन्छ; user-defined तपाईंले लेख्नुहुन्छ। Call by value ले प्रतिलिपि बनाउँछ — बोलाउनेको बदलिँदैन। Call by reference ले & र * सहित ठेगाना पठाउँछ — बोलाउनेको बदलिन्छ। Array को नाम आफैं ठेगाना हो, त्यसैले function लाई सधैं साँच्चैको array पुग्छ। Recursive function लाई base case चाहिन्छ, नत्र stack overflow हुन्छ। Function ले बढीमा एउटा मान फर्काउँछ; दोस्रो उत्तर pointer ले बाहिर निस्कन्छ।
