7.1  Introduction to pointers — Pointer को परिचय

Every variable lives somewhere, and the address is a value

When you declare int n = 25;, two facts come into existence: n holds 25, and n lives at some address in memory. You have been using the first fact since Unit 2. The second is this unit.

A pointer is a variable that stores the address of another variable. It is an ordinary variable in every respect — it has a type, it has a name, it lives at an address of its own — and what it holds happens to be a location rather than a quantity.

The address a program sees is not fixed. Run the same program twice and n may be at a different address each time. That is why a program never writes an address down and always asks for it with &, and why the number 1000 in the figure below is an illustration and not a fact.

हरेक variable कतै बस्छ, र ठेगाना आफैंमा एउटा मान हो

int n = 25; घोषणा गर्दा दुई तथ्य जन्मन्छन्: n सँग २५ छ, र n मेमोरीको कुनै ठेगानामा बस्छ। पहिलो तथ्य तपाईंले युनिट २ देखि चलाइरहनुभएको छ। दोस्रो यही युनिट हो।

Pointer भनेको अर्को variable को ठेगाना राख्ने variable हो। यो हरेक हिसाबले सामान्य variable नै हो — यसको प्रकार छ, नाम छ, आफ्नै ठेगाना छ — र यसले राख्ने कुरा परिमाण नभई स्थान हो।

प्रोग्रामले देख्ने ठेगाना स्थिर हुँदैन। उही प्रोग्राम दुई पटक चलाउँदा n हरेक पटक फरक ठेगानामा हुन सक्छ। त्यसैले प्रोग्रामले ठेगाना कहिल्यै लेखेर राख्दैन, सधैं & ले सोध्छ — र तलको चित्रमा देखिने १००० सङ्ख्या उदाहरण हो, तथ्य होइन।

7.2  Declaring a pointer variable — Pointer variable को घोषणा

The star in the declaration is part of the type

int *p; declares p as "a pointer to an int". The star here is not the dereference operator — it is part of the type, and it is the one place in C where the same symbol means two different things a line apart.

The type matters. int *p; and float *q; both hold an address, and the type tells the compiler how to interpret the bytes found there and how far one step is. A pointer with the wrong type gives nonsense, not an error.

A declared pointer points at nothing useful until it is given an address:

  • int *p; — p exists and holds garbage. Dereferencing it now is a genuine crash waiting to happen.
  • p = &n; — p now holds n's address.
  • int *p = &n; — both on one line, which is the safer habit.

Print an address with %p. Printing it with %d does not fail loudly — it prints a number — but on a 64-bit machine an address is 8 bytes and an int is 4, so the number you see is only part of the address. Checked on gcc: printf("%d", &n) compiled with no message at all and printed 830470604 for an address whose real value was 0x9B659FF94C. gcc -Wall does warn about it.

घोषणामा आउने star प्रकारकै भाग हो

int *p; ले p लाई "int को pointer" घोषणा गर्छ। यहाँको star dereference operator होइन — यो प्रकारकै भाग हो, र C मा उही चिन्हले एक लाइनको फरकमा दुई फरक अर्थ दिने ठाउँ यही एक हो।

प्रकारले फरक पार्छ। int *p; र float *q; दुवैले ठेगाना राख्छन्, र प्रकारले compiler लाई त्यहाँका byte कसरी पढ्ने अनि एक पाइला कति टाढा हो भन्छ। गलत प्रकारको pointer ले त्रुटि होइन, बेकारको नतिजा दिन्छ।

घोषणा गरिएको pointer लाई ठेगाना नदिएसम्म यो काम लाग्ने कतै देखाउँदैन:

  • int *p; — p छ र यसमा garbage छ। अहिले dereference गर्नु भनेको crash निम्त्याउनु हो।
  • p = &n; — अब p सँग n को ठेगाना छ।
  • int *p = &n; — दुवै एउटै लाइनमा, र सुरक्षित बानी यही हो।

ठेगाना छाप्न %p चलाउनुहोस्। %d ले ठाडै असफल हुँदैन — एउटा सङ्ख्या छाप्छ — तर ६४-bit मेसिनमा ठेगाना ८ byte को हुन्छ र int ४ byte को, त्यसैले देखिने सङ्ख्या ठेगानाको अंश मात्र हो। gcc मा जाँचिएको: printf("%d", &n) कुनै सन्देशविनै compile भयो र 0x9B659FF94C ठेगानाको ठाउँमा 830470604 छाप्यो। gcc -Wall ले यसबारे चेतावनी दिन्छ।

7.3  Referencing and dereferencing — Referencing र dereferencing

Two operators, opposite directions

Referencing — the address-of operator & takes a variable and gives its address. &n is "where n lives".

Dereferencing — the value-at operator * takes an address and gives what is stored there. *p is "the value at the address in p".

They undo each other: *(&n) is simply n. Reading them as English helps more than memorising them — "address of n", "value at p".

The star works in both directions. printf("%d", *p); reads a value out through the pointer; *p = 50; writes a value in through it, and n changes although the line never mentions n. That second use is the whole of call by reference, and the whole of why pointers are treated with care.

दुई operator, उल्टा दिशा

Referencing — address-of operator & ले variable लिएर त्यसको ठेगाना दिन्छ। &n भनेको "n कहाँ बस्छ" हो।

Dereferencing — value-at operator * ले ठेगाना लिएर त्यहाँ भएको कुरा दिन्छ। *p भनेको "p मा भएको ठेगानाको मान" हो।

यी एकअर्कालाई उल्ट्याउँछन्: *(&n) भनेको n नै हो। कण्ठ गर्नुभन्दा अङ्ग्रेजीमा पढ्दा बढी सजिलो हुन्छ — "address of n", "value at p"।

Star दुवै दिशामा चल्छ। printf("%d", *p); ले pointer मार्फत मान निकाल्छ; *p = 50; ले त्यसैमार्फत मान भित्र राख्छ, र लाइनले n को नाम नलिई पनि n बदलिन्छ। दोस्रो प्रयोग नै पूरै call by reference हो, र pointer लाई होसियारीसाथ चलाउनुपर्ने कारण पनि त्यही।

Step through it · चरणबद्ध हेर्नुहोस्

A pointer holds an address, not a value

What you will learn: that p and *p are two different things on the same line, and that writing through a pointer changes a variable the line never names. The last two steps are the ones that matter. तपाईंले के सिक्नुहुन्छ: एउटै लाइनमा p र *p दुई फरक कुरा हुन्, र pointer मार्फत लेख्दा लाइनले नाम नै नलिएको variable बदलिन्छ। महत्त्वपूर्ण चरण अन्तिम दुई हुन्।

How to use this

Read the four variable rows as two pairs: what n is and where n is, then what p holds and what is at that place. The last step changes n through the second pair alone.

चारै पङ्क्तिलाई दुई जोडी बनाएर पढ्नुहोस्: n के हो र n कहाँ छ, अनि p सँग के छ र त्यो ठाउँमा के छ। अन्तिम चरणले दोस्रो जोडीबाटै n बदल्छ।

Practise the judgement · निर्णय अभ्यास गर्नुहोस्

Which pointer operator is needed here?

What you will learn: to decide between & and * from the direction the line is travelling — taking an address out, or taking a value out of an address. तपाईंले के सिक्नुहुन्छ: लाइन कुन दिशामा गइरहेको छ हेरेर & र * छुट्याउन — ठेगाना निकालेको, कि ठेगानाबाट मान निकालेको।

How to use this

One case needs neither operator. An array name is already an address, which is why scanf("%s", name) takes no ampersand while scanf("%d", &n) does.

एउटा केसमा कुनै पनि operator चाहिँदैन। Array को नाम आफैं ठेगाना हो — त्यसैले scanf("%s", name) लाई ampersand चाहिँदैन र scanf("%d", &n) लाई चाहिन्छ।

Predict first · पहिले अनुमान गर्नुहोस्

After int n = 7; int *p = &n; *p = *p + 3; what does printf("%d", n); print? int n = 7; int *p = &n; *p = *p + 3; पछि printf("%d", n); ले के छाप्छ?

10. Read *p = *p + 3; as "the value at p becomes the value at p plus three". The value at p is n, so this is n = n + 3 written another way.

Option A is the belief this unit exists to remove: a variable can be changed by a line that does not name it, provided something holds its address. That is not a trick — it is exactly what scanf("%d", &n) has been doing since Unit 2, and what call by reference does in Unit 4.

Option C confuses p with *p. Printing p would show an address; printing n or *p shows 10. One star is the whole difference.

१०। *p = *p + 3; लाई "p को ठेगानाको मान बराबर p को ठेगानाको मान जोड तीन" भनेर पढ्नुहोस्। P को ठेगानाको मान नै n हो, त्यसैले यो n = n + 3 कै अर्को लेखाइ हो। विकल्प (क) यस युनिटले हटाउन खोजेकै विश्वास हो: कसैसँग ठेगाना छ भने नाम नलिने लाइनले पनि variable बदल्न सक्छ। यो जादू होइन — युनिट २ देखि scanf("%d", &n) ले गरिरहेकै काम हो, र युनिट ४ को call by reference ले गर्ने पनि त्यही। विकल्प (ग) ले p र *p मिसाउँछ। p छापे ठेगाना देखिन्थ्यो; n वा *p छापे १०। पूरै फरक एउटा star को हो।

7.4  Advantages of pointers — Pointer का फाइदा

Four, and you have used two already
  • A function can change the caller's variables. This is call by reference, and it is the only way a function can hand back more than one answer. You met it in Unit 4; this unit is the explanation of how it worked.
  • Arrays are passed without copying. An array name is already an address, so sending an array of a thousand elements to a function costs one address rather than a thousand copies — and it is why sorting inside a function changes the caller's array.
  • Memory can be asked for while the program runs — dynamic memory allocation, with malloc and free. It is how a program handles a list whose size nobody knew when it was written. Not on the Grade 9 syllabus; named here because it is the reason pointers matter in Grade 10 and beyond.
  • Data structures become possible. A linked list, a tree and a graph are built out of items that hold the address of the next item. Without pointers there is no way to write one, which is where Grade 10 Unit 1 begins.

The cost, stated honestly: a pointer that holds a wrong address will read or write somewhere it should not, and C will not stop it. Power and risk are the same property seen from two sides.

चार, र तपाईंले दुई त चलाइसक्नुभयो
  • Function ले बोलाउनेका variable बदल्न सक्छ। यही call by reference हो, र function ले एकभन्दा बढी उत्तर फर्काउने एकमात्र उपाय यही हो। युनिट ४ मा भेट्नुभयो; यो युनिट त्यो कसरी चल्यो भन्ने व्याख्या हो।
  • Array प्रतिलिपि नबनाई पठाइन्छ। Array को नाम आफैं ठेगाना हो, त्यसैले हजार element को array function लाई पठाउँदा हजार प्रतिलिपि होइन एउटा ठेगाना मात्र लाग्छ — र function भित्र क्रम मिलाउँदा बोलाउनेकै array बदलिनुको कारण पनि त्यही।
  • प्रोग्राम चल्दै गर्दा मेमोरी माग्न सकिन्छ — dynamic memory allocation, malloc र free सहित। लेख्ने बेला आकार कसैलाई थाहा नभएको सूची प्रोग्रामले यसैगरी सम्हाल्छ। कक्षा ९ को पाठ्यक्रममा छैन; कक्षा १० र त्यसपछि pointer किन महत्त्वपूर्ण हुन्छ भन्ने कारण भएकाले यहाँ नाम लिइएको हो।
  • Data structure सम्भव हुन्छन्। Linked list, tree र graph अर्को वस्तुको ठेगाना राख्ने वस्तुहरूबाट बन्छन्। Pointer नभए यी लेख्ने उपायै हुँदैन, र कक्षा १० को युनिट १ त्यहींबाट सुरु हुन्छ।

लागत, इमानदारीसाथ: गलत ठेगाना बोकेको pointer ले नपुग्नुपर्ने ठाउँमा पढ्छ वा लेख्छ, र C ले रोक्दैन। शक्ति र जोखिम एउटै गुणलाई दुई तिरबाट हेरेको हो।

Example 1 Reading a variable two ways

Question: write a program that prints a variable's value, its address, and the same value reached through a pointer.

Three of the four printf lines below are easy. Decide what &p prints and why it is different from p. तलका चार printf मध्ये तीन सजिलो छन्। &p ले के छाप्छ र p भन्दा किन फरक हुन्छ, निर्णय गर्नुहोस्।

Working 
#include <stdio.h>

int main()
{
    int n = 25;
    int *p;

    p = &n;                        /* p now holds the address of n */

    printf("Value of n      : %d\n", n);
    printf("Address of n    : %p\n", (void *) &n);
    printf("Value in p      : %p\n", (void *) p);   /* same as &n */
    printf("Value at p (*p) : %d\n", *p);           /* same as n  */
    printf("Address of p    : %p\n", (void *) &p); /* p's OWN address */

    *p = 50;                       /* write through the pointer    */
    printf("n is now        : %d\n", n);
    return 0;
}
Output — the addresses here are illustrative; read the note 
Value of n      : 25
Address of n    : 0x7ffd1a2b3c4c
Value in p      : 0x7ffd1a2b3c4c
Value at p (*p) : 25
Address of p    : 0x7ffd1a2b3c40
n is now        : 50

Lines 2 and 3 print the same number, which is the point: p's value is n's address. Line 5 prints a different one, because p is itself a variable living somewhere of its own. And the last two lines are the unit in miniature — a line that does not mention n changes n. दोस्रो र तेस्रो लाइनले उही सङ्ख्या छाप्छन्, र मुख्य कुरा त्यही हो: p को मान नै n को ठेगाना हो। पाँचौंले फरक छाप्छ, किनभने p आफैं कतै बस्ने variable हो। अन्तिम दुई लाइन पूरै युनिटको सानो रूप हुन् — n को नाम नलिने लाइनले n बदल्छ।

Three things in that output are not promised. The addresses change on every run. The shape of them belongs to the compiler's library: gcc on Linux writes an address as 0x7ffd1a2b3c4c, and MinGW gcc on Windows writes the same kind of address as 000000F7EBBFF74C — sixteen digits, upper case, no 0x. And whether p sits above or below n is the compiler's business: when this listing was run on Windows to check it, p turned out to be twelve bytes below n. What is promised is the relationship — lines 2 and 3 equal, line 5 different. The (void *) before each address is there because %p is defined to take a void *; most textbooks write printf("%p", &n) and most compilers accept it, but gcc -Wall will tell you about it. त्यो output का तीन कुराको वाचा छैन। ठेगाना हरेक पटक फेरिन्छ। त्यसको रूप compiler को library को कुरा हो: Linux को gcc ले 0x7ffd1a2b3c4c लेख्छ, Windows को MinGW gcc ले उही किसिमको ठेगानालाई 000000F7EBBFF74C लेख्छ — सोह्र अङ्क, ठूलो अक्षर, 0x छैन। र p, n भन्दा माथि बस्छ कि तल — त्यो compiler को कुरा हो: यो listing जाँच्न Windows मा चलाउँदा p, n भन्दा बाह्र byte तल निस्कियो। वाचा भएको कुरा सम्बन्ध हो — दोस्रो र तेस्रो लाइन बराबर, पाँचौं फरक। हरेक ठेगानाअघिको (void *) त्यहाँ छ किनभने %p ले void * लिने परिभाषा छ; धेरै पाठ्यपुस्तक printf("%p", &n) लेख्छन् र धेरै compiler ले मान्छन्, तर gcc -Wall ले यसबारे भनिदिन्छ।

Example 2 The scanf you have been writing since Unit 2

Question: explain, using this unit's vocabulary, why scanf needs &n for an int and nothing for a char array.

Answer it in one sentence before opening this, using the word "address" twice. खोल्नुअघि "ठेगाना" शब्द दुई पटक प्रयोग गरेर एक वाक्यमा उत्तर दिनुहोस्।

Working 
#include <stdio.h>

int main()
{
    int n;
    char name[20];

    scanf("%d", &n);         /* & REQUIRED : n is an ordinary int    */
    scanf("%s", name);        /* no &       : the array name IS an    */
                              /*              address already          */
    printf("%d %s", n, name);
    return 0;
}
WHY scanf NEEDS AN ADDRESS AT ALL Arguments in C are passed BY VALUE, so a function receives copies. scanf has to change the caller's variable, and it cannot change a copy. It therefore takes the ADDRESS and writes through it — which is call by reference, and which is this unit. WHY THE ARRAY TAKES NO AMPERSAND An array name used on its own already IS the address of its first element. Writing &name is asking for the address of something that is one, which is not what scanf wants here. printf TAKES NEITHER printf only READS its arguments, so copies are enough and no address is needed.

Nothing in this program is new. The only thing that changed between Unit 2 and now is that you can say why — and that sentence is what a two-mark question on pointers is actually asking for. यस प्रोग्राममा नयाँ केही छैन। युनिट २ देखि अहिलेसम्म बदलिएको एउटै कुरा हो — अब तपाईं किन भन्न सक्नुहुन्छ। Pointer बारे दुई अंकको प्रश्नले साँच्चै खोज्ने वाक्य त्यही हो।

Mistakes that cost marks here

  • Confusing p with *p. One is an address, the other is the value there.
  • Thinking the star in int *p; dereferences. There it is part of the type; it only dereferences in a statement.
  • Dereferencing a pointer that was never given an address. It holds garbage, and the program crashes.
  • Writing p = n; instead of p = &n;. That stores a value where an address belongs.
  • Putting & before an array name. The name is already the address of the first element.
  • Quoting a specific address as a fact. It changes every run; say "the address of n", never "1000".
p र *p मिसाउनु: एउटा ठेगाना, अर्को त्यहाँको मान। int *p; को star ले dereference गर्छ भन्ठान्नु: त्यहाँ त्यो प्रकारको भाग हो; dereference statement मा मात्र गर्छ। ठेगाना नदिइएको pointer dereference गर्नु: त्यसमा garbage हुन्छ र प्रोग्राम crash हुन्छ। p = &n; को ठाउँमा p = n; लेख्नु: ठेगाना चाहिने ठाउँमा मान राखिन्छ। Array को नाम अगाडि & राख्नु: नाम आफैं पहिलो element को ठेगाना हो। कुनै निश्चित ठेगानालाई तथ्य भन्नु: त्यो हरेक पटक बदलिन्छ; "n को ठेगाना" भन्नुहोस्, "१०००" कहिल्यै होइन।

Memory hook — & asks "where?", * asks "what's there?" Address out, value out — opposite directions. सम्झने तरिका — & ले "कहाँ?" सोध्छ, * ले "त्यहाँ के छ?" ठेगाना बाहिर, मान बाहिर — उल्टा दिशा।

2 marks Practice question

What is a pointer? Write the syntax to declare a pointer variable with an example. Pointer भनेको के हो? उदाहरणसहित pointer variable घोषणा गर्ने syntax लेख्नुहोस्।

A pointer is a variable that stores the memory address of another variable rather than a value of its own.

Syntax: data_type *pointer_name;

Example: int n = 25; int *p; p = &n; — here p is a pointer to an integer and now holds the address of n. *p would give 25.

Pointer भनेको आफ्नो मान नभई अर्को variable को मेमोरी ठेगाना राख्ने variable हो। Syntax: data_type *pointer_name; उदाहरण: int n = 25; int *p; p = &n; — यहाँ p integer को pointer हो र अहिले n को ठेगाना बोकेको छ। *p ले २५ दिन्थ्यो।
2 marks Practice question

What is the difference between & and *? Write any two advantages of pointers. & र * को फरक के हो? Pointer का कुनै दुई फाइदा लेख्नुहोस्।

& is the address-of operator. It is written before a variable and gives that variable's memory address: &n.

* is the value-at, or dereference, operator. It is written before a pointer and gives the value stored at the address the pointer holds: *p. The two work in opposite directions, so *(&n) is just n.

Advantages (any two): a function can change the caller's variables, which is call by reference; arrays are passed to functions without being copied; memory can be allocated while the program runs; and data structures such as linked lists can be built.

& address-of operator हो — variable अगाडि लेखिन्छ र त्यसको मेमोरी ठेगाना दिन्छ। * value-at वा dereference operator हो — pointer अगाडि लेखिन्छ र pointer ले बोकेको ठेगानामा भएको मान दिन्छ। दुवै उल्टो दिशामा चल्छन्, त्यसैले *(&n) भनेको n नै हो। फाइदा (कुनै दुई): function ले बोलाउनेका variable बदल्न सक्नु — call by reference; array प्रतिलिपि नबनाई function लाई पठाइनु; प्रोग्राम चल्दै गर्दा मेमोरी छुट्याउन सकिनु; linked list जस्ता data structure बनाउन सकिनु।

Key points from this unit

  • A pointer is a variable that stores the address of another variable.
  • int *p; declares a pointer to an int; the star there is part of the type.
  • & gives an address; * gives the value at an address. They are opposites.
  • *p = 50; changes the variable p points at, without naming it.
  • Addresses change on every run, so a program asks for one with & and never writes one down.
  • An array name is already an address, which is why scanf("%s", name) takes no ampersand.
  • Advantages: call by reference, arrays passed without copying, dynamic memory, and data structures.
  • Unit 4's call by reference and Unit 2's scanf were both pointers all along.
Pointer भनेको अर्को variable को ठेगाना राख्ने variable हो। int *p; ले int को pointer घोषणा गर्छ; त्यहाँको star प्रकारकै भाग हो। & ले ठेगाना दिन्छ; * ले ठेगानाको मान — यी उल्टा हुन्। *p = 50; ले नाम नलिई p ले देखाएको variable बदल्छ। ठेगाना हरेक पटक बदलिन्छ, त्यसैले प्रोग्रामले & ले सोध्छ र कहिल्यै लेखेर राख्दैन। Array को नाम आफैं ठेगाना हो, त्यसैले scanf("%s", name) लाई ampersand चाहिँदैन। फाइदा: call by reference, प्रतिलिपि नबनाई array पठाउनु, dynamic memory, र data structure। युनिट ४ को call by reference र युनिट २ को scanf सुरुदेखि नै pointer थिए।
