1.1  Data, information, database, DBMS

Definition — learn this wording

Data is raw, unprocessed facts. On their own they carry no meaning: 78, Ram, 10.

Information is data that has been processed and given meaning: "Ram scored 78 in class 10." The same facts, now useful.

A database is a collection of related data, organised so it can be stored and retrieved efficiently.

A DBMS (Database Management System) is the software that creates, manages and controls access to a database — MySQL, Oracle, MS Access.

परिभाषा — यही शब्दमा सम्झनुहोस्

Data भनेको काँचो, प्रशोधन नगरिएको तथ्य हो। एक्लै यसको अर्थ हुँदैन: 78, Ram, 10।

Information भनेको प्रशोधन गरेर अर्थ दिइएको data हो: "रामले कक्षा १० मा ७८ अंक ल्याए।" उही तथ्य, अब काम लाग्ने।

Database भनेको सम्बन्धित data को सङ्ग्रह हो, जुन राख्न र झिक्न सजिलो हुने गरी व्यवस्थित गरिएको हुन्छ।

DBMS (Database Management System) भनेको डाटाबेस बनाउने, व्यवस्थापन गर्ने र पहुँच नियन्त्रण गर्ने सफ्टवेयर हो — MySQL, Oracle, MS Access।

Predict first · पहिले अनुमान गर्नुहोस्

A school stores its student records in MySQL. Which of these is the DATABASE? एउटा विद्यालयले विद्यार्थीको रेकर्ड MySQL मा राख्छ। यीमध्ये कुन डाटाबेस हो?

MySQL is the DBMS — the software. The database is the collection of data it manages. Saying "MySQL is a database" is the single most common slip in this unit, and it loses the mark in a "differentiate" question.

MySQL DBMS हो — सफ्टवेयर। डाटाबेस भनेको त्यसले व्यवस्थापन गर्ने data को सङ्ग्रह हो। "MySQL एउटा डाटाबेस हो" भन्नु यस युनिटको सबैभन्दा सामान्य गल्ती हो।

Practise the judgement · निर्णय अभ्यास गर्नुहोस्

Sort each one: data, information, database or DBMS?

What you will learn: to separate the four words on real examples, so the "differentiate between…" question is answered from recognition rather than from a memorised sentence. तपाईंले के सिक्नुहुन्छ: वास्तविक उदाहरणमा चारै शब्द छुट्याउन — ताकि "फरक छुट्याउनुहोस्" भन्ने प्रश्न घोकेको वाक्यबाट होइन, चिनेरै उत्तर दिन सकियोस्।

How to use this

Two of the five cases are software and two are content. Before you answer, ask one question: could I install this? If yes it is a DBMS; if it is something the DBMS stores or produces, it is one of the other three.

Then separate data from information by asking whether it means anything on its own. 78 does not. "Ram scored 78" does.

पाँचमध्ये दुई सफ्टवेयर हुन्, दुई सामग्री। उत्तर दिनुअघि एउटा प्रश्न सोध्नुहोस्: के यो install गर्न मिल्छ? मिल्छ भने DBMS; DBMS ले राख्ने वा दिने कुरा भए बाँकी तीनमध्ये एक। अनि आफैंमा अर्थ लाग्छ कि लाग्दैन सोधेर data र information छुट्याउनुहोस्।

1.2 & 1.3  Why the file system was not enough

Advantages and disadvantages

Advantages: redundancy is controlled; data stays consistent; data is shared between users; security and access control are possible; backup and recovery are built in; standards can be enforced.

Disadvantages — and they are real: a DBMS is expensive to buy and to run; it needs powerful hardware; it needs trained staff; and because everything is in one place, a failure affects everything at once.

An answer that lists only advantages is an incomplete answer. Examiners ask for both.

फाइदा र बेफाइदा

फाइदा: दोहोरोपन नियन्त्रण हुन्छ; data एकरूप रहन्छ; प्रयोगकर्ताबीच साझेदारी हुन्छ; सुरक्षा र पहुँच नियन्त्रण सम्भव हुन्छ; backup र recovery भित्रै हुन्छ; मानक लागू गर्न सकिन्छ।

बेफाइदा — र यी साँच्चिकै हुन्: DBMS किन्न र चलाउन महँगो हुन्छ; बलियो हार्डवेयर चाहिन्छ; तालिम पाएका कर्मचारी चाहिन्छन्; र सबै एकै ठाउँमा हुने भएकाले एउटै बिग्रँदा सबै प्रभावित हुन्छ।

फाइदा मात्र लेखेको उत्तर अपूरो हुन्छ। परीक्षकले दुवै सोध्छन्।

1.4 — Where database systems are used. Banking (accounts and transactions), airlines and bus booking (seats), schools and universities (students, marks, fees), hospitals (patient records), telecom (call records), online shops (products, orders), and government records — citizenship, land, voter rolls. डाटाबेस प्रणालीको प्रयोग: बैंकिङ (खाता र कारोबार), हवाई तथा बस टिकट (सिट), विद्यालय र विश्वविद्यालय (विद्यार्थी, अंक, शुल्क), अस्पताल (बिरामीको रेकर्ड), टेलिकम (कल रेकर्ड), अनलाइन पसल (सामान, अर्डर), र सरकारी अभिलेख — नागरिकता, जग्गा, मतदाता नामावली।

1.5  Types of database user

Four users, four jobs

Database Administrator (DBA) — has complete control. Creates the database, grants and revokes permission, takes backups, tunes performance. One person, or a small team.

Database Designer — decides what entities and relationships the database needs, before it is built.

Application Programmer — writes the programs that read and write the database through SQL.

End User — uses those programs. A naive end user works through a form or a menu and never sees SQL; a sophisticated end user writes their own queries.

चार प्रयोगकर्ता, चार काम

Database Administrator (DBA) — पूर्ण नियन्त्रण। डाटाबेस बनाउने, अधिकार दिने–खोस्ने, backup लिने, कार्यसम्पादन सुधार्ने।

Database Designer — बन्नुअघि नै कुन इन्टिटी र सम्बन्ध चाहिन्छ भन्ने तय गर्ने।

Application Programmer — SQL मार्फत डाटाबेस पढ्ने–लेख्ने प्रोग्राम लेख्ने।

End User — ती प्रोग्राम चलाउने। naive प्रयोगकर्ताले फारम वा मेनुबाट काम गर्छ र SQL देख्दैन; sophisticated प्रयोगकर्ताले आफैं क्वेरी लेख्छ।

1.6  DBMS architecture

{{dia:dbArchitecture}}
Data independence in one sentence each. Physical data independence — you can change how the data is stored on disk without changing the tables. Logical data independence — you can change the tables without changing what a user sees. Physical is the easier of the two to achieve; logical is harder, because a user's view is built directly on the tables. एक–एक वाक्यमा: Physical data independence — डिस्कमा data कसरी राखिन्छ त्यो बदल्दा तालिका बदल्नु पर्दैन। Logical data independence — तालिका बदल्दा प्रयोगकर्ताले देख्ने कुरा बदल्नु पर्दैन। पहिलो हासिल गर्न सजिलो, दोस्रो गाह्रो।

1.7 & 1.8  Database models, schema and instance

Schema and instance

A schema is the structure of the database — the table names, the columns and their types, the keys and the constraints. It is designed once and changes rarely.

An instance is the data actually in the database at a given moment. It changes every time a row is inserted, updated or deleted.

The same schema has a different instance every day. The schema of the Student table does not change when a new student joins — only its instance does.

Schema र instance

Schema भनेको डाटाबेसको संरचना हो — तालिकाका नाम, स्तम्भ र तिनका टाइप, कुञ्जी र बन्धन। एक पटक डिजाइन हुन्छ र विरलै बदलिन्छ।

Instance भनेको कुनै क्षणमा डाटाबेसमा साँच्चै भएको data हो। पङ्क्ति थपिँदा, बदलिँदा वा हट्दा हरेक पटक फेरिन्छ।

उही schema को instance हरेक दिन फरक हुन्छ। नयाँ विद्यार्थी भर्ना हुँदा Student तालिकाको schema बदलिँदैन — instance मात्र बदलिन्छ।

Example 1 Distinguishing the four terms in one answer

Question: differentiate between data and information, and between database and DBMS, with one example each. (4 marks)

Model answer
DATA vs INFORMATION Data raw facts with no meaning 78 Information processed data with meaning Ram scored 78 DATABASE vs DBMS Database the organised collection of data the Student table DBMS the software that manages it MySQL

Four marks, four lines. Answer in a two-column layout like this and you cannot accidentally define only one side of the pair — which is how this question is usually half-answered. चार अंक, चार हरफ। यसरी दुई स्तम्भमा लेख्नुभयो भने जोडीको एउटा पक्ष मात्र लेख्ने गल्ती हुँदैन — यो प्रश्न प्रायः त्यसैगरी आधा उत्तर हुन्छ।

Example 2 Deciding which level a change belongs to

Question: for each change, say which level of the three-level architecture it happens at, and which kind of data independence protects the level above it.

Working
"The database is moved to a faster disk." INTERNAL level — how the bytes are stored. Physical data independence means the tables above it do not change. "A new column 'email' is added to Student." CONCEPTUAL level — what data exists. Logical data independence means a teacher's view that never showed email is unaffected. "The class teacher is given a screen showing only name and marks." EXTERNAL level — what one user sees. Nothing below it changes at all.
Answer
disk change → internal (physical independence) new column → conceptual (logical independence) new user screen → external (no effect below)

Work from the bottom up: is this about the disk, about what data exists, or about who sees it? Those three questions map onto the three levels exactly, and the independence is always named after the level below the boundary it protects. तलबाट माथि सोच्नुहोस्: यो डिस्कको कुरा हो, कुन data छ भन्ने कुरा हो, कि कसले देख्छ भन्ने कुरा हो? यी तीन प्रश्न ठ्याक्कै तीन तहमा मिल्छन्, र independence को नाम सधैं आफूले जोगाउने सीमाको तल्लो तहबाट राखिन्छ।

Mistakes that cost marks here

  • Calling the DBMS "the database". The database is the data; the DBMS is the program. MySQL is a DBMS. DBMS लाई "डाटाबेस" भन्नु। डाटाबेस भनेको data, DBMS भनेको प्रोग्राम।
  • Listing advantages when the question says advantages AND disadvantages. Half the question, half the marks. फाइदा र बेफाइदा दुवै सोधिएको ठाउँमा फाइदा मात्र लेख्नु। आधा प्रश्न, आधा अंक।
  • Mixing up schema and instance. Adding a student changes the instance, not the schema. Schema र instance मिसाउनु। विद्यार्थी थप्दा instance बदलिन्छ, schema होइन।
  • Drawing the three-level architecture upside down. External is at the top, nearest the user; internal is at the bottom, nearest the disk. तीन तहको चित्र उल्टो कोर्नु। External माथि — प्रयोगकर्तानजिक; internal तल — डिस्कनजिक।

Exam focus — what is asked from this unit

This unit is short — 6 hours — but it supplies the definitions the whole subject is built on. Almost every question here is either define, differentiate or list. All three are answered from memory, so the work is learning the exact wording rather than reasoning it out in the hall. The three-level architecture is the one diagram from this unit you may be asked to draw. यो युनिट छोटो छ — ६ घण्टा — तर पूरै विषय यसैका परिभाषामाथि बनेको छ। यहाँका प्रायः सबै प्रश्न परिभाषा दिने, फरक छुट्याउने वा सूची बनाउने हुन्। तीनै सम्झेर लेख्ने भएकाले ठ्याक्कै शब्द याद गर्नु नै काम हो। यस युनिटबाट कोर्न सकिने चित्र तीन तहको संरचना हो।
2 marks Practice question

Define database and DBMS. डाटाबेस र DBMS को परिभाषा दिनुहोस्।

A database is a collection of related data organised so that it can be stored and retrieved efficiently.

A DBMS is the software that creates, manages and controls access to a database. Examples: MySQL, Oracle, MS Access.

दुवैको परिभाषा र DBMS का दुई उदाहरण लेख्नुहोस्।

3 marks Practice question

State any three limitations of the traditional file system. परम्परागत फाइल प्रणालीका कुनै तीन सीमा लेख्नुहोस्।

Data redundancy — the same fact is stored in several files. Data inconsistency — one copy is updated and the others are left stale. Data isolation — data sits in different files and formats, so combining it is hard. No concurrency control — two users writing at once can corrupt the file. Weak security — access cannot be controlled at the level of individual records.

Any three, each named and explained in one line.

कुनै तीन — नाम दिएर एक–एक हरफमा व्याख्या गर्नुहोस्।

Key points to revise — दोहोर्‍याउनुपर्ने मुख्य बुँदा

  • Data → information → database → DBMS. Each is built on the one before, and the DBMS is software, not data. Data → information → database → DBMS। हरेक अघिल्लोमाथि बनेको, र DBMS सफ्टवेयर हो, data होइन।
  • The file system's four problems are redundancy, inconsistency, isolation and no concurrency control. A database answers each one. फाइल प्रणालीका चार समस्या: दोहोरोपन, असङ्गति, अलगाव, र समवर्ती नियन्त्रणको अभाव। डाटाबेसले हरेकको जवाफ दिन्छ।
  • A database system also has real costs: money, hardware, trained staff, and one point of failure. डाटाबेस प्रणालीका वास्तविक लागत पनि छन्: पैसा, हार्डवेयर, तालिम पाएका कर्मचारी, र एउटै ठाउँमा जोखिम।
  • Users: DBA, designer, application programmer, end user. प्रयोगकर्ता: DBA, डिजाइनर, एप्लिकेसन प्रोग्रामर, end user।
  • Three levels: external (what a user sees), conceptual (what data exists), internal (how it is stored). The gaps between them are data independence. तीन तह: external (प्रयोगकर्ताले देख्ने), conceptual (कुन data छ), internal (कसरी राखिएको)। बीचका खाली ठाउँ नै data independence हुन्।
  • Schema is the structure and rarely changes; instance is today's data and changes constantly. Schema संरचना हो, विरलै बदलिन्छ; instance आजको data हो, निरन्तर बदलिन्छ।
