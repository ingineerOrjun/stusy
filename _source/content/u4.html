4.1  Abstraction

Definition — learn this wording

Abstraction means showing only the essential features of an object to the user and hiding the internal implementation details — that is, hiding how the work is actually done.

In C++ abstraction is achieved in two ways: using classes with access specifiers (data and helper functions kept private, only the useful functions made public), and at a higher level using abstract classes.

परिभाषा — यही शब्द कण्ठ पार्नुहोस्

एब्स्ट्र्याक्सन भनेको प्रयोगकर्तालाई आवश्यक कुरा मात्र देखाउने र भित्री काम कसरी हुन्छ भन्ने लुकाउने हो।

C++ मा यो दुई तरिकाले हासिल गरिन्छ: access specifier सहितको क्लास (डाटा र सहायक फङ्सन private, काम लाग्ने फङ्सन मात्र public), र माथिल्लो तहमा abstract class मार्फत।

Real-world analogy — driving a car

To drive, you use the steering wheel, accelerator and brake. You do not need to know about fuel injection, spark timing or the gearbox ratios.

The car abstracts all of that away. If the manufacturer redesigns the entire engine next year, you still drive it the same way — because the interface (the controls) did not change. That is the real benefit of abstraction in programming too.

उदाहरण — गाडी चलाउनु। तपाईंलाई स्टेरिङ, एक्सिलेटर र ब्रेक मात्र चाहिन्छ; इन्जिन भित्र के हुन्छ थाहा पाउनु पर्दैन। भोलि कम्पनीले पूरै इन्जिन फेरे पनि तपाईंले उसैगरी चलाउनुहुन्छ — किनकि नियन्त्रण (interface) फेरिएन। प्रोग्रामिङमा पनि abstraction को साँचो फाइदा यही हो।
Advantages of abstraction
  • Reduces complexity — the user sees a small, simple interface instead of thousands of lines.
  • Increases security — internal data and helper functions cannot be misused.
  • Easy to change later — the hidden code can be rewritten without breaking any program that uses it.
  • Improves reusability — the same class can be used in many programs.
  • Avoids code duplication and makes maintenance easier.
एब्स्ट्र्याक्सनका फाइदा
  • जटिलता घटाउँछ — हजारौं लाइनको सट्टा सानो, सजिलो interface मात्र देखिन्छ।
  • सुरक्षा बढाउँछ — भित्री डाटा र सहायक फङ्सनको दुरुपयोग हुँदैन।
  • पछि बदल्न सजिलो — लुकेको कोड बदल्दा प्रयोग गर्ने प्रोग्राम बिग्रँदैन।
  • पुनः प्रयोग — उही क्लास धेरै प्रोग्राममा चल्छ।
  • दोहोरो कोड हट्छ र मर्मत सजिलो हुन्छ।
Example 1 Achieving abstraction with a class
#include <iostream>
using namespace std;

class Calculator {
private:
    // hidden helper - the user never sees or calls this
    int square(int x) {
        return x * x;
    }
public:
    // the only thing the user is given
    int sumOfSquares(int a, int b) {
        return square(a) + square(b);
    }
};

int main() {
    Calculator c;
    cout << c.sumOfSquares(3, 4);   // user just calls this
    // c.square(3);   <-- ERROR: square() is private
    return 0;
}
Output 
25

The user calls one simple function and gets the answer. How it is calculated — the private square() helper — is completely hidden. That is abstraction. प्रयोगकर्ताले एउटा सजिलो फङ्सन बोलाएर जवाफ पाउँछ। कसरी गणना भयो — private square() — पूरै लुकेको छ। यही abstraction हो।

Abstract class and pure virtual function

The higher level of abstraction

A pure virtual function is a virtual function with no body, written by putting = 0 after it. It is a promise that says "every child class must provide this function".

A class that contains at least one pure virtual function is called an abstract class. You cannot create an object of an abstract class — it exists only to be inherited.

माथिल्लो तहको abstraction

Pure virtual function भनेको शरीर नभएको virtual फङ्सन हो, जसमा पछाडि = 0 लेखिन्छ। यसले "हरेक सन्तान क्लासले यो फङ्सन दिनैपर्छ" भन्ने वाचा गर्छ।

कम्तीमा एउटा pure virtual function भएको क्लासलाई abstract class भनिन्छ। यसको अब्जेक्ट बनाउन मिल्दैन — यो इनहेरिट गर्नकै लागि मात्र हुन्छ।

Example 2 An abstract class
class Shape {                     // ABSTRACT class
public:
    virtual void area() = 0;      // pure virtual function
};

class Circle : public Shape {
public:
    void area() {                 // MUST be provided
        cout << "Area of circle";
    }
};

int main() {
    // Shape s;      <-- ERROR: cannot create an object of an abstract class
    Circle c;        // this is fine
    c.area();
    return 0;
}
Output 
Area of circle

4.4  Encapsulation

Definition — learn this wording

Encapsulation means binding data members and member functions together into a single unit (the class), and hiding the data from direct outside access by declaring it private.

Outside code must then go through public functions — usually called setter and getter functions — to change or read that data. For this reason encapsulation is also called data hiding.

परिभाषा — यही शब्द कण्ठ पार्नुहोस्

इनक्याप्सुलेसन भनेको डाटा मेम्बर र मेम्बर फङ्सनलाई एउटै एकाइ (क्लास) मा बाँध्ने र डाटालाई private बनाएर बाहिरबाट सिधै छुन नदिने हो।

त्यसपछि बाहिरको कोडले डाटा बदल्न वा पढ्न public फङ्सन (setter/getter) प्रयोग गर्नै पर्छ। त्यसैले यसलाई data hiding पनि भनिन्छ।

Example 3 Encapsulation with a setter that validates
#include <iostream>
using namespace std;

class Account {
private:
    double balance;                    // hidden data

public:
    void setBalance(double b) {        // setter - it can CHECK the value
        if (b >= 0)
            balance = b;
        else
            cout << "Invalid amount rejected" << endl;
    }
    double getBalance() {              // getter - safe read only
        return balance;
    }
};

int main() {
    Account a;
    // a.balance = -500;    <-- ERROR: balance is private
    a.setBalance(-500);      // rejected by the setter
    a.setBalance(5000);      // accepted
    cout << "Balance = " << a.getBalance() << endl;
    return 0;
}
Output 
Invalid amount rejected
Balance = 5000

This is the whole point of encapsulation. If balance were public, a.balance = -500; would have silently corrupted the account. The setter is a guard at the only door. encapsulation को मुख्य उद्देश्य यही हो। balance public भएको भए a.balance = -500; ले चुपचाप खाता बिगार्थ्यो। setter एउटै ढोकामा उभिएको पहरेदार हो।

Advantages of encapsulation
  • Data security — data cannot be changed accidentally or wrongly from outside.
  • Full control — the setter can validate the value before storing it.
  • Read-only or write-only access — provide only a getter, or only a setter, as needed.
  • Easier maintenance and testing — the class can be changed inside without affecting other code.
  • Achieves data hiding, which is one of the main goals of OOP.
इनक्याप्सुलेसनका फाइदा
  • डाटा सुरक्षा — बाहिरबाट गल्तीले डाटा बदलिन सक्दैन।
  • पूर्ण नियन्त्रण — setter ले मान राख्नु अघि जाँच्न सक्छ।
  • पढ्ने मात्र वा लेख्ने मात्र पहुँच दिन सकिन्छ।
  • मर्मत र परीक्षण सजिलो — भित्र बदल्दा अरू कोडमा असर पर्दैन।
  • Data hiding हासिल हुन्छ, जुन OOP कै मुख्य लक्ष्य हो।

The difference students always get wrong

Say it in one line each

Abstraction hides the complexity — the "how".
Encapsulation hides the data — the "what".

Abstraction is a design idea: decide what to show. Encapsulation is an implementation idea: actually protect the data using private plus getters and setters.

Abstraction ले जटिलता ("कसरी" गर्ने) लुकाउँछ। Encapsulation ले डाटा ("के" छ) लुकाउँछ। एउटा डिजाइन को कुरा, अर्को कार्यान्वयन/सुरक्षा को कुरा।
BasisAbstractionEncapsulation
What it hidesHides the complexity / implementation — the "how".Hides the data — the "what".
LevelA design-level idea.An implementation-level idea.
Achieved byAbstract classes and pure virtual functions; access specifiers.private data with public getter and setter functions.
FocusFocuses on what an object does.Focuses on how the data is protected.
PurposeTo reduce complexity for the user.To secure the data from misuse.
Common mistake
Writing "both hide something, so they are the same". They are not. In the Account example above, encapsulation is balance being private. Abstraction is the user being given only setBalance() and getBalance() and never needing to know what happens inside them. "दुवैले केही लुकाउँछन्, त्यसैले उस्तै हुन्" भन्नु गलत। माथिको Account उदाहरणमा — balance private हुनु encapsulation हो; प्रयोगकर्तालाई setBalance() र getBalance() मात्र दिनु र भित्र के हुन्छ थाहा नदिनु abstraction हो।

Exam focus — questions asked from this unit

Q1 · Define abstraction. Write any three advantages. [4 marks]

Abstraction is the process of showing only the essential features of an object to the user while hiding the internal implementation details of how the work is done.

Advantages: it reduces complexity for the user; it increases security because internal details cannot be misused; and the internal code can be changed later without affecting the programs that use the class.

परिभाषा + कुनै तीन फाइदा। गाडीको उदाहरण दिए झन् राम्रो।

For the program, write the Account class from Example 3 above: a private balance, a public setBalance() and a public getBalance(), with main() creating an object and using the two functions.

परिभाषा + माथिको Example 3 कै प्रोग्राम लेख्नुहोस्।
Q3 · Differentiate between abstraction and encapsulation. [4 marks]

Abstraction hides the complexity or implementation — the "how" — and is a design-level concept achieved through abstract classes and access specifiers; it focuses on what an object does. Encapsulation hides the data — the "what" — and is an implementation-level concept achieved by making data private and providing public getters and setters; it focuses on protecting the data.

तालिकाको रूपमा चार हरफ लेख्नुहोस्: के लुकाउँछ, कुन तह, कसरी हासिल हुन्छ, केमा ध्यान।
Q4 · What is an abstract class? [2 marks]

An abstract class is a class that contains at least one pure virtual function — a virtual function with no body, declared using = 0. An object of an abstract class cannot be created; it exists only to be inherited, and every derived class must provide a definition for the pure virtual function.

pure virtual function भएको क्लास; यसको अब्जेक्ट बन्दैन।

Key points to revise — दोहोर्‍याउनुपर्ने मुख्य बुँदा

  • Abstraction = show essential features, hide implementation (the "how").
  • Encapsulation = bind data + functions together and hide the data (the "what").
  • Encapsulation is achieved by private data + public getter/setter.
  • Encapsulation is also called data hiding.
  • A pure virtual function has no body and is written = 0.
  • A class with at least one pure virtual function is an abstract class — no object can be created from it.
  • Abstraction = design level. Encapsulation = implementation level.
