1

Basic Introduction to Data Structure

डाटा स्ट्रक्चरको आधारभूत परिचय

20 hrs · 15 marks
Definition

A data structure is a particular way of organising, storing and managing data in a computer's memory so that it can be accessed and modified efficiently.

It is not the data itself. It is the arrangement of the data, plus the rules for putting data in and taking data out.

परिभाषा

डाटा स्ट्रक्चर भनेको कम्प्युटरको मेमोरीमा डाटालाई मिलाएर, राखेर र व्यवस्थापन गर्ने एउटा खास तरिका हो, ताकि त्यो डाटा छिटो र सजिलै प्रयोग र परिवर्तन गर्न सकियोस्।

यो डाटा आफैं होइन। यो डाटा कसरी मिलाइएको छ भन्ने कुरा र डाटा राख्ने–झिक्ने नियम हो।

Why it exists — real-world analogy

Think of a school library. The books are the data. If books are thrown on the floor, finding one takes very long. If books are kept on numbered shelves by subject, you find one in seconds.

The shelf system is the data structure. Same books, same room — but the arrangement decides the speed. A computer works the same way.

किन चाहिन्छ — व्यवहारिक उदाहरण

एउटा स्कुलको पुस्तकालय सम्झनुहोस्। किताबहरू डाटा हुन्। किताब भुइँमा जथाभावी फालिएको छ भने एउटा किताब खोज्न धेरै समय लाग्छ। तर विषय अनुसार नम्बर हालेको र्‍याकमा राखिएको छ भने सेकेन्डमै भेटिन्छ।

त्यो र्‍याकको व्यवस्था नै डाटा स्ट्रक्चर हो। किताब उही, कोठा उही — तर मिलाउने तरिकाले गति निर्धारण गर्छ। कम्प्युटरमा पनि ठ्याक्कै यस्तै हुन्छ।

1.2 Advantages of Data Structures

Advantages
  • Efficiency — the right structure makes searching and sorting much faster.
  • Reusability — one structure (e.g. a stack) can be used in many programs.
  • Abstraction — the user uses push() without knowing how it works inside.
  • Better memory use — memory is allocated only as needed.
  • Easy maintenance — organised data means clearer, shorter code.
  • Handles large data — millions of records stay manageable.
फाइदाहरू
  • Efficiency (दक्षता) — सही स्ट्रक्चरले खोज्ने र क्रम मिलाउने काम धेरै छिटो बनाउँछ।
  • Reusability (पुनः प्रयोग) — एउटै स्ट्रक्चर धेरै प्रोग्राममा प्रयोग गर्न सकिन्छ।
  • Abstraction — भित्र कसरी चल्छ थाहा नपाई पनि push() प्रयोग गर्न सकिन्छ।
  • मेमोरीको राम्रो प्रयोग — जति चाहिन्छ त्यति मात्र मेमोरी लिन्छ।
  • सजिलो मर्मत — मिलेको डाटाले कोड छोटो र स्पष्ट बनाउँछ।
  • ठूलो डाटा — लाखौं रेकर्ड पनि व्यवस्थित रहन्छ।

1.4 Need of Data Structures

Why we need them
  • Data is growing — programs must handle huge amounts of data.
  • Processor speed is limited — a faster CPU cannot fix a bad arrangement.
  • Search must be fast — searching 1,00,000 unsorted names is very slow.
  • Many users at once — data must be reached quickly by many requests.
  • Memory is limited — data must be stored without waste.
किन आवश्यक छ
  • डाटा बढ्दै छ — प्रोग्रामले धेरै ठूलो डाटा सम्हाल्नुपर्छ।
  • प्रोसेसरको गति सीमित छ — छिटो CPU ले पनि बिग्रेको मिलानलाई सुधार्न सक्दैन।
  • खोजी छिटो हुनुपर्छ — नमिलेको १ लाख नाम खोज्न धेरै ढिलो हुन्छ।
  • एकैचोटि धेरै प्रयोगकर्ता — डाटा छिटो पुग्नुपर्छ।
  • मेमोरी सीमित छ — खेर नफाली राख्नुपर्छ।

1.5 Classification of Data Structures

Two main groups

Linear data structure: elements are arranged in a sequence, one after another. Each element has one previous and one next element. It can be traversed in a single run.

Non-linear data structure: elements are not in a sequence. One element may connect to many elements. It cannot be traversed in a single straight run.

दुई मुख्य समूह

Linear (रेखीय): तत्त्वहरू एउटा पछि अर्को गरी क्रमैसँग राखिन्छन्। प्रत्येकको एउटा अघिल्लो र एउटा पछिल्लो हुन्छ। एकै पटकमा सबै घुम्न सकिन्छ।

Non-linear (अरेखीय): तत्त्वहरू क्रममा हुँदैनन्। एउटा तत्त्व धेरैसँग जोडिन सक्छ। सिधा एकै पटकमा सबै घुम्न सकिँदैन।

Array

A collection of elements of the same data type stored in continuous memory locations, accessed by an index that starts at 0. Size is fixed.

Stack

A list where insertion and deletion happen at only one end, called the top. It follows LIFO — Last In, First Out. Operations: push(), pop(), peek().

एउटै छेउ (top) बाट मात्र राख्ने र झिक्ने लिस्ट। LIFO — पछिल्लो राखेको पहिले निस्कन्छ। थाकिएको प्लेट जस्तै।

Queue

A list where insertion happens at the rear and deletion at the front. It follows FIFO — First In, First Out. Operations: enqueue(), dequeue().

पछाडि (rear) बाट राख्ने र अगाडि (front) बाट झिक्ने लिस्ट। FIFO — पहिले आएको पहिले जान्छ। लाइनमा बस्नु जस्तै।

1.5.2 Non-Linear Data Structures — अरेखीय

Tree

A hierarchical structure of nodes. It has one root node at the top, and every other node has exactly one parent. Nodes below a node are its children; a node with no child is a leaf. There is no cycle (loop).

तह–तह मिलेको नोडको संरचना। माथि एउटा root हुन्छ, हरेक नोडको एउटा मात्र parent हुन्छ। सन्तान नभएको नोड leaf हो। परिवारको वंशवृक्ष जस्तै।

Graph

A set of vertices (nodes) joined by edges (lines). Any vertex can connect to any other vertex, and cycles are allowed. There is no parent–child rule and no root.

बिन्दु (vertex) हरूलाई रेखा (edge) ले जोडेको संरचना। जुनसुकै बिन्दु जुनसुकैसँग जोडिन सक्छ, चक्र पनि हुन सक्छ। सडक नक्सा जस्तै।

2

Concept of Object Oriented Programming (OOP) using C++

C++ प्रयोग गरी अब्जेक्ट ओरिएन्टेड प्रोग्रामिङको अवधारणा

10 hrs · 14 marks
Definition

Object Oriented Programming (OOP) is a programming method that solves a big problem by breaking it into small parts called objects. Each object keeps its own data and the functions that work on that data bound together, so that no other part of the program can touch that data directly.

परिभाषा

OOP भनेको ठूलो समस्यालाई अब्जेक्ट भनिने साना–साना भागमा बाँडेर समाधान गर्ने प्रोग्रामिङ तरिका हो। हरेक अब्जेक्टले आफ्नो डाटा र त्यही डाटामाथि काम गर्ने फङ्सन लाई सँगै बाँधेर राख्छ, ताकि प्रोग्रामको अरू भागले त्यो डाटा सिधै छुन नसकोस्।

Real-world analogy — a TV remote
You press a button to change the channel. You do not know the circuit inside, and you cannot touch it. The remote keeps its parts (data) hidden and gives you only buttons (functions). That is exactly what an object does. TV को रिमोट सम्झनुहोस्। बटन थिच्दा च्यानल फेरिन्छ। भित्रको सर्किट तपाईंलाई थाहा हुँदैन र छुन पनि पाइँदैन। रिमोटले भित्री भाग (डाटा) लुकाएर बटन (फङ्सन) मात्र दिन्छ — अब्जेक्ट ले पनि ठ्याक्कै यही गर्छ।

2.2 Features of OOP

These are the standard exam-listed features. Learn all seven names in English.

1. Object

A real-world entity that has data (state) and functions (behaviour). It is an instance of a class.

डाटा र व्यवहार भएको वास्तविक वस्तु। क्लासको एउटा उदाहरण (instance)।

2. Class

A blueprint or template that describes what data and functions its objects will have. It takes no memory by itself.

अब्जेक्ट बनाउने नक्सा वा टेम्प्लेट। यसले आफैंले मेमोरी लिँदैन।

3. Encapsulation

Binding data and functions together in one unit and hiding the data from outside access.

डाटा र फङ्सनलाई एउटै एकाइमा बाँध्ने र डाटालाई बाहिरबाट लुकाउने।

4. Abstraction

Showing only the necessary features and hiding the internal details of how it works.

आवश्यक कुरा मात्र देखाउने र भित्री जटिलता लुकाउने।

5. Inheritance

One class acquires the properties and functions of another class, so code can be reused.

एउटा क्लासले अर्को क्लासका गुण र फङ्सन प्राप्त गर्ने — कोड पुनः प्रयोग हुन्छ।

6. Polymorphism

One name, many forms. The same function name behaves differently in different situations.

एउटै नाम, धेरै रूप। उही फङ्सनको नामले फरक अवस्थामा फरक काम गर्छ।

7. Message Passing

Objects communicate with each other by calling one another's member functions.

अब्जेक्टहरूले एकअर्काको फङ्सन बोलाएर सञ्चार गर्ने।

+ Dynamic Binding

The code to run for a function call is decided at run time, not at compile time.

कुन कोड चल्ने हो भन्ने कुरा कम्पाइल गर्दा होइन, चल्दै गर्दा निर्णय हुने।

2.5 Tokens and Character Set

Token

A token is the smallest individual unit of a C++ program that has meaning to the compiler. C++ has six kinds of tokens:

  • Keywords — reserved words with a fixed meaning: int, class, if, return
  • Identifiers — names given by the programmer: roll, sum, Student
  • Constants / Literals — fixed values: 25, 3.14, 'A', "Ram"
  • Operators — symbols that do an operation: + - * / % = <<
  • Punctuators / Separators — ; , ( ) { } [ ]
  • Strings — a sequence of characters in double quotes

Character set = all the characters C++ understands: letters A–Z a–z, digits 0–9, special symbols, and white space.

टोकन

टोकन भनेको C++ प्रोग्रामको सबैभन्दा सानो अर्थपूर्ण एकाइ हो, जुन कम्पाइलरले बुझ्छ। C++ मा ६ प्रकारका टोकन हुन्छन्:

  • Keywords — पहिल्यै अर्थ तोकिएका शब्द: int, class, if
  • Identifiers — प्रोग्रामरले राखेको नाम: roll, sum
  • Constants — नबदलिने मान: 25, 3.14, 'A'
  • Operators — काम गर्ने चिन्ह: + - * /
  • Punctuators — ; , ( ) { }
  • Strings — डबल कोट भित्रका अक्षरहरू

Character set = C++ ले बुझ्ने सबै अक्षर: A–Z, a–z, ०–९, विशेष चिन्ह र खाली ठाउँ।

Class and Object

क्लास र अब्जेक्ट

7 hrs
Class

A class is a user-defined data type that acts as a blueprint. It groups data members (variables) and member functions (methods) together. A class does not take memory — it is only a design.

क्लास

क्लास भनेको प्रयोगकर्ताले बनाएको डाटा टाइप हो, जुन नक्सा (blueprint) जस्तै काम गर्छ। यसले डाटा मेम्बर (भेरिएबल) र मेम्बर फङ्सन लाई एकैठाउँ राख्छ। क्लासले आफैंले मेमोरी लिँदैन — यो डिजाइन मात्र हो।

Object

An object is a variable of a class — one real copy made from the blueprint. An object takes memory. Each object has its own separate copy of the data members. Creating an object is called instantiation.

अब्जेक्ट

अब्जेक्ट भनेको क्लासको भेरिएबल हो — नक्सा हेरेर बनाइएको वास्तविक प्रति। अब्जेक्टले मेमोरी लिन्छ। हरेक अब्जेक्टसँग आफ्नै छुट्टै डाटाको प्रति हुन्छ। अब्जेक्ट बनाउने कामलाई instantiation भनिन्छ।

One-line memory hook
A class is the house design on paper. An object is the real house built from it. One design → many houses. You cannot live in the design. क्लास = कागजमा कोरेको घरको नक्सा। अब्जेक्ट = त्यो नक्साबाट बनेको साँच्चिकै घर। एउटा नक्साबाट धेरै घर बन्छ। नक्सामा बस्न मिल्दैन।

3.5 Constructor and Destructor

Constructor

A constructor is a special member function that is called automatically when an object is created. Its job is to initialise the object's data.

  • Its name is exactly the same as the class name.
  • It has no return type — not even void.
  • It can take parameters and can be overloaded.
  • Types: default, parameterized, copy constructor.
कन्स्ट्रक्टर

कन्स्ट्रक्टर एउटा विशेष मेम्बर फङ्सन हो, जुन अब्जेक्ट बन्ने बित्तिकै आफैं बोलिन्छ। यसको काम अब्जेक्टको डाटालाई सुरुवाती मान दिनु हो।

  • यसको नाम क्लासको नामसँग ठ्याक्कै मिल्नुपर्छ।
  • यसको return type हुँदैन — void पनि होइन।
  • यसले प्यारामिटर लिन सक्छ र overload पनि हुन सक्छ।
  • प्रकार: default, parameterized, copy।
Destructor

A destructor is a special member function that is called automatically when an object is destroyed (when it goes out of scope). Its job is to free the memory.

  • Its name is the class name with a tilde ~ in front.
  • It has no return type and takes no parameters.
  • It cannot be overloaded — there is only one destructor per class.
  • Objects are destroyed in the reverse order of their creation.
डिस्ट्रक्टर

डिस्ट्रक्टर एउटा विशेष मेम्बर फङ्सन हो, जुन अब्जेक्ट नष्ट हुँदा आफैं बोलिन्छ। यसको काम मेमोरी खाली गर्नु हो।

  • नाम अगाडि टिल्ड ~ राखेर क्लासकै नाम लेखिन्छ।
  • return type हुँदैन र प्यारामिटर पनि लिँदैन।
  • overload गर्न मिल्दैन — क्लासमा एउटा मात्र डिस्ट्रक्टर हुन्छ।
  • अब्जेक्टहरू बनेको उल्टो क्रममा नष्ट हुन्छन्।
Exam favourite
Constructor and destructor are both called automatically — you never write s1.Student(); yourself. Destruction order is always the reverse of creation order (like plates in a stack). दुवै आफैं बोलिन्छन् — तपाईंले हातले बोलाउनु पर्दैन। नष्ट हुने क्रम सधैं बनेको उल्टो हुन्छ (स्ट्याकमा थुपारेको प्लेट जस्तै)।

Abstraction and Encapsulation

एब्स्ट्र्याक्सन र इनक्याप्सुलेसन

7 hrs · 5 marks
Abstraction — definition

Abstraction means showing only the essential features of an object to the user and hiding the internal implementation details — that is, hiding how the work is done.

In C++ it is achieved using classes with access specifiers and, at a higher level, using abstract classes (a class with a pure virtual function, written = 0).

एब्स्ट्र्याक्सन — परिभाषा

एब्स्ट्र्याक्सन भनेको प्रयोगकर्तालाई आवश्यक कुरा मात्र देखाउने र भित्री काम कसरी हुन्छ भन्ने लुकाउने हो।

C++ मा यो access specifier सहितको क्लास र abstract class (= 0 लेखिएको pure virtual function भएको क्लास) मार्फत हासिल गरिन्छ।

Encapsulation — definition

Encapsulation means binding data members and member functions together into a single unit (the class), and hiding the data from direct outside access by declaring it private.

Outside code must then use public functions (often called getter and setter functions) to read or change that data. This is also called data hiding.

इनक्याप्सुलेसन — परिभाषा

इनक्याप्सुलेसन भनेको डाटा मेम्बर र मेम्बर फङ्सनलाई एउटै एकाइ (क्लास) मा बाँध्ने र डाटालाई private बनाएर बाहिरबाट सिधै छुन नदिने हो।

त्यसपछि बाहिरको कोडले डाटा पढ्न वा बदल्न public फङ्सन (getter/setter) प्रयोग गर्नै पर्छ। यसैलाई data hiding पनि भनिन्छ।

Advantages

Abstraction: reduces complexity, the user sees a simple interface, internal code can be changed later without breaking user code, and it increases security and reusability.

Encapsulation: protects data from accidental change, gives full control (you can validate inside the setter), makes the class easier to maintain and test, and supports data hiding.

फाइदाहरू

Abstraction: जटिलता घटाउँछ, प्रयोगकर्ताले सजिलो इन्टरफेस मात्र देख्छ, भित्री कोड पछि बदल्दा पनि प्रयोगकर्ताको कोड बिग्रँदैन, सुरक्षा र पुनः प्रयोग बढ्छ।

Encapsulation: डाटा गल्तीले बदलिनबाट जोगिन्छ, setter भित्र जाँच राख्न सकिन्छ, क्लास मर्मत र परीक्षण गर्न सजिलो हुन्छ, र data hiding हुन्छ।

The difference students always mix up
Abstraction hides the complexity (the "how"). Encapsulation hides the data (the "what"). Abstraction is about design; encapsulation is about implementation / protection. Abstraction ले जटिलता ("कसरी" गर्ने) लुकाउँछ। Encapsulation ले डाटा ("के" छ) लुकाउँछ। एउटा डिजाइनको कुरा, अर्को सुरक्षाको कुरा।

Inheritance

इनहेरिटेन्स — गुण सर्ने प्रक्रिया

10 hrs · 7 marks
Definition

Inheritance is the process by which one class acquires (gets) the properties and member functions of another class.

The class that gives its features is called the base class (or parent / super class). The class that receives them is called the derived class (or child / sub class).

The main purpose is reusability of code — you write common code once in the base class and reuse it in every derived class.

परिभाषा

इनहेरिटेन्स भनेको एउटा क्लासले अर्को क्लासका गुण र मेम्बर फङ्सन प्राप्त गर्ने प्रक्रिया हो।

गुण दिने क्लासलाई base class (बाबु/parent) भनिन्छ। गुण पाउने क्लासलाई derived class (छोरा/child) भनिन्छ।

मुख्य उद्देश्य कोडको पुनः प्रयोग हो — साझा कोड एक पटक base मा लेख्ने र सबै derived क्लासमा प्रयोग गर्ने।

Real-world analogy
A child inherits eye colour and surname from a parent, and also has some qualities of their own. The child does not get everything — private members are like the parent's personal diary: they exist, but the child cannot open them directly. छोराले बाबुबाट आँखाको रङ र थर पाउँछ, र आफ्नै छुट्टै गुण पनि राख्छ। तर सबै कुरा पाउँदैन — private मेम्बर बाबुको व्यक्तिगत डायरी जस्तै हो: छ त, तर छोराले सिधै खोल्न पाउँदैन।

Polymorphism

पोलिमर्फिज्म — एउटै नाम, धेरै रूप

10 hrs · 7 marks
Definition

The word polymorphism comes from Greek: poly = many, morph = forms. So it means "many forms".

In C++, polymorphism is the ability of the same function name or same operator to behave differently in different situations, depending on the object or the arguments used.

परिभाषा

Polymorphism ग्रीक शब्दबाट आएको हो: poly = धेरै, morph = रूप। अर्थात् "धेरै रूप"।

C++ मा एउटै फङ्सनको नाम वा एउटै अपरेटर ले फरक अवस्थामा फरक व्यवहार गर्ने क्षमतालाई polymorphism भनिन्छ — कुन अब्जेक्ट वा कस्तो आर्गुमेन्ट प्रयोग भयो त्यसमा भर पर्छ।

Real-world analogy
One person is a son at home, a student at school, and a customer in a shop. Same person, different behaviour in different places. That is polymorphism. एउटै मान्छे घरमा छोरा, स्कुलमा विद्यार्थी, पसलमा ग्राहक हुन्छ। व्यक्ति उही, ठाउँ अनुसार व्यवहार फरक। यही नै polymorphism हो।

6.4 Types of Polymorphism

A. Compile-time Polymorphism

Also called static polymorphism or early binding. The compiler decides which function to call while compiling, by looking at the function's arguments.

Achieved by:
Function Overloading Operator Overloading

यसलाई static polymorphism वा early binding भनिन्छ। कुन फङ्सन बोलाउने भन्ने कुरा कम्पाइल गर्दै आर्गुमेन्ट हेरेर निर्णय हुन्छ।

B. Run-time Polymorphism

Also called dynamic polymorphism or late binding. The decision is made while the program is running, by looking at which object the base pointer is actually pointing to.

6.5 Function Overriding

Function Overriding

Function overriding means the derived class defines a function with exactly the same name, same return type and same parameters as a function in its base class.

The derived version replaces the base version for objects of the derived class. Overriding requires inheritance.

If the base function is marked virtual and you call it through a base class pointer, C++ calls the derived version at run time. That is run-time polymorphism. Without virtual, the base version is called instead.

फङ्सन ओभरराइडिङ

Function overriding भनेको derived क्लासमा base क्लासकै फङ्सन जस्तै उही नाम, उही return type र उही प्यारामिटर भएको फङ्सन लेख्नु हो।

derived अब्जेक्टका लागि derived को संस्करणले base को संस्करणलाई प्रतिस्थापन गर्छ। Overriding का लागि inheritance अनिवार्य छ।

base फङ्सनमा virtual लेखिएको छ र base पोइन्टर बाट बोलाइयो भने C++ ले चल्दै गर्दा derived संस्करण बोलाउँछ — यही run-time polymorphism हो। virtual नलेखे base कै संस्करण चल्छ।

The rule to memorise

Overloading → the compiler chooses by looking at the number and type of arguments. Decided before the program runs. Compile-time.

Overriding + virtual → the computer chooses by looking at the object the pointer points to. Decided while the program runs. Run-time.

कण्ठ पार्नुपर्ने नियम

Overloading → कम्पाइलरले आर्गुमेन्टको संख्या र प्रकार हेरेर छान्छ। प्रोग्राम चल्नु अघि नै निर्णय हुन्छ। Compile-time.

Overriding + virtual → पोइन्टरले कुन अब्जेक्ट देखाएको छ त्यो हेरेर छानिन्छ। प्रोग्राम चल्दै गर्दा निर्णय हुन्छ। Run-time.

Advantages of Polymorphism
  • One interface, many implementations — easier to read and remember.
  • Code reusability and shorter programs.
  • Flexibility — new derived classes can be added without changing existing code.
  • Supports dynamic binding and cleaner design.
  • Reduces the number of different function names to remember.
पोलिमर्फिज्मका फाइदा
  • एउटै इन्टरफेस, धेरै काम — पढ्न र सम्झन सजिलो।
  • कोड पुनः प्रयोग र छोटो प्रोग्राम।
  • लचकता — पुरानो कोड नछोई नयाँ derived क्लास थप्न सकिन्छ।
  • Dynamic binding सम्भव बनाउँछ।
  • फरक–फरक नाम सम्झिरहनु पर्दैन।
