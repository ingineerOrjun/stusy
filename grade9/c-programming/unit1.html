Principles of Programming

प्रोग्रामिङका सिद्धान्त

6 hrs · 5 marks · 2 practical hrs

By the end of this unit you can… — यो युनिट सकिँदा तपाईं यी कुरा गर्न सक्नुहुनेछ

  1. Define program, programmer, programming language and software, and say what separates a program from software.
  2. Name the three categories of programming language and say who or what can read each one.
  3. Explain why a high-level program must be translated before a computer can run it.
  4. Give scientific and business applications of programming, and say what each one needs from the machine.
  5. Write an algorithm for a small problem and draw its flowchart with the correct symbols.
यो युनिट सकिँदा: program, programmer, programming language र software को परिभाषा दिन र program अनि software को फरक भन्न, प्रोग्रामिङ भाषाका तीन श्रेणी नाम लिई हरेकलाई कसले पढ्न सक्छ भन्न, high-level प्रोग्राम चल्नुअघि किन अनुवाद गर्नुपर्छ बुझाउन, वैज्ञानिक र व्यावसायिक प्रयोगका उदाहरण दिन, र सानो समस्याको algorithm लेखेर सही चिन्हसहित flowchart कोर्न सक्नुहुनेछ।

1.1  Program, programmer, programming language, software — प्रोग्राम, प्रोग्रामर, प्रोग्रामिङ भाषा, सफ्टवेयर

Four words the examination asks for separately

A program is a set of instructions, written in order, that tells a computer how to do one particular job. Two things are doing work in that sentence: instructions, and in order. The same four instructions in a different order are a different program, and usually a wrong one.

A programmer is the person who writes it. Not the person who uses it, and not the person who installs it — the one who decides what the steps are and writes them down.

A programming language is the notation the programmer writes in. It exists because the two sides cannot meet: a computer cannot read Nepali or English, and a person cannot comfortably write binary. The language is a meeting point with rules strict enough that a machine can translate it mechanically.

Software is the wider word. It is the collection of programs, the data they work on, and the documentation that says how to use them. One program is software, but software is usually many programs — a browser is one program; an operating system is hundreds.

परीक्षाले छुट्टाछुट्टै सोध्ने चार शब्द

Program भनेको क्रमैसँग लेखिएका निर्देशनको समूह हो, जसले कम्प्युटरलाई कुनै एउटा काम कसरी गर्ने भन्छ। यो वाक्यमा दुई कुराले काम गरिरहेका छन्: निर्देशन, र क्रम। उही चार निर्देशन फरक क्रममा राखे फरक प्रोग्राम हुन्छ, र प्रायः गलत हुन्छ।

Programmer भनेको त्यो लेख्ने मान्छे हो। प्रयोग गर्ने होइन, install गर्ने पनि होइन — चरण के–के हुन् भनेर निर्णय गरेर लेख्ने।

Programming language भनेको प्रोग्रामरले लेख्ने लिपि हो। यो त्यसैले चाहिन्छ कि दुवै पक्ष आपसमा भेट्न सक्दैनन्: कम्प्युटरले नेपाली वा अङ्ग्रेजी पढ्न सक्दैन, र मान्छेले सजिलै binary लेख्न सक्दैन। भाषा बीचको भेटघाट हो, र यसका नियम मेसिनले यान्त्रिक रूपमै अनुवाद गर्न सक्ने गरी कडा हुन्छन्।

Software फराकिलो शब्द हो। यो प्रोग्रामहरूको समूह, तिनले काम गर्ने data, र कसरी चलाउने भन्ने documentation मिलेर बन्छ। एउटा प्रोग्राम पनि software हो, तर software प्रायः धेरै प्रोग्राम हुन्छ — browser एउटा प्रोग्राम हो; operating system सयौं।

The difference that carries the mark. "Program and software are the same thing" is marked wrong. A program is one set of instructions for one job. Software is the package: the programs, the files they need, and the manual. If a question asks you to differentiate them, the word to reach for is scope — a program is a part, software is the whole. अंक बोक्ने फरक यही हो। "Program र software एउटै हो" भन्नु गलत मानिन्छ। Program एउटा कामका लागि एउटा निर्देशन समूह हो। Software चाहिँ पूरा प्याकेज हो: प्रोग्राम, तिनलाई चाहिने फाइल, र म्यानुअल। फरक सोधिए दायरा शब्द सम्झनुहोस् — program भाग हो, software सिङ्गो।

1.2  Categories of programming language — प्रोग्रामिङ भाषाका श्रेणी

Three levels, and the question that sorts them

Languages are classified by how close they are to the machine. The question that decides the category is: who can read this without help?

  • Machine level language — 0s and 1s only. The processor reads it directly, with no translation of any kind. It is the fastest to run and almost impossible to write by hand, and it is different on every make of processor. Example: 10110000 01100001.
  • Assembly level language — short codes called mnemonics that stand one-for-one for machine instructions: MOV, ADD, JMP. A person who knows the processor can read it. It needs an assembler to become machine code, and it is still tied to one processor.
  • High level language — English-like words and ordinary arithmetic: C, C++, Java, Python. Anybody who has learnt the language can read it, the same source file works on different machines, and it needs a compiler or an interpreter.

Machine and assembly together are called low level languages, because they are close to the hardware and far from the person. C is a high level language, though it is often called a middle level language as well, because it can reach down to memory addresses in a way that most high level languages cannot. That ability is Unit 7.

तीन तह, र छुट्याउने प्रश्न

भाषाको वर्गीकरण मेसिनसँग कति नजिक छ भन्ने आधारमा हुन्छ। श्रेणी निर्णय गर्ने प्रश्न यही हो: सहायताविना यो कसले पढ्न सक्छ?

  • Machine level language — ० र १ मात्र। प्रोसेसरले कुनै अनुवादविनै सिधै पढ्छ। चल्न सबैभन्दा छिटो, हातले लेख्न झन्डै असम्भव, र हरेक बनोटको प्रोसेसरमा फरक। उदाहरण: 10110000 01100001।
  • Assembly level language — mnemonic भनिने छोटा सङ्केत, जो एक–एक गरी मेसिन निर्देशनका ठाउँमा आउँछन्: MOV, ADD, JMP। प्रोसेसर जान्ने मान्छेले पढ्न सक्छ। मेसिन कोड बन्न assembler चाहिन्छ, र यो पनि एउटै प्रोसेसरसँग बाँधिएको हुन्छ।
  • High level language — अङ्ग्रेजीजस्ता शब्द र सामान्य गणित: C, C++, Java, Python। भाषा सिकेको जोसुकैले पढ्न सक्छ, उही source फरक मेसिनमा चल्छ, र compiler वा interpreter चाहिन्छ।

Machine र assembly लाई सँगै low level भाषा भनिन्छ, किनभने ती hardware सँग नजिक र मान्छेसँग टाढा छन्। C high level भाषा हो, तर यसलाई middle level पनि भनिन्छ — किनभने यसले धेरै high level भाषाले नसक्ने गरी मेमोरीको ठेगानासम्म पुग्न सक्छ। त्यो क्षमता युनिट ७ मा आउँछ।

Beyond the topic list, and needed from Unit 2 onwards. The curriculum's topic 1.2 names only the categories. The three translators are not on the list and you will meet all three in this subject, so learn them here: an assembler turns assembly into machine code; a compiler reads a whole high level program and produces an executable file before anything runs; an interpreter reads and runs one line at a time, so the program stops at the first bad line rather than refusing to start. C uses a compiler. विषयसूचीभन्दा बाहिर, तर युनिट २ देखि चाहिने। पाठ्यक्रमको विषय १.२ ले श्रेणी मात्र नाम लिन्छ। तीन अनुवादक सूचीमा छैनन् तर यस विषयमा तीनै भेटिन्छन्, त्यसैले यहीँ सिक्नुहोस्: assembler ले assembly लाई मेसिन कोड बनाउँछ; compiler ले पूरै high level प्रोग्राम पढेर चल्नुअघि नै executable फाइल बनाउँछ; interpreter ले एक–एक लाइन पढेर चलाउँछ, त्यसैले प्रोग्राम सुरु नै नहुने होइन, पहिलो गलत लाइनमा पुगेर रोकिन्छ। C ले compiler प्रयोग गर्छ।

Practise the judgement · निर्णय अभ्यास गर्नुहोस्

Which category of language is this? — यो कुन श्रेणीको भाषा हो?

What you will learn: to classify a language from a sample rather than from its name. The deciding question is always who can read it unaided — the processor, a person with a manual, or anybody who learnt the language. तपाईंले के सिक्नुहुन्छ: नाम होइन, नमुना हेरेर भाषा छुट्याउन। निर्णय गर्ने प्रश्न सधैं यही हो — सहायताविना कसले पढ्न सक्छ: प्रोसेसरले, म्यानुअल भएको मान्छेले, कि भाषा सिकेको जोसुकैले?

How to use this

Read the sample before the options. If you can see register names, it is assembly; if you can see only digits, it is machine; if you can read it as a sentence, it is high level.

विकल्पभन्दा पहिले नमुना पढ्नुहोस्। Register का नाम देखिए assembly; अङ्क मात्र देखिए machine; वाक्यजस्तै पढ्न सकिए high level।

Predict first · पहिले अनुमान गर्नुहोस्

A program written in C is compiled on a Windows computer and the resulting .exe file is copied to a Linux computer. It refuses to run. Was the programmer wrong to call C portable? C मा लेखिएको प्रोग्राम Windows कम्प्युटरमा compile गरेर बनेको .exe फाइल Linux कम्प्युटरमा सारियो। त्यो चल्न मानेन। त्यसो भए C लाई portable भन्नु गलत थियो?

The source is portable, not the executable. Portability means the same .c file can be compiled on each machine and will behave the same way. The .exe is machine code for one processor and one operating system, so copying it across is copying the wrong file.

Option B is tempting and still wrong: an interpreted program travels as source too, and it needs the interpreter installed on the other machine before it runs. Nothing is portable without something being installed on the far side.

Source portable हो, executable होइन। Portability को अर्थ उही .c फाइल हरेक मेसिनमा compile गर्दा उस्तै व्यवहार गर्छ भन्ने हो। .exe चाहिँ एउटा प्रोसेसर र एउटा operating system कै मेसिन कोड हो, त्यसैले त्यसलाई सार्नु गलत फाइल सार्नु हो। माथिको चित्रको व्यावहारिक अर्थ यही हो: compiler को बायाँ भएको सबै सर्छ, दायाँ भएको सर्दैन। विकल्प (ख) लोभलाग्दो छ तर गलत: interpret हुने प्रोग्राम पनि source कै रूपमा सर्छ, र अर्को मेसिनमा interpreter install भएपछि मात्र चल्छ।

1.3  Applications — scientific and business — प्रयोग — वैज्ञानिक र व्यावसायिक

Two kinds of job, and what each demands

The syllabus names two application areas, and they are named together because they pull the machine in opposite directions.

Scientific applications do a large amount of calculation on a small amount of data. Weather forecasting for the Kathmandu valley, earthquake modelling, satellite image processing, the engineering calculations behind a bridge. What they need is arithmetic speed and accuracy — many decimal places, many operations per second, and floating-point work that does not drift.

Business applications do a small amount of calculation on a large amount of data. A bank's daily transactions, a school's result processing, payroll for a factory, the stock ledger of a shop. The arithmetic is addition and percentages; what they need is storage, sorting, searching and well-formatted reports — and absolute reliability, because an error here is somebody's salary.

C is used for both, and it is used far more for a third kind the syllabus does not name: system programming. Operating systems, compilers and device drivers are written in C because of the memory control Unit 7 introduces.

दुई किसिमका काम, र हरेकले माग्ने कुरा

पाठ्यक्रमले दुई प्रयोग क्षेत्र नाम लिन्छ, र सँगै नाम लिनुको कारण यिनले मेसिनलाई उल्टो दिशामा तान्छन् भन्ने हो।

वैज्ञानिक प्रयोग ले थोरै data मा धेरै गणना गर्छ। काठमाडौं उपत्यकाको मौसम पूर्वानुमान, भूकम्पको मोडेल, उपग्रह तस्बिरको प्रशोधन, पुल बनाउने इन्जिनियरिङ गणना। यिनलाई गणनाको गति र शुद्धता चाहिन्छ — धेरै दशमलव, प्रति सेकेन्ड धेरै क्रिया, र नबग्ने floating-point काम।

व्यावसायिक प्रयोग ले धेरै data मा थोरै गणना गर्छ। बैंकको दैनिक कारोबार, विद्यालयको नतिजा, कारखानाको तलब, पसलको मौज्दात खाता। गणना भनेको जोड र प्रतिशत मात्र; यिनलाई भण्डारण, क्रम मिलाउने, खोज्ने र राम्ररी ढाँचा मिलेको प्रतिवेदन चाहिन्छ — र पूर्ण भरपर्दोपन, किनभने यहाँको त्रुटि कसैको तलब हो।

C दुवैमा चल्छ, र पाठ्यक्रमले नाम नलिएको तेस्रो किसिममा झन् बढी: system programming। Operating system, compiler र device driver C मै लेखिन्छन्, किनभने युनिट ७ ले देखाउने मेमोरी नियन्त्रण यसमा छ।

1.4  Program design tools — algorithm and flowchart — प्रोग्राम डिजाइनका साधन — algorithm र flowchart

The planning you do before any code

An algorithm is a finite, step-by-step procedure for solving a problem, written in ordinary language. It is not C, and it does not have to be: its job is to get the method right while mistakes are still cheap to fix.

Five properties are expected in an answer, and each one is a way an algorithm can be wrong:

  • Finiteness — it must end after a limited number of steps. A procedure that never stops has not solved anything.
  • Definiteness — every step must mean exactly one thing. "Add some numbers" is not a step.
  • Input — zero or more values supplied at the start.
  • Output — at least one result. An algorithm that produces nothing has no purpose.
  • Effectiveness — every step must be simple enough to actually be carried out with paper and pencil.

A flowchart is the same method drawn as a picture, using standard symbols joined by arrows. It shows the path through the steps, which is exactly what a list of sentences hides: a decision with two branches is one line of text and two visible arrows.

कोड लेख्नुअघिको योजना

Algorithm भनेको समस्या समाधान गर्ने सीमित, चरणबद्ध विधि हो, सामान्य भाषामा लेखिएको। यो C होइन, र हुनु पनि पर्दैन: गल्ती सच्याउन सस्तै हुँदा विधि ठिक बनाउनु यसको काम हो।

उत्तरमा पाँच गुण खोजिन्छ, र हरेक गुण algorithm बिग्रने एउटा तरिका पनि हो:

  • Finiteness — सीमित चरणपछि सकिनै पर्छ। कहिल्यै नरोकिने विधिले केही समाधान गरेको हुँदैन।
  • Definiteness — हरेक चरणको ठ्याक्कै एउटै अर्थ हुनुपर्छ। "केही सङ्ख्या जोड्नुहोस्" चरण होइन।
  • Input — सुरुमा शून्य वा बढी मान दिइन्छ।
  • Output — कम्तीमा एउटा नतिजा। केही नदिने algorithm को प्रयोजन हुँदैन।
  • Effectiveness — हरेक चरण कागज–कलमले साँच्चै गर्न सकिने गरी सरल हुनुपर्छ।

Flowchart भनेको त्यही विधि चित्रमा कोरेको हो — मानक चिन्हहरू तीरले जोडेर। यसले चरणहरूबीचको बाटो देखाउँछ, जुन वाक्यहरूको सूचीले लुकाउँछ: दुई शाखा भएको decision पाठमा एक लाइन हो, चित्रमा दुई देखिने तीर।

Example 1 Largest of two numbers — algorithm and flowchart

Question: write an algorithm and draw a flowchart to find the larger of two numbers entered by the user.

Write the steps out before opening this. Count how many arrows must leave your decision box, and check that every path reaches a Stop. खोल्नुअघि चरणहरू लेख्नुहोस्। Decision बाकसबाट कति तीर बाहिर जानुपर्छ गन्नुहोस्, र हरेक बाटो Stop सम्म पुग्छ कि पुग्दैन जाँच्नुहोस्।

ALGORITHM Step 1 Start Step 2 Read a, b Step 3 If a > b then Print a is larger else Print b is larger Step 4 Stop FLOWCHART (read downwards) ( Start ) oval | / Read a, b / parallelogram | < a > b > diamond yes / \ no / \ / Print a / / Print b / two parallelograms \ / \ / ( Stop ) oval

Three things are being marked here and only one of them is the comparison. Both branches are labelled yes and no; both branches end at the same Stop; and the printing boxes are parallelograms, not rectangles, because printing crosses the boundary to the person. Note also that the algorithm never says what happens when a and b are equal — it prints "b is larger", which is wrong. A complete answer would use three branches or say "a is not larger". यहाँ तीन कुराको अंक छ, र तीमध्ये एउटा मात्र तुलना हो। दुवै शाखामा yes र no लेखिएको छ; दुवै शाखा उही Stop मा पुग्छन्; र छाप्ने बाकस rectangle होइन parallelogram हुन्, किनभने छाप्नु मान्छेसम्मको सिमाना नाघ्नु हो। अर्को कुरा — a र b बराबर भए के हुन्छ algorithm ले भनेकै छैन; त्यसले "b is larger" छाप्छ, जुन गलत हो। पूरा उत्तरमा तीन शाखा हुन्थ्यो, वा "a is not larger" लेखिन्थ्यो।

Example 2 Sum of the first ten natural numbers

Question: write an algorithm to find 1 + 2 + 3 + … + 10. This one repeats, so it is where a flowchart earns its keep.

Two variables are needed, not one. Decide what each holds and what its value must be before the repetition starts. एउटा होइन, दुई variable चाहिन्छ। हरेकले के राख्छ र दोहोरिन सुरु हुनुअघि त्यसको मान के हुनुपर्छ, निर्णय गर्नुहोस्।

Working
ALGORITHM Step 1 Start Step 2 sum = 0, i = 1 both must be set FIRST Step 3 If i > 10 go to Step 7 Step 4 sum = sum + i Step 5 i = i + 1 Step 6 Go to Step 3 Step 7 Print sum Step 8 Stop TRACE (the first three turns and the last) i = 1 sum = 0 + 1 = 1 i = 2 sum = 1 + 2 = 3 i = 3 sum = 3 + 3 = 6 ... i = 10 sum = 45 + 10 = 55 i = 11 11 > 10, so jump to Step 7 Printed: 55

Step 2 is where this goes wrong in real answers. If sum is not set to 0 first, step 4 adds to an unknown value; if i is not set to 1, the count starts nowhere. The loop ends because step 5 changes the thing step 3 tests — remove step 5 and the algorithm fails finiteness and runs forever. वास्तविक उत्तरमा चरण २ कै कारण बिग्रन्छ। sum लाई पहिले ० नराखे चरण ४ ले अज्ञात मानमा जोड्छ; i लाई १ नराखे गन्ती कतैबाट सुरु हुँदैन। Loop सकिनुको कारण चरण ५ ले चरण ३ ले जाँच्ने कुरै बदल्छ — चरण ५ हटाए algorithm finiteness मा असफल हुन्छ र सधैं चलिरहन्छ।

Practise the judgement · निर्णय अभ्यास गर्नुहोस्

Which flowchart symbol does this step need? — यो चरणलाई कुन flowchart चिन्ह चाहिन्छ?

What you will learn: to pick the shape from the kind of step rather than from the words in it. Input and output share one symbol; calculation has its own; a question has two arrows out. तपाईंले के सिक्नुहुन्छ: शब्द होइन, चरणको किसिम हेरेर आकार छान्न। Input र output को एउटै चिन्ह हुन्छ; गणनाको आफ्नै; प्रश्नबाट दुई तीर बाहिर जान्छन्।

How to use this

Ask one question per case: does anything leave or enter the program here? If yes it is a parallelogram. If it is a question with a yes and a no, it is a diamond. Otherwise it is almost always a rectangle.

हरेक केसमा एउटा प्रश्न सोध्नुहोस्: यहाँ प्रोग्रामबाट केही बाहिर जान्छ वा भित्र आउँछ? भए parallelogram। हो–होइन भएको प्रश्न भए diamond। नत्र झन्डै सधैं rectangle।

Mistakes that cost marks here — यहाँ अङ्क गुमाउने गल्तीहरू

  • Saying a program and software are the same. A program is one set of instructions; software is programs plus data plus documentation.
  • Calling assembly language "machine language". Assembly uses mnemonics and needs an assembler. Machine language is binary and needs nothing.
  • Drawing a rectangle for Read or Print. Both are input/output and both take the parallelogram.
  • Leaving a decision branch unlabelled. A diamond with two unmarked arrows does not say which path is which, and the marks are for the labels.
  • Writing an algorithm with no Stop. Finiteness is one of the five properties, and it is the one tested by leaving it out.
  • Forgetting to initialise before a loop. sum = 0 before the repetition begins, every time.
Program र software एउटै भन्नु: program एउटा निर्देशन समूह, software चाहिँ program + data + documentation। Assembly लाई machine language भन्नु: assembly मा mnemonic हुन्छन् र assembler चाहिन्छ; machine language binary हो र केही चाहिँदैन। Read वा Print लाई rectangle कोर्नु: दुवै input/output हुन्, parallelogram। Decision का शाखामा नाम नलेख्नु: नाम नभएका दुई तीरले कुन बाटो कुन हो भन्दैनन्, र अंक नाम कै हो। Stop नभएको algorithm लेख्नु: finiteness पाँच गुणमध्ये एक हो। Loop अघि initialise बिर्सनु: दोहोरिन सुरु हुनुअघि sum = 0, सधैं।

Memory hook — Oval starts, slanted talks, box works, diamond asks. Four shapes, four jobs. सम्झने तरिका — Oval सुरु, छड्के बोल्छ, बाकस काम गर्छ, diamond सोध्छ।

2 marks Practice question

Define program and software. Write one difference between them. Program र software को परिभाषा दिनुहोस्। दुईबीचको एउटा फरक लेख्नुहोस्।

A program is a set of instructions, written in a particular order, that tells a computer how to perform one specific task.

Software is the collection of programs together with the data they use and the documentation that explains them.

Difference: a program is a single item; software is the whole package. Every program is software, but software is normally made of many programs.

Program भनेको निश्चित क्रममा लेखिएका निर्देशनको समूह हो, जसले कम्प्युटरलाई एउटा निश्चित काम कसरी गर्ने भन्छ। Software भनेको प्रोग्रामहरू, तिनले प्रयोग गर्ने data र तिनलाई बुझाउने documentation को समूह हो। फरक: program एउटा वस्तु हो; software पूरै प्याकेज। हरेक program software हो, तर software प्रायः धेरै program मिलेर बन्छ।
4 marks Practice question

Explain the categories of programming language with one example of each. प्रोग्रामिङ भाषाका श्रेणी हरेकको एउटा उदाहरणसहित बुझाउनुहोस्।

1. Machine level language — written only in 0s and 1s. The processor executes it directly with no translation. It is fastest to run, hardest to write, and different for every processor. Example: 10110000 01100001.

2. Assembly level language — uses mnemonics such as MOV and ADD that correspond one-to-one with machine instructions. It needs an assembler to translate it and it is still processor-specific. Example: MOV AL, 61h.

3. High level language — uses English-like words and ordinary arithmetic. It is readable, portable between machines, and needs a compiler or interpreter. Example: C, C++, Java.

Machine and assembly together are called low level languages.

१. Machine level — ० र १ मात्र; प्रोसेसरले सिधै चलाउँछ; छिटो, लेख्न गाह्रो, हरेक प्रोसेसरमा फरक। उदाहरण 10110000 01100001। २. Assembly level — MOV, ADD जस्ता mnemonic, मेसिन निर्देशनसँग एक–एक मिल्ने; assembler चाहिन्छ; प्रोसेसरसँग बाँधिएको। उदाहरण MOV AL, 61h। ३. High level — अङ्ग्रेजीजस्ता शब्द; पढ्न सजिलो, मेसिनबीच portable; compiler वा interpreter चाहिन्छ। उदाहरण C, C++, Java। Machine र assembly लाई सँगै low level भनिन्छ।
4 marks Practice question

Write an algorithm and draw a flowchart to find the sum and average of three numbers. तीन सङ्ख्याको जोड र औसत निकाल्ने algorithm लेखेर flowchart कोर्नुहोस्।

Algorithm

Step 1 Start
Step 2 Read a, b, c
Step 3 sum = a + b + c
Step 4 avg = sum / 3
Step 5 Print sum, avg
Step 6 Stop

Flowchart: oval (Start) → parallelogram (Read a, b, c) → rectangle (sum = a + b + c) → rectangle (avg = sum / 3) → parallelogram (Print sum, avg) → oval (Stop), joined by downward arrows.

There is no decision in this problem, so there is no diamond and no branch. Marks here are for the right symbols in the right order, and for not merging steps 3 and 4 into one box — each calculation is its own process step.

Algorithm: चरण १ Start; चरण २ a, b, c पढ्नुहोस्; चरण ३ sum = a + b + c; चरण ४ avg = sum / 3; चरण ५ sum र avg छाप्नुहोस्; चरण ६ Stop। Flowchart: oval (Start) → parallelogram (Read a, b, c) → rectangle (sum) → rectangle (avg) → parallelogram (Print) → oval (Stop), तलतिरका तीरले जोडिएको। यस समस्यामा कुनै decision छैन, त्यसैले diamond र शाखा छैनन्। अंक सही चिन्ह सही क्रममा राखेको र चरण ३ अनि ४ लाई एउटै बाकसमा नमिसाएको हो — हरेक गणना आफ्नै process चरण हो।

Key points from this unit

  • A program is ordered instructions for one job; software is programs plus data plus documentation.
  • Three categories: machine (binary, no translation), assembly (mnemonics, assembler), high level (English-like, compiler or interpreter).
  • Machine and assembly are low level. C is high level, and is also called middle level.
  • Source code is portable; a compiled executable is not.
  • Scientific work is heavy calculation on little data; business work is light calculation on a lot of data.
  • An algorithm must be finite, definite, effective, and must produce output.
  • Flowchart symbols: oval terminal, parallelogram input/output, rectangle process, diamond decision, circle connector, arrow flow.
Program = एउटै कामका लागि क्रमबद्ध निर्देशन; software = program + data + documentation। तीन श्रेणी: machine (binary, अनुवाद नचाहिने), assembly (mnemonic, assembler), high level (अङ्ग्रेजीजस्तो, compiler वा interpreter)। Machine र assembly low level; C high level, जसलाई middle level पनि भनिन्छ। Source portable हुन्छ, compile भएको executable हुँदैन। वैज्ञानिक काम = थोरै data मा धेरै गणना; व्यावसायिक काम = धेरै data मा थोरै गणना। Algorithm finite, definite र effective हुनुपर्छ, र output दिनैपर्छ। Flowchart चिन्ह: oval terminal, parallelogram input/output, rectangle process, diamond decision, circle connector, तीर flow।
